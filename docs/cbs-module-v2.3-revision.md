## 一、LP 行为目的穷举与信号收纳

### 1.1 前置澄清

添加 LP 不等于买入。但添加 LP 经常**伴随着看多**，或者服务于某种更大的目的。我们需要穷举所有可能的 LP 行为目的，然后筛选出对投研团队有价值的部分。

以下按一级分类（A/B/C/D/E）逐类穷举。

### 1.2 A 类（主动买方）的 LP 行为

| # | 行为场景 | 目的/意图 | 对投研的信号含义 | 价值等级 |
|---|---------|---------|--------------|:------:|
| A-1 | 买入 Token 后**添加全范围 LP** | 赚取手续费收益，长期持有的"增强"版 | 看好该 Token + 希望在持有期间获得额外收益。**是间接看多的信号** | ★★★ |
| A-2 | 买入 Token 后**质押/Staking** | 获得质押收益或治理权 | 长期看好的更强信号——质押通常意味着锁定期，说明没打算短期卖出 | ★★★★ |
| A-3 | 在当前价格**下方**设集中流动性 LP（窄区间） | 等效于"限价买入单"——如果价格跌到区间内，自动买入 | **看多 + 有明确的买入价格预期**。是一种有纪律的建仓策略 | ★★★★★ |
| A-4 | 在当前价格**上方**设集中流动性 LP（窄区间） | 等效于"限价卖出单"——如果价格涨到区间内，自动卖出 | **计划获利了结**。说明有明确的目标价 | ★★★★ |
| A-5 | 在当前价格**附近**设集中流动性 LP | 赚取手续费（当前价格区间交易最活跃） | **短期看好不跌破区间** + 赚取收益。间接看多但信号弱于 A-3 | ★★ |
| A-6 | 买入后**不做任何 LP/质押**，仅持有 | 纯方向性持仓 | 看多，但对"长期持有"的信心弱于 A-2 | ★★★ |

**关键发现**：对于 A 类地址，买入后的"下一步动作"本身就是信号强度的修饰器：

```
信号强度递增:
  纯持有 < 添加全范围LP < 设定上方限价卖出LP < 质押/锁仓
                                                    ↑
                                            说明有长期持有意图

特殊:
  设定下方限价买入LP → 虽然还没买入，但意图已经明确
```

### 1.3 B 类（潜在卖方）的 LP 行为

| # | 行为场景 | 目的/意图 | 信号含义 | 价值等级 |
|---|---------|---------|---------|:------:|
| B-1 | 解锁后将 Token 添加**全范围 LP** | 想边持有边赚收益，暂时不想直接卖出 | **短期不卖的信号**（如果想卖直接去 CEX/DEX swap 更快）。但不等于长期看好 | ★★★ |
| B-2 | 解锁后在当前价格**上方**设窄区间 LP | 计划在价格上涨时自动减仓 | **有序减仓信号**——不是恐慌性抛售，而是有计划地在高点退出 | ★★★★ |
| B-3 | 解锁后在当前价格**附近**设大量窄区间 LP | 可能在利用高手续费区间变相减仓 | **变相减仓**——在高交易量区间提供流动性，被动被"交易掉" | ★★★ |
| B-4 | 从 LP 中**撤出**（之前一直在做 LP） | 准备直接卖出或迁移资产 | **减仓前兆**——撤出 LP 是卖出前的准备动作 | ★★★★ |

### 1.4 C1（做市商）的 LP 行为

| # | 行为场景 | 目的/意图 | 信号含义 | 价值等级 |
|---|---------|---------|---------|:------:|
| C1-1 | **首次**为某 Token 添加大量 LP | 建立做市关系（可能有合约） | **新项目关系信号**：可能暗示上所、合作等 | ★★★★ |
| C1-2 | 大幅**增加**已有做市对的 LP 深度 | 预期交易量增加、或主动加码 | **看好交易量前景** / 可能有内部信息显示即将有催化事件 | ★★★ |
| C1-3 | 大幅**减少**或**完全撤出**做市 LP | 风控、合约到期、或项目出现问题 | **风险信号**：做市商比任何人更早知道流动性风险 | ★★★★★ |
| C1-4 | 调窄做市区间（减少暴露范围） | 降低方向性风险，只在窄区间提供流动性 | **谨慎信号**：做市商在"缩小阵地"，可能预期波动加剧 | ★★★ |
| C1-5 | LP 库存明显偏向持有更多 Token（而非稳定币） | 有意让做市过程偏向"接盘"更多 Token | **隐含看多**：愿意持有更多 Token 方向风险 | ★★★★ |
| C1-6 | LP 库存明显偏向稳定币 | 有意让做市过程偏向"卖出"更多 Token | **隐含看空或避险**：在做市过程中逐步退出 Token 头寸 | ★★★★ |

### 1.5 C4（LP 池/流动性调度）的 LP 行为

| # | 行为场景 | 目的/意图 | 信号含义 | 价值等级 |
|---|---------|---------|---------|:------:|
| C4-1 | 大量新 LP 提供者涌入某 Token 的池 | 预期该 Token 交易活跃、手续费收入可观 | **市场对该 Token 热度的预期上升** | ★★ |
| C4-2 | LP 提供者持续流失 | 手续费收入下降、或对该 Token 失去信心 | **流动性环境恶化** | ★★★ |
| C4-3 | 流动性从 V2 池迁移到 V3 集中流动性池 | 效率优化，不一定是方向性信号 | **中性**——结构升级而非方向判断 | ★ |
| C4-4 | 流动性从链 A 迁移到链 B | 跟随用户/交易量迁移 | **生态迁移信号**（对原链偏空，对新链偏多） | ★★★ |

### 1.6 E 类（特殊观察）的 LP 行为

| # | 行为场景 | 目的/意图 | 信号含义 | 价值等级 |
|---|---------|---------|---------|:------:|
| E1-1 | 地址在借贷协议借出 Token 后，将借来的 Token 添加 LP | 杠杆做收益——借出资产并用于 LP 赚取手续费 | **高风险收益策略**：不是方向性信号，但如果大量此类行为存在，说明市场过热 | ★★ |
| E3-1 | 从质押/Staking **撤出**后未卖出，而是转入 LP | 从锁仓转为流动性提供 | **降低锁定程度但仍持有**：比直接卖出的信号好，但比继续质押的信号弱 | ★★ |
| E3-2 | 协议方用 Treasury 资金添加自家 Token 的 LP | 维护流动性、展示信心 | **项目方行为**：需关注是"正常运营"还是"护盘"。如果在价格下跌时突然加大 LP，可能是护盘信号 | ★★★ |

### 1.7 筛选：对团队有价值的 LP 信号

从上述穷举中，筛选出**价值等级 ≥ ★★★★** 的信号，这些是投研团队应该重点关注的：

| 编号 | 场景 | 信号 | 归入指标 |
|------|------|------|---------|
| **A-2** | A 类买入后质押 | 长期持有强信号 | 指标 1（净流入的信号增强标签：`BUY+STAKE`） |
| **A-3** | A 类在下方设窄区间 LP | 有纪律的限价买入 | 指标 1（隐含买入意图，置信度 0.2-0.5） |
| **A-4** | A 类在上方设窄区间 LP | 计划获利了结 | 指标 1（隐含卖出意图，置信度 0.2-0.5） |
| **B-2** | B 类解锁后设上方 LP | 有序减仓信号 | 指标 1（隐含卖出意图） |
| **B-4** | B 类从 LP 撤出 | 减仓前兆 | 指标 6（如果偏离基线则触发异常） |
| **C1-1** | 做市商首次做市 | 新项目关系 | 指标 6（新做市关系事件） |
| **C1-3** | 做市商撤出做市 | 风险信号 | 指标 6（做市商风控事件）★★★★★ |
| **C1-5** | 做市商库存偏向 Token | 隐含看多 | 指标 6（做市商方向性偏移事件） |
| **C1-6** | 做市商库存偏向稳定币 | 隐含看空 | 指标 6（做市商方向性偏移事件） |

**不收纳的部分**（★★ 或以下，信号噪声比低）：
- A-5（当前价格附近的 LP，太常规）
- C4-1/C4-3（普通 LP 涌入/结构迁移，方向性弱）
- E1-1（杠杆收益策略，非方向性）
- E3-1（从质押转 LP，信号模糊）

**特别说明**：A-1（买入后添加全范围 LP）虽然只有 ★★★，但发生在 A 类地址上时具有**信号增强作用**——如果已经有"真实买入"信号，后续的 LP 添加可以作为"买入后行为"的附加标签（如 `BUY → LP`），提升该买入信号的置信度。

### 1.8 对 Event Layer 的影响

将以上分析纳入 Event Layer 的行为判定：

```
LP 事件处理流程 (v2.3):

1. 识别 LP 事件类型:
   ├── 添加 LP (Mint)
   ├── 撤出 LP (Burn)
   ├── 调整区间 (Collect + Mint)
   └── 库存比例变化 (被动，价格变动导致)

2. 识别实体一级分类:
   ├── A/B 类 → 进入"方向性分析"
   ├── C1 类 → 进入"做市商行为分析"

3. A/B 类方向性分析:
   ├── 区间位置 vs 当前价格 → 判断隐含方向
   ├── 是否伴随前序买入/卖出 → 生成"后续行为标签"
   ├── 是否涉及质押 → 生成"长期持有标签"
   └── 输出: 计入指标 1 (附置信度和标签)

4. C1 做市商行为分析:
   ├── 是否首次做市 → C1-1 事件

   ├── 区间变化 → 是否触发 C1-4

   └── 输出: 计入指标 6 (做市商事件)

5. 所有 LP 事件:
   └── 汇总为 Token 级流动性快照 → 计入指标 7
```

## 二、指标 6 的彻底重构

### 2.1 问题诊断

你说"指标 6 和指标 1 还是区分不开，都是异动"。这个判断是对的。让我直面这个问题。

v2.2 给指标 6 的定义是"关键实体异常行为——偏离自身基线的异常"。但问题在于：**一个实体的异常买入既会被指标 1 计入（因为是买入），也会被指标 6 计入（因为异常）。分析师看到的是同一个事件在两个指标上的重复反映。**

原需求文档的定义是："大额转移与实体标签——关键实体之间的大额转账、入所/出所、跨链迁移"。

### 2.2 回到本质：指标 1 和指标 6 到底应该各管什么？

| | 指标 1 管的 | 指标 6 应该管的 |
|-|-----------|--------------|
| 对象 | 所有白名单实体的确认买卖**汇总** | **单个事件级**的异动 |
| 颗粒度 | Token 级聚合值 | 事件级明细 |
| 触发方式 | 每小时批量计算 | 事件驱动即时触发 |
| 输出形式 | 一个数字（+$2.3M） | 一条异动报告（"Paradigm 买了 $1.8M"） |

**核心矛盾：在数据层面，指标 6 的事件是指标 1 的组成部分。指标 1 = Σ(所有指标 6 级别的事件)。**

### 2.3 解决方案：指标 6 不是"另一种量化指标"，而是"事件流"

**根本性重定义：指标 6 不输出一个分数，而输出一个事件列表。**

原来 7 个指标都是量化评分（-100 到 +100），然后加权求和。但指标 6 的本质不是一个"分数"，它是**投研切入点**——告诉分析师"今天有哪些值得关注的事件"。

```
指标 1-5, 7: 量化指标 → 输出有向分值 → 参与 CBS Score 计算

指标 6: 事件流指标 → 输出事件列表 → 不直接参与 CBS Score 加权
         └── 但事件的方向性已经体现在指标 1/4 中（避免重复计分）
         └── 其独特价值在于：
             1. 提供"为什么 CBS Score 在变化"的解释
             2. 触发异动推送给分析师
             3. 记录那些不属于买卖但仍有投研价值的事件
```

### 2.4 指标 6 应该捕获哪些事件？

重新审视原需求文档的定义——"大额转移与实体标签"。结合 v2.2 的"异常检测"定义。融合后：

**指标 6 = 结构性资金移动事件流**

它捕获的事件不是"买入/卖出"（那是指标 1 的事），而是：

| 事件类型 | 描述 | 举例 | 为什么不属于指标 1 |
|---------|------|------|----------------|
| **大额入所** | 白名单实体向 CEX 转入大额 Token | Paradigm 向 Binance 转入 $5M ETH | 转入 CEX ≠ 已卖出。可能是做 OTC、质押、或等待卖出。指标 4 记录金额，指标 6 记录"谁做了这件事" |
| **大额出所** | 白名单实体从 CEX 提出大额资产 | Jump 从 Coinbase 提出 $10M USDC | 提出 CEX ≠ 已买入。可能是做 DeFi、LP、或准备链上操作。指标 4 记录金额，指标 6 记录"谁" |
| **跨链迁移** | 白名单实体将资产从链 A 转移到链 B | 鲸鱼将 $3M 从 Ethereum bridge 到 Base | 跨链 ≠ 买卖。但如果多个实体同时向某链迁移，说明该链/生态有新动向 |
| **内部转账/地址更换** | 白名单实体在自有地址间转移 | VC 从冷钱包转到热钱包 | 不是买卖行为，但**冷→热转移往往是卖出的前兆** |
| **做市商事件** | C1 类的异常行为（C1-1/C1-3/C1-5/C1-6） | Wintermute 从 $XYZ 完全撤出做市 | 做市行为不是买卖，但对投研有极高信号价值 |
| **首次参与** | A1/A3 类实体首次与某 Token 交互 | a16z 关联地址首次出现在 $XYZ 的 holder 列表中 | 首次参与本身就是事件，即使金额小也值得关注 |
| **异常规模操作** | 任何实体的操作规模偏离其历史中位数 3 倍以上 | 某匿名高手平时每笔 $50K，这次买了 $800K | 金额已经计入指标 1，指标 6 标记"这次不正常" |

### 2.5 指标 6 与其他指标的最终边界

```
事件发生: "Paradigm 向 Binance 转入 $5M 的 Token XYZ"

指标 1 (净流入): 不计入。转入 CEX 不是确认卖出，只是转移。
指标 4 (交易所流量): 计入。CEX 入金 +$5M。
指标 6 (事件流): 记录一条事件 ——
    类型: 大额入所
    实体: Paradigm (A1, 趋势配置型)
    金额: $5M
    标的: XYZ
    上下文: Paradigm 过去 90 天持有 $12M 的 XYZ，本次转入占 42%
    Contrast: 偏离基线 (过去 180 天未向 CEX 转入过 XYZ)
    推测: 可能准备减仓，建议观察后续是否出现在 CEX 卖单
```

```
事件发生: "某匿名高手用 $800K USDC 在 Uniswap 买入 Token XYZ"

指标 1 (净流入): 计入。确认买入 +$800K。
指标 3 (参与动态): 计入。如果是首次参与。
指标 6 (事件流): 记录一条事件 ——
    类型: 异常规模买入
    说明: 该实体历史单笔中位数 $50K，本次 $800K 是 16 倍
    注意: 金额已计入指标 1，此处标记"异常规模"这个特征
```

**指标 6 的独特价值不在于"又算了一次同样的事"，而在于：**
1. **标注"谁做了这个事"**（指标 1 只输出汇总值，不告诉你是谁）
2. **标注"这次不正常"**（指标 1 不区分正常和异常）
3. **捕获非买卖类事件**（入所/出所/跨链/做市商行为）
4. **直接服务于"异动推送"**——分析师收到的推送就是指标 6 的事件流

### 2.6 对 CBS Score 计算的影响

```
CBS Score 参与者: 指标 1/2/3/4/5/7 (6个量化指标) × PerpModifier

指标 6 不参与 CBS Score 加权计算。

指标 6 的作用:
  1. 输出"异动事件列表"到 Dashboard 和消息推送
  2. 提供"CBS Score 为什么变了"的解释层
  3. 触发分析师的深度调研流程
```

**权重重分配**（指标 6 退出加权后）：

```
w1 (净流入)     = 0.30  (上调，核心指标)
w2 (增持天数)   = 0.15
w3 (参与动态)   = 0.20
w4 (交易所流量) = 0.15  (上调)
w5 (持仓集中度) = 0.10
w7 (流动性环境) = 0.10

指标 6: 不参与加权，作为事件流独立输出
```

### 2.7 评估原需求文档定义

原需求文档："大额转移与实体标签——关键实体之间的大额转账、入所/出所、跨链迁移。识别超过阈值的大额转移，并标注来源/去向实体与可能含义。进入'事件型证据'，结合其他模块确认后升级。"

| 维度 | 原定义 | v2.3 修订 | 评价 |
|------|-------|---------|------|
| 核心对象 | 大额转移 | 结构性资金移动 + 异常行为 | v2.3 更全面——不仅捕获大额转移，还捕获做市商行为、首次参与等非"转移"类事件 |
| 标注 | 来源/去向实体 + 含义 | 实体标签 + Contrast Layer 上下文 + 推测 | v2.3 增加了基线对比，不仅标注是谁，还标注"这次对它来说是否异常" |
| 定位 | "事件型证据" | 事件流（不参与 CBS Score 加权） | **原定义的"事件型证据"定位其实非常精准**——它本来就不该是一个量化评分指标，而应该是事件证据。v2.3 回归了这个初衷 |
| "结合其他模块确认后升级" | 跨模块验证 | 异动推送模板中引导分析师查看 ECS/NDS/BAS | 思路一致，v2.3 将其落地为推送模板中的引导语 |

**结论：原需求文档对指标 6 的定位（"事件型证据"）是最合理的。v2.0-v2.2 试图将其量化为一个评分指标是方向偏差。v2.3 回归了原始定位，将其作为事件流而非评分项。**

## 三、持仓集中度方案确认

### 3.1 确认采用方法 C（分层持仓分析）

根据反馈，直接采用 v2.2 中的方法 C 作为 V1 方案（不再走 Top N 过渡）。

**方法 C 核心设计**：

```
Layer 1 (鲸鱼层): 持仓 > 总供应量的 0.1%
Layer 2 (中等层): 持仓在 0.01% ~ 0.1%
Layer 3 (零售层): 持仓 < 0.01%

排除: CEX 地址 / 合约地址 / 桥地址 / 销毁地址 / 0x0

每层分别计算:
  - 总持仓占比
  - 地址数量
  - 叠加一级分类标签 (A/B/C/D/E)

跨层流转检测:
  - 鲸鱼层 → 零售层 = 分散化 (正向)
  - 零售层 → 鲸鱼层 = 集中化 (需结合一级分类判断正负)
```
