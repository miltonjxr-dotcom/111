## 修正一：LP 行为的买入/卖出语义

### 1.1 问题

v2 将 LP 行为（指标 7）与真实买入/卖出（指标 1-3）完全分离。但集中流动性（如 Uniswap V3）的 LP 实际上具有**隐含的买入/卖出效果**：

- 当价格**高于** LP 设定的区间上限时，LP 持有的全部是 Quote Token（如 USDT）——相当于**自动卖出**了 Base Token
- 当价格**低于** LP 设定的区间下限时，LP 持有的全部是 Base Token——相当于**自动买入**了 Base Token
- 在区间内时，LP 持有混合比例，随价格变动持续"卖出涨的、买入跌的"

### 1.2 分析

这个观察是正确的，但需要区分**两种截然不同的 LP 行为**：

| LP 类型 | 行为特征 | 是否构成方向性信号 | 说明 |
|---------|---------|:--:|------|
| **做市型 LP** | 窄区间、高频调仓、双边对称 | **否** | C1 类（做市商）的日常操作，目的是赚取手续费，不表达方向性观点。区间被穿越后通常立即调仓恢复。 |
| **策略型 LP** | 单边偏移区间、低频、区间设定具有明确方向性 | **是** | A 类（主动买方）或 B 类（潜在卖方）的一种**执行手法**。比如：在当前价格下方设置一个窄区间，本质上是挂了一个"限价买入单"。 |

**关键洞察**：LP 的方向性语义不在"添加/撤出"这个动作本身，而在**区间设定相对于当前价格的位置**。

### 1.3 修正方案

**不改变 LP 作为独立指标（指标 7）的定位，但增加"LP 方向性信号提取"子模块**：

```
LP 行为事件
    │
    ├── 判断 LP 类型
    │   ├── C1 类地址 → 做市型 LP → 仅计入指标 7（LP 行为变化），不计入方向性
    │   └── A/B/E 类地址 → 策略型 LP → 进入方向性分析
    │
    └── 策略型 LP 方向性分析
        ├── 区间下限 > 当前价格 × 0.95 → 接近当前价的卖出型 LP → 提取"隐含卖出"信号
        ├── 区间上限 < 当前价格 × 1.05 → 接近当前价的买入型 LP → 提取"隐含买入"信号
        ├── 区间已被完全穿越 + 未调仓 → 被动建仓/清仓完成 → 强方向性信号
        └── 宽区间 + 双边对称 → 收益策略 → 弱/无方向性信号
```

**提取出的"隐含买入/卖出"应计入指标 1（净流入/流出）和指标 3（参与动态），但标注信号来源为 LP 策略**，置信度低于直接的 DEX Swap 买入。

建议置信度权重：

| 信号来源 | 置信度权重 |
|---------|:--------:|
| 绝对确认买入（DEX Swap） | 1.0 |
| 推定确认买入 | 0.7 |
| 策略型 LP 隐含买入（区间穿越完成） | 0.5 |
| 策略型 LP 隐含买入（区间设定但未穿越） | 0.2（预期信号，非已完成） |

### 1.4 对五类行为识别的影响

在 Event Layer 的五类行为中，LP 操作现在需要**二次判定**：

```
原来:
  LP 添加/撤出 → 统一归入"结构行为"

修正后:
  LP 添加/撤出
  ├── 做市型 LP (C1) → 结构行为 (不变)
  ├── 策略型 LP + 区间穿越 → 真实买入/卖出 (提升分类)
  └── 策略型 LP + 区间未穿越 → 结构行为 + 附加"方向性意图"标签
```

## 修正二：指标 4-7 的分组逻辑重构

### 2.1 问题

v2 将指标 4-7 统一标注为"风险/结构分"，并在总分计算中作为减分项（`CBS_Net = Positive_Adj - Risk_Base`）。这个分组存在逻辑问题：

- 交易所净**流出**（提币）通常是看多信号，不是风险
- 持仓**集中**可以是鲸鱼重仓看好，也可以是控盘风险
- 实体异动可以是正面（鲸鱼建仓）也可以是负面（VC 减仓）
- LP 增加是信心信号，LP 撤出才是风险信号

**本质问题：这 4 个指标都是双向的（可正可负），不应被预设为"风险"方向。**

### 2.2 修正方案

**取消"正向基础分 vs 风险/结构分"的二元对立分组，改为统一的"信号维度"体系。**

每个指标独立计算正负分值，最终通过加权汇总得到 CBS 总分。

#### 新的指标分组逻辑

| 分组 | 指标 | 分组逻辑 | 说明 |
|------|------|---------|------|
| **资金方向信号** | 指标 1: 净流入/流出 | 核心方向性判断 | 直接回答"钱在往哪流" |
| | 指标 2: 连续增持/减持天数 | 方向性的时间维度 | 回答"方向持续了多久" |
| | 指标 3: 参与动态 | 方向性的广度维度 | 回答"多少人在参与、方向是否一致" |
| **市场结构信号** | 指标 4: 交易所净流量 | CEX 层面的供需变化 | 独立数据源，补充链上 DEX 信号 |
| | 指标 5: 持仓集中度变化 | 筹码分布的结构变化 | 反映持仓结构健康度 |
| **行为追踪信号** | 指标 6: 标记实体异动追踪 | 关键实体的异常行为 | 投研切入点，触发深度分析 |
| | 指标 7: LP 行为变化 | 流动性市场微观结构 | 反映流动性环境和参与者信心 |
| **修正项** | Adj: Perp 仓位修正 | 衍生品敞口对现货信号的修正 | 仅修正资金方向信号组 |

#### 新的 CBS 总分计算逻辑

```
旧逻辑 (v2):
  CBS_Net = PerpAdj(正向1,2,3) - Risk(4,5,6,7)    ← 问题：4-7 被强制设为减分项

新逻辑 (v2.1):
  每个指标独立计算有向值 (正=看多信号, 负=看空/风险信号, 0=中性)

  Direction_Score = w1×指标1 + w2×指标2 + w3×指标3        // 资金方向
  Structure_Score = w4×指标4 + w5×指标5                    // 市场结构
  Tracking_Score  = w6×指标6 + w7×指标7                    // 行为追踪

  CBS_Raw = Direction_Score + Structure_Score + Tracking_Score
  CBS_Final = CBS_Raw × PerpModifier                       // Phase 2 启用

  其中:
  - 指标4 = 交易所净流量，正值=净流出(看多)，负值=净流入交易所(看空)
  - 指标5 = 集中度变化，需要结合上下文判断正负（详见下文）
  - 指标6 = 实体异动，按实体类型和行为方向独立判断正负
  - 指标7 = LP 行为，增加=正向，撤出=负向，策略型LP按区间判断
```

#### 指标 5（持仓集中度）的方向性判断

持仓集中度变化是所有指标中语义最复杂的。同样是"集中度上升"，在不同场景下含义相反：

| 场景 | 集中度变化 | 信号方向 | 理由 |
|------|----------|---------|------|
| A 类（主动买方）地址集中度上升 | ↑ | **正向** | 聪明钱在加仓 |
| B 类（潜在卖方）地址集中度上升 | ↑ | **负向** | 即将卖出的筹码更集中，风险更大 |
| 散户地址集中度下降（分散化） | ↓ | **正向** | 筹码从弱手转向更多持有者，结构更健康 |
| A 类地址集中度下降 | ↓ | **负向** | 聪明钱在减仓/分散退出 |

**修正**：指标 5 的正负方向不能单看集中度数值，必须**结合持仓地址的一级分类**来判断。这与你在图 2 中设计的 A/B/C/D/E 分类体系直接呼应。

## 修正三：EVM 全链监测可行性分析

### 3.1 问题

v2 建议"Day 1 支持 Ethereum + Base + Arbitrum + Solana"。实际上是否应该覆盖更多 EVM 链（BSC、Polygon、Avalanche 等）？

### 3.2 可行性分析

| 维度 | 分析 |
|------|------|
| **技术可行性** | EVM 链之间的数据结构高度一致——相同的 ABI、相同的 Event Log 格式（Transfer, Swap, Mint/Burn）。一套 Event Layer 代码理论上可以复用到**所有 EVM 链**，仅需更换 RPC 端点和合约地址。技术上完全可行。 |
| **数据获取** | 主要方式：(a) 公共 RPC（免费但速率有限）；(b) 付费节点服务（Alchemy, QuickNode, Chainstack 等，各 EVM 链均已覆盖）；(c) 数据索引平台（Allium, Goldsky, Chainbase 均支持主流 EVM 链的结构化数据）。获取成本随链数线性增长但非指数级。 |
| **成本** | 每增加一条 EVM 链，主要增量成本在 RPC 调用量和存储。按 Alchemy 定价，每条链约 $49-199/月（Growth Plan）。5-8 条 EVM 链的总数据成本在可控范围内。 |
| **信号价值** | 不同链的信号价值差异很大（见下表）。 |

### 3.3 各 EVM 链的信号价值评估

| 链 | 日活跃地址 | DeFi TVL | 高质量资金活跃度 | CBS 信号价值 | 优先级 |
|-----|---------|---------|:--:|:--:|:--:|
| **Ethereum** | 极高 | 极高 ($30B+) | ★★★★★ | ★★★★★ | **P0 必须** |
| **Base** | 高 | 高 ($5B+) | ★★★★ | ★★★★★ | **P0 必须** |
| **Arbitrum** | 高 | 高 ($3B+) | ★★★★ | ★★★★ | **P0 必须** |
| **Solana** (非EVM) | 极高 | 高 ($5B+) | ★★★★ | ★★★★★ | **P0 必须**（需独立适配） |
| **BSC** | 极高 | 中高 ($4B+) | ★★★ | ★★★ | **P1 推荐** |
| **Polygon** | 高 | 中 ($1B+) | ★★ | ★★ | **P2 可选** |
| **Optimism** | 中 | 中 ($1B+) | ★★★ | ★★★ | **P1 推荐** |
| **Avalanche** | 中低 | 低 | ★★ | ★★ | **P2 可选** |
| **其他 EVM** | 低 | 低 | ★ | ★ | **P3 按需** |

### 3.4 推荐的分阶段覆盖策略

```
Phase 0 (MVP):
  Ethereum + Base + Arbitrum + Solana (4链)
  → 覆盖 ~80% 的高质量资金活动

Phase 1 (扩展):
  + BSC + Optimism (6链)
  → 覆盖 ~90%+

Phase 2 (全面):
  + Polygon + Avalanche + 其他热门 EVM (8-10链)
  → 基本全覆盖
```

### 3.5 关键工程建议

由于 EVM 链之间数据结构一致，建议**从 Phase 0 就设计为"链无关"的架构**：

```python
# 伪代码示例：链无关的 Event Layer 设计
class ChainConfig:
    chain_id: int
    rpc_url: str
    dex_contracts: dict  # {protocol_name: {factory, router, ...}}
    cex_addresses: set
    known_labels: dict

class EventListener:
    def __init__(self, chain_config: ChainConfig):
        self.config = chain_config

    def process_swap_event(self, event):
        # 统一的 Swap 事件处理逻辑，与链无关
        ...

# 每条链只需要一份 ChainConfig，核心逻辑完全复用
ethereum = EventListener(ChainConfig(chain_id=1, ...))
base = EventListener(ChainConfig(chain_id=8453, ...))
bsc = EventListener(ChainConfig(chain_id=56, ...))  # Phase 1 加入
```

这样新增一条 EVM 链的边际成本仅为：**编写一份 ChainConfig（DEX 合约地址、CEX 地址等）+ 开通 RPC 节点**。

### 3.6 BSC 的特殊考虑

BSC 值得额外关注的原因：

1. **PancakeSwap 是全球最大的 DEX 之一**，交易量不亚于 Uniswap
2. **BSC 上有大量 Binance 生态项目**，Binance Labs 投资的项目 Token 通常最先在 BSC 上有流动性
3. **BSC 的"聪明钱"画像与 Ethereum 有差异**——更多亚洲机构和交易员，可以扩展白名单的多样性
4. **BSC Gas 极低**，做市商和交易员行为更频繁，数据量更大但信号密度可能更低（需要更强的噪声过滤）

**建议：BSC 提升至 P0 末期或 P1 初期，在 MVP 验证核心逻辑后尽快接入。**

## 修正四：做市商信号价值重新定位

### 4.1 问题

v2 在多处将做市商（C1 类）视为"中介通道"，其行为被弱化甚至排除（例如 Perp 修正中建议排除 C1 地址、LP 分析中将 C1 视为无方向性的做市行为）。但做市商在市场中是极其重要的角色，其行为可能反映背后的客户关系、机构预期或自营判断。

### 4.2 客观分析

**做市商行为的信号复杂性在于其"双重身份"**：

| 身份层 | 行为特征 | 信号价值 |
|--------|---------|---------|
| **做市服务（Agency）** | 为项目方提供流动性、维护价格稳定 | **低直接信号**——这是合约义务而非市场观点 |
| **自营交易（Proprietary）** | 用自有资金做方向性押注 | **极高信号**——做市商拥有最全面的市场微观结构信息 |
| **客户关系推断** | 突然为某个新 Token 提供做市服务 | **中高信号**——暗示该项目可能有重要进展（上所、合作等） |
| **风险管理行为** | 大幅削减某 Token 的做市深度或完全退出 | **极高信号**——做市商比任何人更早发现流动性风险 |

**关键洞察：不是所有做市商行为都没有方向性信号。问题不在于"是否关注做市商"，而在于"如何区分做市商的哪些行为是信号、哪些是噪声"。**

### 4.3 做市商行为分类与信号提取

建议将做市商（C1 类）的行为细分为 4 种模式，分别处理：

#### 模式 A：常规做市（噪声）

- **特征**：在已知做市对的池中，持续的 LP 调仓、双边报价调整、库存再平衡
- **识别方式**：固定的做市对列表 + 规律性的调仓频率
- **处理**：过滤，不计入 CBS 方向性指标
- **但仍计入指标 7**（LP 行为变化）作为流动性环境参考

#### 模式 B：做市深度异常变化（重要信号）

- **特征**：
  - 某个做市对的流动性深度突然大幅下降（撤出 50%+）
  - 或者 spread 突然拉大
  - 或者从某个 Token 完全撤出做市
- **信号含义**：做市商可能预见到负面事件（项目风险、即将 delist、流动性危机）
- **处理**：**高权重纳入指标 7 + 指标 6（实体异动追踪）**
- **投研触发**：生成异动报告，标记"做市商风控行为"

#### 模式 C：新做市关系建立（中等信号）

- **特征**：
  - 做市商首次为某个 Token 提供流动性
  - 特别是在该 Token 上线主流 DEX 之前
- **信号含义**：可能暗示即将上所、项目方合作关系、或做市商看好该项目
- **处理**：**纳入指标 3（参与动态）的一个子维度**，但标注为"做市介入"而非"主动买入"
- **投研触发**：标记为"新做市关系"，建议研究员关注该项目动态

#### 模式 D：方向性自营交易（极高信号）

- **特征**：
  - 做市商地址在做市范围之外进行大额单向交易
  - 或者通过关联地址（非做市地址）进行方向性操作
  - 或者在非做市对的 Token 上进行买入/卖出
- **识别方式**：行为偏离该地址的做市基线（Contrast Layer - Self Baseline）
- **信号含义**：做市商的自营判断，信息含量极高
- **处理**：**高权重纳入指标 1（净流入/流出）+ 指标 6（实体异动）**
- **投研触发**：高优先级异动报告

### 4.4 做市商行为的特殊信号场景

以下场景对投研团队具有特别高的价值：

| 场景 | 描述 | 信号强度 | 投研动作 |
|------|------|:--------:|---------|
| **做市商集体撤出** | 多家做市商同时减少某 Token 的流动性 | ★★★★★ | 立即关注该 Token 的风险面 |
| **做市商反向操作** | 做市商在为某 Token 做市的同时，通过其他地址做空或卖出该 Token | ★★★★★ | 深度调查——可能是利益冲突的先行指标 |
| **做市商跨链部署** | 做市商在新链上为某 Token 首次部署流动性 | ★★★★ | 关注该 Token 的多链扩展计划 |
| **做市商深度加码** | 做市商大幅增加某 Token 的做市深度（超出合约义务） | ★★★ | 可能看好该 Token 的交易量增长 |
| **做市商库存偏移** | 做市商有意让库存偏向持有更多某 Token（而非稳定币端） | ★★★★ | 隐含看多——做市商愿意承担更多该 Token 的方向性风险 |

### 4.5 对分类体系的修正

**C1（做市商）不应被简单归入"中介通道"然后忽略。** 建议修正为：

```
C1 做市商
├── C1a 常规做市行为 → 中介通道（原有定位，保持不变）
├── C1b 做市异常行为 → 提升为行为追踪信号源（纳入指标 6/7）
├── C1c 新做市关系 → 纳入参与动态（指标 3）
└── C1d 自营方向性交易 → 提升为资金方向信号源（纳入指标 1/3）
```

**对 Perp 修正项的相应调整**：

v2 建议"C1 类地址的 Perp 仓位不纳入修正项计算"。修正为：

- **C1a/C1b（做市行为）的 Perp 仓位不纳入**——这些是 delta-neutral 的做市对冲
- **C1d（自营方向性交易）的 Perp 仓位应当纳入**——这代表做市商自身的方向性判断

### 4.6 Wintermute 案例分析

以 Wintermute 为例，说明为什么做市商信号不可忽视：

Wintermute 是最活跃的链上做市商之一。公开信息显示：
- 在 2024 年 Solana 生态爆发前，Wintermute 显著增加了 SOL 相关 Token 的做市深度
- 在某些 Token 崩盘前（如 LUNA），Wintermute 的做市深度提前数天开始萎缩
- Wintermute 的自营交易账户历史胜率在行业中属于顶级

**如果 CBS 系统忽略做市商，就等于放弃了市场中最有信息优势的参与者之一的信号来源。**

## 修正五：系统定位校准——投研发现工具而非高频交易

### 5.1 定位声明

**CBS 系统是团队内部的投研信号发现工具。它的用户是人类分析师，不是交易机器人。**

这个定位校准对整个系统设计产生深远影响。

### 5.2 定位对设计决策的影响

| 设计维度 | 高频交易系统（不是我们） | 投研发现系统（我们的定位） | 影响 |
|----------|---------------------|----------------------|------|
| **延迟要求** | 毫秒级 | 分钟到小时级 | 不需要自建节点做 mempool 监控，公共 RPC/数据索引平台完全够用，**大幅降低基础设施成本** |
| **信号输出形式** | 自动执行交易指令 | 异动报告 + Dashboard，人类分析师介入决策 | 信号不需要精确到可直接交易的程度，更重要的是**可解释性** |
| **准确率 vs 召回率** | 准确率极高（错误直接亏钱） | **召回率优先**（宁可多报不漏报，人类会过滤误报） | 推定确认买入/卖出的阈值可以适当放宽 |
| **实时性** | 实时流处理（Kafka/Flink） | **批处理 + 准实时触发**即可 | 可以用更简单的技术栈（定时任务 + WebSocket 推送异动） |
| **信号颗粒度** | 单笔交易级别 | **实体级 / Token 级聚合** | 不需要追踪每一笔交易，聚合后的趋势和异常更有价值 |
| **告警机制** | 自动执行 | **推送异动报告，等待人类判断** | 关键信号可推送到 Slack/飞书/邮件 |
| **误报容忍度** | 极低 | **中等**（人类会过滤） | 可以降低各环节的确认阈值 |

### 5.3 "投研发现"定位下的输出设计

CBS 的核心输出不是一个分数，而是**结构化的异动报告**，供分析师决定是否深入调研：

#### 日常输出：Token 级别 CBS 面板

```
Token: $XYZ
CBS Score: 72/100 (过去24h)
趋势: ↑↑ (连续3天上升)

资金方向信号:
  净流入: +$2.3M (A3类匿名高手贡献68%)
  增持天数: 5天
  参与动态: 新增3个实体, 净方向 87% 看多, 覆盖率 4.2%

市场结构信号:
  交易所: 净流出 $1.1M (Binance 为主)
  集中度: Top 10 持仓占比 +2.3% (主要由A类地址增持)

行为追踪信号:
  实体异动: Wintermute 新增做市 [C1c]
  LP变化: 3个策略型LP在当前价格-10%处设置买入区间

修正项:
  Perp: 暂无数据

置信度: ★★★★ (4/5)
建议动作: 建议分析师关注，多个独立信号指向看多
```

#### 异动触发：实时推送

```
🔔 CBS 异动报告 | $XYZ | 2026-04-13 14:32 UTC

触发条件: A1类机构(Paradigm关联地址)首次买入$XYZ

事件详情:
  地址: 0x7a25...3f8b (Paradigm Fund III)
  行为: 绝对确认买入
  金额: $1.8M (通过1inch路由)
  成本基础: $2.34/token

上下文:
  该实体过去180天未参与$XYZ
  该实体近30天整体仓位:稳定币占比从62%降至41%(风险偏好转多)
  同风格实体(趋势配置型)近7天对$XYZ: 2买入/0卖出

Contrast Layer:
  Self: ★★★★★ 显著偏离基线(180天未动)
  Peer: ★★★★ 同类实体有共振
  Object: ★★★★ $XYZ买方质量近7天持续提升

建议: 高优先级关注。分析师请评估:
  1. $XYZ 近期是否有催化事件? (→ 查ECS模块)
  2. 叙事层面是否有扩散? (→ 查NDS模块)
  3. 基本面采用数据? (→ 查BAS模块)
```

### 5.4 对技术架构的简化

鉴于投研发现定位，技术栈可以显著简化：

| 组件 | v2 方案（偏高频） | v2.1 修正方案（投研发现） | 理由 |
|------|----------------|----------------------|------|
| 数据管道 | Kafka + Flink | **定时批处理 + 事件触发器** | 不需要毫秒级实时流处理 |
| 计算引擎 | 实时流计算 | **每小时批量计算 + 大额异动实时触发** | 分析师不需要秒级更新 |
| 存储 | Kafka + ClickHouse + Redis | **PostgreSQL/ClickHouse + 简单缓存** | 降低运维复杂度 |
| 后端 | Go (高性能) + Python (分析) | **Python (FastAPI) 为主** | 不需要极致性能 |
| 前端 | 复杂实时 Dashboard | **Streamlit/Grafana + 消息推送** | MVP 阶段用现成工具 |
| 告警 | 自动交易执行 | **Slack/飞书 Webhook + 邮件** | 人工介入为主 |

**核心简化原则：用"小时级批处理 + 大额异动即时触发"代替"全量实时流处理"。**

具体而言：
- **每小时**：批量计算所有 Token 的 7 个指标 + CBS Score，更新 Dashboard
- **即时触发**：当检测到以下事件时，立即生成异动报告并推送：
  - A 类地址的绝对确认买入 > $500K
  - 多个独立高质量实体在 4h 内同向操作同一 Token
  - 做市商异常行为（模式 B/D）
  - 连续增持天数突破 7 天
  - 新的 A1 类实体首次参与某 Token

### 5.5 对时间粒度的简化

| v2 方案 | v2.1 修正方案 | 理由 |
|---------|-------------|------|
| 1h / 4h / 24h / 7d / 30d 五个窗口并行 | **24h / 7d / 30d 三个窗口** | 1h/4h 对投研分析师价值有限，增加计算成本但不增加决策质量。异动触发已经覆盖了"即时"需求。 |

## 融合后的 CBS v2.1 完整指标体系

### 指标体系

| # | 指标名称 | 分组 | v2→v2.1 变更 |
|---|---------|------|-------------|
| 1 | 高质量资金净流入/流出 | 资金方向 | **增加**：纳入策略型 LP 隐含买卖信号（加权 0.5），纳入做市商自营交易信号（C1d） |
| 2 | 连续增持/减持天数 | 资金方向 | 不变 |
| 3 | 高质量资金参与动态 | 资金方向 | **增加**：做市商新做市关系（C1c）纳入参与动态的一个子维度 |
| 4 | 交易所净流量 | 市场结构 | **修正**：不再预设为"风险指标"，正/负值独立判断 |
| 5 | 持仓集中度变化 | 市场结构 | **修正**：结合持仓地址的一级分类判断正负方向 |
| 6 | 标记实体异动追踪 | 行为追踪 | **增加**：纳入做市商异常行为（C1b 做市深度异变、C1d 自营交易） |
| 7 | LP 行为变化 | 行为追踪 | **增加**：LP 方向性信号提取子模块，区分做市型 vs 策略型 |
| Adj | Perp 仓位修正 | 修正项 | **修正**：仅排除 C1a/C1b 的 Perp 仓位，C1d 自营仍纳入 |

### CBS 总分逻辑 (v2.1)

```
每个指标独立输出有向值: [-100, +100]
  正值 = 看多信号
  负值 = 看空/风险信号
  0 = 中性/无信号

CBS_Score = Σ(wi × 指标i) × PerpModifier

权重建议 (初始值，需回测调优):
  w1 (净流入)    = 0.25
  w2 (增持天数)  = 0.15
  w3 (参与动态)  = 0.20
  w4 (交易所流量) = 0.10
  w5 (持仓集中度) = 0.10
  w6 (实体异动)  = 0.10
  w7 (LP行为)    = 0.10

CBS_Score 范围: [-100, +100]
  +60 ~ +100: 强看多信号
  +20 ~ +60:  温和看多
  -20 ~ +20:  中性/信号不明确
  -60 ~ -20:  温和看空
  -100 ~ -60: 强看空信号
```

### 关键设计变更总结 (v2 → v2.1)

| 变更点 | v2 | v2.1 | 理由 |
|--------|-----|------|------|
| LP 信号 | 独立于买卖信号 | 策略型 LP 的隐含买卖纳入方向性指标 | LP 在 Uniswap V3 下具有真实的方向性语义 |
| 指标 4-7 分组 | "风险/结构分"（固定负向） | 独立有向值（可正可负） | 这些指标本身是双向的，不应预设方向 |
| 做市商定位 | "中介通道"，信号弱化 | 四种行为模式分别处理，异常和自营行为是高价值信号 | 做市商是市场中信息优势最强的参与者之一 |
| 技术架构 | 实时流处理 | 小时级批处理 + 异动即时触发 | 投研发现定位不需要毫秒级延迟 |
| 时间窗口 | 5 个（1h/4h/24h/7d/30d） | 3 个（24h/7d/30d）+ 异动即时触发 | 投研场景下 1h/4h 价值有限 |
| EVM 链覆盖 | 4 链（ETH+Base+Arb+Sol） | Phase 0 四链 + Phase 1 尽快加入 BSC/OP | EVM 架构复用成本低，BSC 信号价值被低估 |
| 总分逻辑 | 正向分 - 风险分 | 所有指标独立有向值加权求和 | 消除了预设偏向 |
| 输出形式 | 评分 + Dashboard | **异动报告 + Dashboard + 消息推送** | 服务于分析师的决策流程 |
