# CBS 模块（资金行为信号）— 逻辑总览

> 用途：快速理解模块二的整体逻辑链路，适合内部沟通和评审
> 配套文档：`cbs-v4.1-engineering.md`（工程版 PRD）

---

## CBS 要解决什么问题

**在链上找到聪明钱，看懂它们在做什么，判断这些动作有多大参考价值，然后推送给分析师。**

具体而言：某个 Token 上，有哪些高质量资金正在买入/卖出/移动？这些行为和它们过去的表现比起来，是高确信度的动作还是试探性的？这些信号叠在一起，整体指向看多还是看空？

## 核心链路（六步）

```
① 找到高质量资金实体，建立白名单
        ↓
② 回测每个实体的历史链上行为，构建实体画像（胜率、风格、偏好）
        ↓
③ 持续监控白名单实体的链上行为，识别有效动作
        ↓
④ 每次异动与该实体画像对比——这次像不像它过去赚钱时的操作？
        ↓
⑤ 汇总所有异动计算 7 个指标 + CBS 总分，检测是否触发推送
        ↓
⑥ 推送后追踪价格表现（回测），结果反馈回实体画像，形成闭环
```

## 每一步的关键设计

### ① 白名单——谁是"高质量资金"

**来源**：Arkham/Nansen 标签 + 链上溯源 + 手动添加。规模 ≥3,000 实体。

**分类**：5 大类 18 子类。核心不是按"它是什么机构"分，而是按**"它对某个 Token 是买方还是卖方"**分。

- A 类（主动买方）：机构/KOL/匿名高手 — 看它们买什么
- B 类（潜在卖方）：VC/项目方 — 看它们什么时候卖
- C 类（中介通道）：做市商/交易所/路由 — 常规行为过滤，异常行为高价值
- D 类（去噪）：MEV/Bot/女巫 — 直接排除
- E 类（特殊观察）：借贷/清算/质押 — 不直接买卖但提供上下文

**关键**：不同分类需要关注的行为完全不同。A 类看"买了什么、买了多少"；B 类看"什么时候卖、冷钱包有没有异动"；C1 做市商看"常规 vs 异常"。

### ② 实体画像——"这个人过去表现如何"

**不是人为标注，而是通过回测链上历史数据计算出来的。**

系统拉取每个实体过去 6 个月的所有链上买卖，配对为完整交易（买入→卖出），逐笔计算 PnL/持仓时间/仓位占比等，聚合后生成画像：

- **胜率组**：整体胜率、30d 胜率、90d 胜率
- **盈亏组**：平均 PnL、盈亏比
- **持仓组**：平均持仓天数、平均仓位占比、最大单注
- **节奏组**：月均交易次数、每笔交易平均建仓次数
- **择时组**：建仓位置（左侧/右侧）、事件驱动度
- **偏好组**：偏好市值区间、偏好链、板块分布

基于这些指标自动生成三层风格标签：

- **A 层**（靠什么赚钱）：事件驱动型 / 趋势配置型 / 早期发现型 — 给分析师看
- **B 层**（怎么操作）：阶梯建仓 / 一次性重仓 / 左侧 / 右侧 — 给系统做异常对比
- **C 层**（最近靠谱吗）：近期有效 / 近期衰减 — 调整信号权重

### ③ 链上行为识别——"它做了什么"

所有链上活动归入五类：

| 行为 | 含义 | 处理 |
|------|------|------|
| 真实买入 | 风险敞口真实增加（7 种链上路径） | 计入指标 |
| 真实卖出 | 风险敞口真实减少（7 种链上路径） | 计入指标 |
| 迁移 | 地址间转移，不代表观点（8 种） | 部分计入指标 |
| 结构 | 做市/路由/桥接等执行层（7 种） | 穿透或过滤 |
| 噪音 | MEV/Bot 等无意义（6 种） | 丢弃 |

**核心设计**：买入不能按"收到了 Token"来算，而是按**风险敞口是否真实增加**来算。VC 轮分配、空投、LP 撤除后收币都不算买入。LP 的方向性操作（如下方窄区间 = 限价买入）可以算。

### ④ 画像对比——"这次行为对它来说正不正常"

**这是 CBS 最核心的设计。**

当检测到实体异动时，系统自动将本次行为与其画像对比，输出**行为匹配分**：

```
实体 SM_0042 画像: 阶梯建仓, 平均仓位12%, 右侧确认, 30D胜率68%

本次: 一次性买入 $800K, 仓位15%, 右侧确认

对比结果:
  仓位 15% > 均值 12% → 高于惯常 → 认真下注
  一次性 vs 惯常阶梯 → 偏离基线 → 紧迫感
  右侧 → 符合风格 ✓
  历史上类似操作胜率 78% > 整体 68%

输出: HIGH_CONVICTION — 该实体的高确信度操作
```

这直接回答了"这次异动到底有多大参考价值"。

### ⑤ 指标与评分——"总体情况如何"

7 个指标不分组，各自输出有向值，加权求和得到 CBS Score：

| 指标 | 回答什么 | 权重 |
|------|---------|:----:|
| 净流入/流出 | 白名单买卖净方向 | 0.25 |
| 连续增持/减持天数 | 方向持续多久 | 0.15 |
| 参与动态 | 多少人参与、方向一致性 | 0.15 |
| 交易所净流量 | CEX 端资金供需 | 0.15 |
| 持仓集中度 | 筹码向谁集中 | 0.10 |
| 结构性事件 | 非买卖的方向性信号 + 事件明细 | 0.10 |
| LP 动态 | 流动性层面的资金异动 | 0.10 |
| Perp 修正 | 衍生品对信号的增强/削弱 | 乘数 |

每个指标的打分逻辑：收到 Event Layer 输出的标准化事件 → 按该指标的计算规则汇总 → 归一化到 [-100, +100] → 乘以权重 → 汇总为 CBS Score。

### ⑥ 回测闭环——"推送的信号准不准"

推送后追踪 24h/7d/30d 的价格表现。结果反馈回实体画像（更新胜率等指标），也用于优化系统参数（指标权重、推送阈值等）。

## 系统运行方式

**两种触发模式并行**：

- **白名单主动扫描**（常驻）：每小时扫描全部白名单地址 → 发现异动 → 推送
- **跨模块被动响应**（按需）：其他模块发现某 Token 有异动 → 通知 CBS 检查 → "白名单无异动"本身也是信号

## 输出物

1. **异动推送**（Slack/飞书）：事件 + 实体画像 + 行为匹配分 + CBS 指标
2. **Token CBS 面板**（Dashboard）：每小时更新的 7 指标 + 总分
3. **实体画像卡**：每个白名单实体的画像页
4. **跨模块 API**：供其他模块查询

## 与其他模块的关系

| 模块 | CBS 与其的关系 |
|------|-------------|
| MTS（市场交易） | MTS 发现市场异动 → 触发 CBS 检查资金面 |
| NDS（叙事传播） | CBS 发现资金异动 → NDS 检查是否有叙事支撑 |
| ECS（事件催化） | ECS 的解锁/上所预警 → CBS 提升对应 Token 的监控灵敏度 |
| BAS（业务采用） | TVL 等基本面指标归 BAS；CBS 只看 LP 层面的资金动静 |
