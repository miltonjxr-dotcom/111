# CBS 模块 v3.1 — 结构反思与五项深度修正

> 版本: v3.1 | 日期: 2026-04-14
> 本版本对 v3.0 进行五项结构性修正

---

## 一、v1 vs v3 叙事结构对比

### 1.1 客观对比

| 维度 | v1 (12章线性叙事) | v3 (9章模块化) |
|------|-----------------|--------------|
| **叙事逻辑** | 问题驱动——"地址从哪来→怎么分类→行为模式→如何映射到指标→指标是否完备→盲区→落地" | 系统驱动——"定位→分类→标签→行为→架构→指标→评分→落地" |
| **读者体验** | 像读一篇研究报告，每章回答一个具体问题，**为什么这么做**的逻辑链清楚 | 像读一份技术规范，每章是一个系统模块，**做什么**清楚但**为什么**弱化 |
| **产品经理视角** | 容易理解设计背后的思考过程 | 容易对照开发，但如果不看 v1-v2.4 的过程文档会缺少 context |
| **可维护性** | 全部在一篇中，更新时需要通篇修改 | 模块化更好维护 |

### 1.2 诚实评价

**v1 的叙事结构确实更适合"说服人"和"建立共识"**。它的 12 章是一个递进推导的过程——每一章的结论是下一章的输入。这对一个尚在探讨阶段的产品方案来说至关重要，因为团队需要理解"为什么是这样"而不仅仅是"是什么"。

**v3 的结构更适合"指导实施"**。当设计已确定、进入开发阶段时，工程师需要的是明确的规范而非推导过程。

**建议：保留 v1 的叙事逻辑作为 v3 的组织框架。** 即：在 v3 的每个章节中增加"为什么这样设计"的简要推理，而不是只列规范。最终合并文档会同时采用两种风格。

## 二、A4 稳定币激活型买方评估 + 各分类行为模式

### 2.1 A4 是否包含在 A1/A2/A3 中？

**是的，A4 确实与 A1/A2/A3 存在包含关系。** 诚实分析：

| 问题 | 分析 |
|------|------|
| 一个机构(A1)长期持有稳定币后首次买入风险资产 | 这个实体是 A1，它的这次行为具有"稳定币激活"特征 |
| 一个匿名高手(A3)长期持有稳定币后首次买入 | 这个实体是 A3，这次行为同样是"稳定币激活" |

**"稳定币激活"不是一种实体类型，而是一种行为特征。** 它描述的不是"这个实体是谁"，而是"这个实体这次做了什么类型的动作"。

**结论：取消 A4 作为独立的一级/二级分类。** 将"稳定币激活型买入"作为一种**行为标签**——当任何 A/B/E 类实体从长期稳定币持仓状态转向风险资产时，自动标注 `STABLECOIN_ACTIVATION`。

修正后的 A 类：
```
A 主动买方
├── A1 机构买方
├── A2 公开人物/KOL 买方
└── A3 匿名高质量买方

行为标签 (可附加到任何 A 类实体的某次操作):
  STABLECOIN_ACTIVATION: 从长期稳定币持仓转入风险资产
```

### 2.2 各分类需要看重的行为模式

以下逐类分析每种资金角色**最需要看重的行为**，以及共性和特性。

#### A1 机构买方

| 看重的行为 | 为什么重要 |
|-----------|---------|
| 首次买入某 Token | 新的机构配置方向 |
| 加仓行为（在已持仓 Token 上增持） | 信心加强 |
| 买入后质押/锁仓 | 长期持有意图确认 |
| 稳定币激活（从长期稳定币→风险资产） | 沉默资金苏醒 |
| 持仓占比显著变化 | 仓位管理策略变化 |

#### A2 公开人物/KOL

| 看重的行为 | 为什么重要 |
|-----------|---------|
| 首次买入某 Token | 可能带动关注 |
| 大额加仓 | 真金白银（vs 嘴上说说） |
| 买入后是否在社交媒体公开 | 公开=可能表演，不公开=可能更真实 |
| 清仓行为 | 丧失信心，且可能引发跟随者抛售 |

**特殊注意：A2 有"表演折扣"——知道被追踪的人可能做出非真实意图的操作。**

#### A3 匿名高质量买方

| 看重的行为 | 为什么重要 |
|-----------|---------|
| 首次参与某 Token | 新 Alpha 信号（最高信号价值） |
| 多个 A3 同时买入同一 Token | 独立发现共振 |
| 建仓速度和规模 | 急切程度反映信息时效性 |
| 买入后持有周期 | 短持=投机，长持=配置 |
| 获利了结的模式 | 分批卖出=有纪律，恐慌卖出=判断变化 |

#### B1 机构供给方

| 看重的行为 | 为什么重要 |
|-----------|---------|
| 解锁后的第一步行为 | 立即转 CEX=减仓，质押=继续持有，LP=观望 |
| 冷→热钱包转移 | 减仓前兆 |
| 向 CEX 大额充值 | 即将卖出信号 |
| 通过 OTC/大宗减仓 | 比直接在市场卖出的冲击更小，但仍是减持 |
| 解锁后长期不动 | 最强的持有信号 |

#### B2 项目方/基金会/Treasury

| 看重的行为 | 为什么重要 |
|-----------|---------|
| 大额 Token 转出（非常规运营） | 可能是抛售 |
| 回购自家 Token | 看好信号 |
| 为自家 Token 添加 LP | 维护流动性/护盘 |
| 向做市商转入 Token | 新做市合约或上所准备 |
| 向 CEX 充入自家 Token | 可能上所或出售 |

#### C1 做市商（异常行为）

| 看重的行为 | 为什么重要 |
|-----------|---------|
| 撤出/新增做市 | 关系变化信号 |
| 做市区间上移/下移 | 公允价格判断 |
| 库存偏移 | 隐含方向性 |
| 自营方向性交易 | 信息优势极强 |
| 多做市商同向行动 | 最强信号之一 |

（C1 常规做市行为过滤，不列入）

#### C2 交易所

| 看重的行为 | 为什么重要 |
|-----------|---------|
| 大额冷钱包异动 | 交易所级别的资金调度 |
| 新 Token 出现在交易所热钱包 | 可能即将上所 |

#### D 类（去噪）

不追踪行为。**唯一需要做的是确保它们被准确识别和过滤。**

#### E1 借贷/清算

| 看重的行为 | 为什么重要 |
|-----------|---------|
| 大额抵押物追加 | 避免清算=仍看好 |
| 接近清算线 | 潜在强制卖压 |
| 清算发生 | 已实现的强制抛售 |

#### E3 治理/质押

| 看重的行为 | 为什么重要 |
|-----------|---------|
| 大额质押 | 长期信心 |
| 大额解除质押 | 可能准备退出 |
| 治理投票参与 | 深度参与的信号 |

### 2.3 共性与特性

**共性（所有分类通用）**：

| 行为模式 | 通用信号含义 |
|---------|-----------|
| 首次参与某 Token | 新注意力/新兴趣 |
| 规模异常（偏离自身基线） | 非常规决策，需要关注 |
| 稳定币激活 | 从观望转向行动 |
| 冷→热钱包转移 | 准备操作的前兆 |
| 跨链迁移 | 生态偏好变化 |

**特性差异**：

| 维度 | A 类 | B 类 | C1 做市商 |
|------|------|------|----------|
| 核心看什么 | 在买什么、买了多少、持有多久 | 什么时候卖、通过什么方式卖 | 常规做市 vs 异常行为的分界 |
| 信号方向 | 偏重看多信号 | 偏重看空/风险信号 | 双向（异常行为可看多可看空） |
| 分析重点 | 后续行为（买入→质押=加强） | 前置行为（冷→热=卖出前兆） | 偏离基线的程度 |

## 三、三层标签体系深度说明

### 3.1 "只有 3 个主标签吗？不在标签内怎么办？"

**不是只有 3 个。** v3.0 的表述过于简略。完整的标签池如下：

#### A 层主标签（完整候选池）

| 标签 | 定义 | P 级别 |
|------|------|:------:|
| 事件驱动型 | 在重大事件前精准布局获利 | P0 |
| 趋势配置型 | 顺势配置中长线仓位获利 | P0 |
| 早期发现型 | 在 Token 极早期（上线初期/首轮流动性）介入获利 | P0 |
| 均值回归型 | 在极端偏离时逆向操作获利 | P1 |
| 供需博弈型 | 利用供给端信息（解锁/做市/流动性变化）获利 | P1 |
| 叙事轮动型 | 跟随叙事热点快速轮动获利 | P1 |
| 被动配置型 | 类指数基金风格，跟随市场权重被动配置 | P2 |
| 未分类 | 行为数据不足以判定，或不符合以上任何模式 | — |

**如果某实体不在任何标签内 → 标注为"未分类"。** 这不是错误，而是数据不足。随着行为数据积累，系统会自动重新评估。V1 阶段只实现 P0 的 3 个标签 + "未分类"，其他逐步迭代。

B 层和 C 层同理，各有完整的候选标签池，V1 只实现高优精选项。

### 3.2 三层标签的作用

| 层 | 核心问题 | 给谁用 | 用在哪里 |
|---|---------|--------|---------|
| A 层（主风格） | "这个实体靠什么赚钱？" | 主要给**人类分析师**看——帮助快速判断该实体的动作应该如何解读 | 异动报告中展示 |
| B 层（执行路径） | "这个实体习惯怎么操作？" | 主要给**Contrast Layer 计算**用——判断某次行为是否偏离该实体的惯常路径 | 异常检测引擎 |
| C 层（有效性） | "这个实体最近靠谱吗？" | **两者都用**——分析师看有效性判断是否信任该信号，计算层用有效性调整权重 | 质量权重 + 异动报告 |

**具体对比场景示例**：

```
实体: 0x7a2.. (A3匿名高手)
A层: 趋势配置型
B层: 右侧确认 + 阶梯建仓 + 分批止盈
C层: 近期有效(30D胜率68%)

某次行为: 一次性重仓买入 $800K 的 $XYZ

Contrast Layer 判定:
  B层对比: 该实体惯常是"阶梯建仓"，但这次是"一次性重仓"
  → 偏离基线 → 标记为异常行为
  → 推断: 对这次操作的紧迫感高于平时，可能有时间敏感的信息

如果没有B层标签: 系统只知道"买了$800K"，无法知道这对它来说是否异常
```

### 3.3 标签如何通过计算/信息抓取获得？

| 标签 | 获取方式 | 技术实现 |
|------|---------|---------|
| **A 层 - 事件驱动型** | 统计该实体在重大事件前 72h 内建仓、事件后 7d 获利的次数占比 | 事件日历(ECS 模块) × 该实体交易记录的时间对齐 |
| **A 层 - 趋势配置型** | 统计该实体的平均持仓周期 > 14 天 + 建仓时趋势已形成（价格在 20d MA 之上） | 交易记录 × 价格数据 |
| **A 层 - 早期发现型** | 统计该实体买入时 Token 的流通市值 < $10M 或上线 < 30 天的比例 | 交易记录 × Token 上线时间/市值数据 |
| **B 层 - 阶梯建仓** | 对同一 Token 在 7d 内有 3+ 笔买入且单笔金额差异 < 50% | 交易记录聚合 |
| **B 层 - 一次性重仓** | 对某 Token 的首次买入占最终仓位的 80%+ | 交易记录 |
| **B 层 - 左侧/右侧** | 买入时价格相对近 30d 低点的位置：< 20% = 左侧，> 50% = 右侧 | 交易记录 × 价格数据 |
| **C 层 - 近期有效** | 过去 30d 已平仓交易的盈利比例 > 55% | 交易记录 × 价格追踪 |
| **C 层 - 近期衰减** | 过去 30d 胜率 < 40% 或最大回撤 > 30% | 同上 |
| **C 层 - 特定生态有效** | 在某链/某板块上的胜率显著高于整体 | 分链/分板块的胜率统计 |

**Phase 0 阶段**：人工为头部 200-500 实体标注 A 层标签（基于 Arkham/Nansen 已有标签 + 手动分析）。

**Phase 1 阶段**：基于积累的交易数据自动计算 P0 标签（3 个 A 层 + B 层高优 + C 层有效性）。

**Phase 2 阶段**：自动化覆盖全白名单实体 + P1 标签扩展。

## 四、五类行为的链上表现形式穷举与技术实现

### 4.1 真实买入——链上表现形式

| # | 链上表现 | Event Log / 技术识别方式 | 置信度 |
|---|---------|----------------------|:------:|
| 1 | **DEX Swap 买入** | `Swap` event (Uniswap V2/V3, SushiSwap, PancakeSwap, Raydium 等)。解析 `amount0In/amount1Out`，判断哪个是主要资产(USDT/USDC/ETH)流出、哪个是风险资产流入 | 1.0 |
| 2 | **聚合器路由买入** | 1inch/Paraswap/CowSwap 的 `Swapped`/`OrderFilled` event → 穿透到底层 DEX Swap → 将终端买方归为发起交易的地址（非 Router 合约） | 1.0 |
| 3 | **CEX 等额对价推定买入** | (a) 检测到白名单地址向 CEX 地址转入主要资产(USDC/ETH) → (b) 在时间窗口(24-72h)内从 CEX 提出风险 Token → (c) 金额大致匹配 → 推定为买入 | 0.6-0.8 |
| 4 | **LP 隐含买入 (区间穿越)** | Uniswap V3 的 `Burn` event → 检查撤出时该 LP 头寸已完全变为单边风险 Token（区间被穿越） → 推定为被动买入完成 | 0.5 |
| 5 | **LP 意图买入 (区间设定)** | Uniswap V3 的 `Mint` event → 检查 tickLower/tickUpper 是否全部低于当前价格 → 等效限价买单 | 0.2 |
| 6 | **跨链后买入** | 检测到 Bridge 合约的 `BridgeCompleted` event → 资金到达目标链 → 随后在目标链上发生 Swap 买入 → 整条链路归为同一实体的买入 | 1.0 (Swap部分) |
| 7 | **OTC 对价买入** | 两个地址之间的直接 `Transfer` event，一个转主要资产、另一个转风险 Token，金额匹配、时间接近 → 推定为场外对价交易 | 0.5 |

**不应计入买入的链上事件**：

| 链上事件 | 为什么排除 | 技术识别 |
|---------|---------|---------|
| Token `Transfer` from 项目方合约 | VC 轮分配/团队解锁 | 来源地址在 B2 名单中 + 无对应主要资产流出 |
| Airdrop `Claimed` event | 空投领取 | 来自已知 airdrop 合约地址 |
| LP `Burn` → 收回双边资产 | 撤出 LP 不是买入 | Burn event + 收到两种 Token |
| `Transfer` from Bridge 合约 | 跨链到账，不是买入 | 来源是 Bridge 合约地址 |

### 4.2 真实卖出——链上表现形式

（与买入对称，关键差异在于方向相反）

| # | 链上表现 | 技术识别 | 置信度 |
|---|---------|---------|:------:|
| 1 | DEX Swap 卖出 | `Swap` event，风险资产流出 + 主要资产流入 | 1.0 |
| 2 | 聚合器路由卖出 | 同买入，方向相反 | 1.0 |
| 3 | CEX 推定卖出 | 白名单转入 Token 到 CEX → 后续 CEX 提出主要资产回到链上 | 0.6-0.8 |
| 4 | LP 隐含卖出 (区间穿越) | LP 头寸完全变为主要资产（Token 全部被换走） | 0.5 |
| 5 | LP 意图卖出 (区间设定) | 区间全部高于当前价格 = 等效限价卖单 | 0.2 |

**不应计入卖出**：LP 撤除收回双边资产（非方向性）、迁移至自有冷钱包、质押解除（不等于卖出意图）

### 4.3 迁移行为——链上表现形式

| # | 链上表现 | 技术识别 | 信号含义 |
|---|---------|---------|---------|
| 1 | **冷→热钱包转移** | 同一实体的已标记冷钱包地址 → 热钱包地址的 `Transfer` | **卖出前兆**（高信号） |
| 2 | **热→冷钱包转移** | 反向 Transfer | 长期存储意图（看好信号） |
| 3 | **跨链迁移** | Bridge 合约的入金/出金事件 (`Deposit`/`Withdraw`) | 生态偏好变化 |
| 4 | **CEX 入金** | 向已知 CEX 充值地址 `Transfer` | 可能准备卖出/OTC/其他 |
| 5 | **CEX 出金** | 从 CEX 热钱包收到 `Transfer` | 可能准备链上操作/买入/DeFi |
| 6 | **同实体跨地址转移** | Gas Funder 分析确认为同一实体的不同地址间 Transfer | 内部调仓，中性 |
| 7 | **向做市商转 Token** | 向已标记 C1 地址 Transfer Token | 做市合约启动 |
| 8 | **做市商退回 Token** | C1 地址向 B2 地址 Transfer Token | 做市关系终止 |

### 4.4 结构行为——链上表现形式

| # | 链上表现 | 技术识别 | 处理方式 |
|---|---------|---------|---------|
| 1 | **Router/Aggregator 中转** | 来自 1inch/Paraswap 等已知 Router 合约的 Swap | **穿透**到发起交易的 EOA 地址 |
| 2 | **Bridge 中转** | Bridge 合约的 deposit/withdraw | **穿透**到原始发送者，追踪目标链上同一实体的后续行为 |
| 3 | **做市商常规做市** | C1 地址的高频、双向、小额 LP 调仓 | **过滤**（不计入方向性指标） |
| 4 | **Solver 执行** | CoW Protocol 等的 Solver 地址执行交易 | **穿透**到原始订单发起者 |
| 5 | **LP 全范围做市** | C4 类地址添加 V2 式全范围 LP | **不计入**方向性，仅计入指标 7 |
| 6 | **做市商常规库存平衡** | C1 在做市过程中的常规 Swap 对冲 | **过滤** |
| 7 | **闪电贷操作** | 同一 tx 中的 borrow → swap → repay | **过滤**（零风险敞口变化） |

### 4.5 噪音行为——链上表现形式

| # | 链上表现 | 技术识别 | 处理 |
|---|---------|---------|------|
| 1 | **MEV/Sandwich Attack** | 在目标交易前后各一笔反向交易，利润在同一 block 内实现 | D1 名单 + 交易模式匹配 → **丢弃** |
| 2 | **套利 Bot** | 同一 tx 或相邻 block 中的跨池/跨 DEX 价差捕获 | D1 名单 + 零持仓时间 → **丢弃** |
| 3 | **女巫/空投猎人** | 大量小额交互、批量地址、模式化操作 | D2 名单 + 行为模式匹配 → **丢弃** |
| 4 | **尘埃攻击/小额 Transfer** | 极小金额（< $1）的 Token Transfer | 金额阈值过滤 → **丢弃** |
| 5 | **合约自动执行** | 合约定时触发的自动操作（如自动复利、自动收割） | 来源为已知自动化合约 → **丢弃** |
| 6 | **测试交易** | 极小金额的探测性交易后紧跟大额交易 | 小额探测本身丢弃，大额交易正常处理 |

### 4.6 技术实现架构

```
链上数据源
  ├── EVM 链: RPC / 数据索引平台(Allium/Goldsky)
  │   → 监听 Event Logs: Transfer, Swap, Mint, Burn, Deposit, Withdraw
  │
  └── Solana: RPC / Helius
      → 监听 Program Logs: SPL Token Transfer, Raydium Swap, Orca Swap

Event Layer 处理流程:

  1. 原始事件接收
     ↓
  2. D类地址过滤 (黑名单匹配 + 行为模式匹配)
     ├── 命中 D1/D2/D3/D4 → 丢弃
     └── 未命中 → 继续
     ↓
  3. 结构行为穿透
     ├── 来源是 Router/Bridge/Solver → 追踪到原始 EOA
     ├── 闪电贷 → 丢弃
     └── C1 常规做市 → 过滤
     ↓
  4. 白名单匹配
     ├── 地址在白名单 → 继续精细分析
     └── 地址不在白名单 → 仅计入指标 5(持仓)/7(流动性)的全量统计
     ↓
  5. 行为分类 (白名单地址)
     ├── Swap event → 真实买入/卖出 (4.1/4.2)
     ├── Transfer to/from CEX → 迁移行为 (4.3)
     ├── Transfer 同实体 → 迁移行为 (4.3)
     ├── LP Mint/Burn → LP方向性判定 (区间分析)
     │   ├── 策略型 + 方向性 → 真实买入/卖出
     │   └── 全范围/做市型 → 结构行为 (仅计入指标7)
     └── 做市商行为 → 33种分类匹配
     ↓
  6. 标准化事件输出
     → 每个事件: {实体, Token, 行为类型, 金额, 置信度, 时间, 链, 标签}
```

## 五、指标 7 修正——TVL 归属 BAS

### 5.1 问题

你指出 TVL 应该属于 BAS（业务采用信号），基本面和业务采用相关的指标不应出现在 CBS。CBS 的 LP 行为应该能**反映资金动静**。

**这个判断是对的。**

### 5.2 TVL 归属分析

| 指标 | 性质 | 应归属模块 | 理由 |
|------|------|----------|------|
| TVL 绝对值 | 基本面 | **BAS** | "这个协议锁了多少钱"是业务采用指标 |
| TVL 增长率 | 基本面趋势 | **BAS** | "采用是否在增长"是 BAS 核心问题 |
| LP 数量变化 | 可以是基本面也可以是资金动静 | **边界** | 取决于看"有多少人在用"(BAS) 还是"资金在进出"(CBS) |
| 池子深度变化 | 资金动静 | **CBS** | "买卖 2% 滑点有多大"直接影响交易行为 |
| 撤池行为 | 资金动静 | **CBS** | "有人在撤流动性"是明确的资金行为 |
| 流动性集中度 | 风险结构 | **CBS** | "少数 LP 控制大部分流动性"是资金结构风险 |

### 5.3 指标 7 修正

**剔除 TVL 相关内容，聚焦于"LP 行为反映的资金动静"。**

```
指标 7 (修正后): LP 行为与流动性动态

回答的问题: "资金在流动性层面有什么异动？"

不再包含:
  ✗ TVL 绝对值/增长率 → 归入 BAS
  ✗ LP 提供者数量的绝对值 → 归入 BAS

保留/聚焦:
  7a: 池子深度变化 (±2% 区间内的挂单深度变动)
     → 深度突然变薄 = 有人在撤，风险升高
  7b: 撤池/加池行为检测 (短时间内多个非白名单LP的进出)
     → 撤池 + 深度恶化 = 高风险提醒
  7c: 流动性集中度变化 (Top 5 LP 占比变化)
     → 集中度升高 = 流动性脆弱性增加
  7d: 流动性迁移 (V2→V3、链 A→链 B 的流动性转移)
     → 反映资金在流动性层面的流向偏好

不重叠保证:
  - 白名单LP的方向性行为 → 指标1
  - 做市商异常LP行为 → 指标6
  - 指标7 = 全量LP的资金动静（深度/撤池/集中度/迁移）
```

**核心转变**：从"流动性环境好不好"（BAS 的问题）变为"流动性层面有什么资金异动"（CBS 的问题）。
