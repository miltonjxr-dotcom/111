## 一、五大模块校正定位

根据图 1 提供的最新模块定义，五大模块的准确名称和职责如下（与 v1 对比有重要修正）：

| 模块 | v1 版本名称 | 图 1 正确名称 | 核心问题 |
|------|-----------|-------------|---------|
| 模块 1 | 市场结构信号 (MSS) | **市场交易信号 (MTS)** | 市场是否已经开始交易它、拥挤它、重新定价它？ |
| **模块 2** | **资金行为信号 (CBS)** | **资金行为信号 (CBS)** | 钱是否正在流向它、撤离它，以及这些资金是否值得信。 |
| 模块 3 | 叙事动量信号 (NMS) | **叙事传播信号 (NDS)** | 市场是否正在形成共识、扩散讨论，或者只是营销噪音？ |
| 模块 4 | 链上活跃度信号 (OAS) | **事件催化信号 (ECS)** | 是否存在可能触发重估的明确事件窗口？ |
| 模块 5 | 风险预警信号 (RAS) | **业务采用信号 (BAS)** | 它是否真的被用起来了，以及这种使用是否具有质量？ |

**关键修正**：

1. **CBS 是模块 2**，而非模块 3。它的定位是"价格异动"之上、"谁在动钱"的关键层。
2. **ECS（事件催化信号）** 负责融资、上线、治理提案、解锁、合作、监管变化等结构化事件。这对后续"解锁压力"归属判断至关重要。
3. **BAS（业务采用信号）** 关注用户、留存、费用、收入、TVL、净流入、重复交互等采用指标，承担"Smart Adoption"质量穿透职责。
4. 五模块形成**统一证据框架**：MTS 看"市场有没有动" → CBS 看"资金有没有动" → NDS 看"共识有没有扩散" → ECS 看"催化有没有临近" → BAS 看"真实采用有没有变化"。

## 二、一级分类体系：对比分析与融合

### 2.1 两版本对比

**图 2 既有版本**（5 一级类 × 15 二级类）：

| 一级类 | 二级类 | 核心逻辑 |
|-------|-------|---------|
| **A 主动买方** | A1 机构买方, A2 公开人物/KOL买方, A3 匿名高质量买方 | 有明确配置意图、主动下注的资金 |
| **B 潜在卖方** | B1 机构供给方, B2 项目方/基金会/Treasury | 低成本筹码持有者，未来可能成为供给 |
| **C 中介通道** | C1 做市商, C2 交易所体系地址, C3 桥/路由/聚合器/Solver, C4 LP/池子/流动性调度 | 负责执行、路由、流动性的中间层 |
| **D 去噪排除** | D1 MEV/套利/高频机器人, D2 羊毛/女巫/营销分发, D3 污染型伪高手 | 噪声源，需要从信号中过滤 |
| **E 特殊观察** | E1 借贷/清算相关, E2 托管/代持, E3 治理/质押/验证 | 不直接计入买卖信号但需要备注和后续关注 |

**v1 版本**（7 类扁平分类）：

| 分类 | 对应 |
|------|------|
| 做市商 | → 图 2 的 C1 |
| VC/基金 | → 图 2 的 A1 + B1（混在一起了） |
| 鲸鱼个人 | → 图 2 的 A3 |
| DEX 专业交易员 | → 部分 A3 + 部分 D1 |
| 协议财库 | → 图 2 的 B2 |
| CEX 关联 | → 图 2 的 C2 |
| 稳定币巨鲸 | → 图 2 中无明确对应 |

### 2.2 客观评价

**图 2 既有版本的优势**（推荐采纳的方面）：

1. **"买方/卖方/通道/噪声/特殊"五维分类逻辑极其精准**。这不是按"实体性质"分类，而是按**该实体相对于某个标的的资金角色**分类。这对投研来说信息密度更高——研究员看到一个地址时，最想知道的不是"它是什么机构"，而是"它对这个币是买方还是卖方"。

2. **引入了"去噪排除"层（D 类）**。这是 v1 完全缺失的关键维度。MEV Bot、女巫攻击者、空投猎人如果不显式排除，会严重污染 CBS 的所有指标。

3. **引入了"特殊观察"层（E 类）**。借贷/清算相关、托管/代持、治理/质押这些行为不是简单的买卖，但提供重要上下文。v1 将其忽略了。

4. **每个二级类的"看到它时优先怎么理解"列**非常有价值，这是直接服务于投研判断的设计哲学。

**图 2 既有版本的不足**（需要修正的方面）：

1. **A 类（主动买方）和 B 类（潜在卖方）的分界有时是动态的**。同一个 VC（如 Paradigm）对某 Token 可能既是 A1（主动买入新仓位）又是 B1（持有早期低成本筹码）。需要机制来处理"同一实体在不同 Token 上角色不同"。

2. **A2（公开人物/KOL 买方）的信号纯度问题**。KOL 的链上行为可能受"表演性操作"影响——他们知道自己的地址被追踪，可能会据此做出非真实意图的操作。需要标注"公开性折扣"。

3. **C3（桥/路由/聚合器/Solver）的"不是终态"提醒非常好**，但在实现中容易被忽视。需要在数据管道层就做穿透处理。

**v1 版本的优势**（可保留的方面）：

1. **"稳定币巨鲸"作为独立类别**有信号价值。大额稳定币从沉睡到活跃，是市场情绪的先行指标。建议纳入图 2 框架的 A 类或 E 类作为子类。

**v1 版本的不足**：

1. **扁平分类无法表达"角色"**。VC/基金被当作一个整体，但同一个 VC 对不同 Token 可能是买方也可能是卖方。
2. **缺乏噪声过滤层**。
3. **"DEX 专业交易员"类别边界模糊**，与 MEV Bot、高频套利者混淆。

### 2.3 融合建议

**结论：采纳图 2 的五维分类架构作为主框架**，但做以下修正：

| 修正项 | 具体内容 |
|--------|---------|
| A 类增加 A4 | **A4 稳定币激活型买方**：长期持有大额稳定币后首次转入风险资产的地址。信号价值在于"沉默资金的苏醒"。 |
| B 类补充说明 | 明确 B 类的定义是**"当前处于潜在供给侧"**，而非永久标签。同一实体的角色应该是"Token × 时间"维度的。 |
| D 类增加 D4 | **D4 已知操纵者/Rug 关联地址**：有历史 Rug Pull、操纵记录的地址，需要独立标记，不仅仅是去噪，更是风险标记。 |
| E 类增加 E4 | **E4 稳定币深度观察**：Tether Treasury、Circle Mint 等稳定币发行方的行为，不直接计入买卖但反映宏观资金意愿。 |
| 跨类机制 | 增加"实体 × Token 角色矩阵"设计：同一实体对不同 Token 的角色可以不同。例如 Paradigm 对 ETH 是 A1（主动买方），对某个已解锁项目 Token 是 B1（潜在卖方）。 |

## 三、质量评级体系的位置问题

### 3.1 v1 方案回顾

v1 将质量评级放在"地址来源体系"中（2.4 节），在发现地址后立即进行质量评分。

### 3.2 客观评价

**这个位置安排是有问题的，但不是完全错误的。** 需要拆分为两个阶段：

#### 应该在来源阶段做的：**准入评级（Admission Score）**

| 维度 | 目的 | 说明 |
|------|------|------|
| 标签可信度 | 是否该被纳入白名单 | 多源交叉验证、标签来源质量 |
| 基础活跃度 | 是否还在活跃 | 近 90 天交易频率 |
| 最低规模门槛 | 是否达到"大资金"标准 | 管理资产 > 某阈值 |

这是一个**二元判断**（是否纳入白名单），而非精细评分。在来源阶段做复杂的多维评分是**过早优化**：你还没看到这个地址对任何 Token 的具体行为，就给它打分，依据不充分。

#### 应该在行为分析阶段做的：**动态质量评分（Dynamic Quality Score）**

| 维度 | 目的 | 为什么不适合在来源阶段 |
|------|------|---------------------|
| 历史胜率 | 评估投资能力 | 胜率是按 Token 维度计算的，不同赛道胜率可能差异很大 |
| 信息优势度 | 评估是否有内幕信息 | 需要大量交易历史才能统计 |
| 行为一致性 | 评估可追踪性 | 需要持续观察一段时间后才能判断 |
| 有效性衰减 | 评估当前状态 | 近期表现可能与历史偏离 |

### 3.3 融合建议

```
地址发现 → 准入评级（简单，二元决策）→ 纳入白名单
              ↓
         行为积累
              ↓
         动态质量评分（复杂，持续更新）
              ↓
         指标计算时加权使用
```

**具体而言**：

1. **准入评级**放在地址来源阶段（Phase 0），门槛清晰、规则简单
2. **动态质量评分**放在行为分析层（Phase 1+），基于持续积累的行为数据
3. v1 中的评分维度（历史胜率、持仓规模、信息优势度等）应归入阶段 2
4. 与图 3-4 的三层标签体系（A/B/C 层）形成互补：A/B 层是定性标签，动态质量评分是定量分数

## 四、二级分类体系：风格标签对比与融合

### 4.1 图 3-4 三层标签体系回顾

用户与 ChatGPT 讨论生成的版本采用了三层解耦架构：

**A 层：主风格标签（Alpha 来源）** — 该实体靠什么模式获利

- 规则：每个实体仅贴 1 个主标签（最多 1 个辅助）
- 高优精选：事件驱动型、趋势配置型、早期发现型

**B 层：修饰风格标签（行为执行路径）** — 惯用的建仓、持仓及退出手法

- 规则：每个实体贴 2-4 个
- 高优精选：左侧潜伏/右侧确认、阶梯建仓/一次性重仓、分批止盈/快速兑现、中线持有、高集中度

**C 层：状态与适配性标签（有效性与胜率场景）** — 当前有效性及最擅长的生态/环境

- 规则：每个实体贴 1-3 个，需高频动态更新
- 高优精选：近期有效/近期衰减、高波动期有效、中小市值有效、特定生态有效（如 Solana）

**四层运行逻辑**：
1. Event Layer（数据清洗）
2. Feature Layer（指标量化）— 8 组特征
3. Profile Layer（静态基线）— 实体画像卡
4. Contrast Layer（异常研判）— 自我对比、同类对比、标的对比

**系统化优先级**：
- P0 必做：事件驱动、趋势配置、左/右侧入场、建仓分布、持仓周期、集中度、近期有效性验证
- P1/P2 逐步迭代：均值回归、供需错配博弈、市场结构博弈、主题集束等
- P3 暂缓：主观性强、难以严谨回测的标签

### 4.2 v1 版本回顾

v1 的"二级分类"是简单的 5 类策略风格：趋势跟踪者、逆向投资者、事件驱动者、流动性提供者、套利者。

### 4.3 客观对比

| 维度 | 图 3-4 三层标签 | v1 二级分类 | 优劣判断 |
|------|--------------|-----------|---------|
| **架构设计** | 三层解耦（Alpha来源 × 执行路径 × 有效性状态） | 单层扁平 | **图 3-4 远优** — 三维正交设计信息密度极高 |
| **颗粒度** | 每层多个标签组合，可表达 100+ 种画像 | 5 类无法交叉 | **图 3-4 远优** |
| **动态性** | C 层明确要求高频更新 | 未考虑动态性 | **图 3-4 优** |
| **落地可行性** | 有明确的 P0/P1/P2/P3 优先级 | 无优先级设计 | **图 3-4 优** |
| **运行逻辑** | 四层处理架构（Event → Feature → Profile → Contrast） | 无 | **图 3-4 远优** |
| **回测导向** | 明确要求"可回测性"作为标签入选标准 | 未提及 | **图 3-4 优** |
| **简洁性** | 相对复杂，需要团队共识 | 简洁但信息不足 | v1 略优（但简洁到失去了价值） |

**总评**：图 3-4 的三层标签体系在设计哲学上**显著优于** v1 的扁平分类。核心理由：

1. **"Alpha 来源"和"执行路径"分离是关键洞察**。同样是"事件驱动型"策略的两个实体，一个可能习惯左侧潜伏、阶梯建仓，另一个可能右侧确认、一次性重仓——这两种完全不同的信号模式，在 v1 中被混为一谈。

2. **C 层的"有效性衰减"概念极有价值**。一个 6 个月前表现优秀的实体，如果近期连续亏损，其信号权重应该自动降低。这解决了 v1 中"静态评分"的问题。

3. **Contrast Layer 的三维对比机制**（自我基线 vs 同类 vs 标的）是将画像数据转化为研判结论的关键引擎。

### 4.4 融合建议

**结论：完全采纳图 3-4 的三层标签 + 四层运行架构**，在此基础上做以下补充：

| 补充项 | 内容 | 理由 |
|--------|------|------|
| A 层增加"被动配置型" | 指数基金风格，跟随市场权重被动配置 | Web3 机构中越来越多采用此策略 |
| B 层增加"跨链迁移型" | 习惯在新生态早期快速部署、多链并行操作 | 当前多链环境下的重要行为特征 |
| C 层增加"特定市值段有效" | 大盘/中盘/小盘/微盘 的胜率差异 | 很多鲸鱼只在特定市值段表现出色 |
| P0 增加 | "持仓周期"从高优提升到必做 | 持仓周期是区分"配置"和"投机"最直接的信号 |
| Contrast Layer 增加 | "时间窗口对比"维度 | 7d vs 30d vs 90d 的行为变化趋势 |

## 五、异动定义：买入/卖出精细化对比与融合

### 5.1 图 5-6 买入定义体系回顾

用户既有版本对"真实买入"进行了极其严谨的定义：

**五类行为识别**（V1 阶段）：
1. **真实买入** — 主动建立或增加对某风险资产的敞口
2. **真实卖出** — 主动减少或退出对某风险资产的敞口
3. **迁移行为** — 资产在地址或账户之间转移，不一定代表观点变化
4. **结构行为** — 做市、路由、桥接、LP 调度、库存管理等执行层行为
5. **噪音行为** — 没有实际研究判断意义、或会制造伪信号的动作

**真实买入的精确定义**：
- 不能按"地址收到了代币"来算，而要按**风险敞口是否真实增加**来算
- 买入拆成两种：
  - **绝对确认买入**：风险资产增加 + 主要资产减少 + 同 hash/清晰链路中完成配对
  - **推定确认买入**：前序有主要资产流出 + 后续有风险资产流入 + 时间窗口合理 + 规模匹配 + 地址关联可确认

**不应计入买入的情况**：
- VC 轮分配（无对价交换）
- 项目方分发/非透明 OTC
- 撤除流动性后收到代币（成本早期已付出）
- 空投、奖励、激励发放

**买入识别的边界注意**：
- Router/Aggregator/Solver 是执行路径，不是最终买方
- 跨链地址、跨链回流需按实体视角判断
- 分批建仓应作为同一建仓过程统一识别

### 5.2 v1 异动定义回顾

v1 的异动定义框架（第 5 节）：
- 以"事件类型"分类（大额 CEX 充值、提币、新 Token 交互等）
- 按实体类型给出差异化解读
- 三层映射：原始事件 → 行为模式 → 信号

### 5.3 深度对比

| 维度 | 图 5-6 既有版本 | v1 版本 | 优劣判断 |
|------|--------------|--------|---------|
| **核心哲学** | "是否真正增加/减少了风险敞口" | "发生了什么链上事件" | **图 5-6 本质性优于 v1** |
| **买入定义** | 绝对确认 + 推定确认的二分法 | 未定义什么是"买入" | **图 5-6 远优** |
| **排除规则** | 明确 5 类不应计入的情况 | 无 | **图 5-6 远优** |
| **边界处理** | Router/聚合器穿透、跨链回流、分批统一 | 未涉及 | **图 5-6 远优** |
| **事件覆盖** | 聚焦于买入/卖出两个核心行为 | 覆盖更广（LP、CEX流量等） | **v1 覆盖面更广** |
| **实体差异化** | 按行为定义，不按实体区分 | 同一事件按实体类型差异解读 | **两者互补** |

### 5.4 关键分析

**图 5-6 的买入定义体系是 CBS 模块最有价值的设计成果之一**。原因：

1. **解决了链上数据最本质的问题**：链上看到的是 Token Transfer，但 Transfer ≠ 买入。不做这层翻译，所有下游指标都建立在沙子上。

2. **"绝对确认买入"和"推定确认买入"的区分**提供了信号置信度分级——可以对两种买入给予不同权重。

3. **Spartan Group / $Link 的案例极具说明力**：Aster 代币是从 Aster Treasury 转出的，虽然 Arkham 显示，但实际上 ETH&USDT 先转入 Aster 再转出代币，本质是购买行为。这种"看起来不是买入但实质是买入"的场景，恰恰是需要精细定义才能捕获的。

4. **"不应计入买入"的排除清单**直接服务于指标准确性：如果把 VC 轮分配计入"新增买入"，指标 1（净流入）和指标 3（新增参与）都会被严重污染。

**v1 的互补价值**：
- v1 的"同一事件按实体类型差异解读"矩阵仍然有用——在确认了"这是一次真实买入"之后，它是来自鲸鱼还是交易员，信号含义确实不同。
- v1 覆盖了 LP 行为、CEX 流量等图 5-6 未涉及的异动类型。

### 5.5 融合方案

建立**两层异动处理架构**：

```
Layer A: 行为本质识别（采纳图 5-6）
  "这笔链上活动的本质是什么？"
  → 真实买入（绝对/推定）
  → 真实卖出（绝对/推定）
  → 迁移行为
  → 结构行为
  → 噪音行为

Layer B: 信号语义解读（采纳 v1 + 扩展）
  "这个行为来自什么类型的实体、意味着什么？"
  → 结合一级分类（A/B/C/D/E）
  → 结合三层风格标签
  → 结合历史基线对比（Contrast Layer）
  → 输出信号含义 + 置信度 + 权重
```

**同时需要补充"真实卖出"的等同精细定义**（图 5-6 中侧重买入，卖出部分需要同等设计）：

| 卖出类型 | 定义 | 说明 |
|---------|------|------|
| 绝对确认卖出 | 风险资产减少 + 主要资产增加 + 同 hash 配对 | DEX 直接卖出 |
| 推定确认卖出 | 风险资产转出 → 后续在其他地址/CEX 出现主要资产回流 | 分批减仓/跨地址卖出 |
| 不应计入卖出 | LP 撤除（回收双边资产，非方向性）、迁移至自有冷钱包、质押解除（不等于卖出意图） | 防止误判 |

## 六、指标体系重构：解锁压力迁移 + Perp 修正项 + 去重分析

### 6.1 解锁压力迁移至 ECS 的合理性评估

**结论：合理且推荐，但需要建立跨模块引用机制。**

| 评估维度 | 分析 | 结论 |
|----------|------|------|
| **本质归属** | "未来解锁"是一个**可预知的结构化事件**（已知时间、已知数量），本质上是"事件催化信号"而非"资金行为信号" | **归属 ECS 更合理** |
| **CBS 的定义边界** | CBS 关注"钱是否正在流向/撤离"，强调的是**已发生的资金行为**。解锁是"尚未发生但预期会发生的供给事件" | **不属于 CBS 核心域** |
| **与 ECS 的契合度** | 图 1 明确 ECS 负责"融资、上线、治理提案、**解锁**、合作、监管变化"等事件 | **天然属于 ECS** |
| **信息不丢失** | 解锁后如果真的发生了卖出行为，那个卖出行为会被 CBS 的"真实卖出"检测捕获。CBS 仍然能看到结果 | **不会造成盲区** |
| **跨模块协同** | ECS 标记"未来 7 天有大额解锁" → CBS 加强对该 Token 的卖出行为监控 → 两模块联动 | **协同效果更好** |

**实施建议**：
1. 从 CBS 指标体系中移除"未来解锁压力"
2. 在 ECS 中建立"Token Unlock Calendar"子模块
3. 建立 CBS ← ECS 的事件订阅机制：当 ECS 发出解锁预警时，CBS 自动提升对该 Token 的 B 类（潜在卖方）地址监控灵敏度

### 6.2 Perp 修正项评估

**Perp Position Adjustment 的设计评价**：

**设计优点**：

1. **"修正项而非主项"的定位极其正确**。理由与原文一致：
   - Perp 仓位与现货前三子项高度相关，并入主项会重复计分
   - 不是所有币都有活跃 Perp 市场，做成主项破坏可比性
   - Perp 净敞口语义不干净（套利、对冲、做市），更适合做修正器

2. **只修正正向基础分，不修正风险/结构子项**是对的。Perp 对冲行为直接影响的是"这个人真的看多吗"，而不是"LP 流动性好不好"。

3. **启用条件设计合理**。没有活跃合约市场时修正值为 0，避免了强行使用低质量数据。

**设计需要修正/补充的地方**：

| 问题 | 具体分析 | 建议 |
|------|---------|------|
| **数据可获取性** | 白名单地址的 Perp 仓位在大部分 DEX Perp 协议上可查（如 GMX, dYdX, Hyperliquid），但 CEX Perp 完全不可观测。如果大部分聪明钱用 CEX 做对冲，修正项的覆盖率会很低 | 明确标注"仅覆盖链上 Perp"，V1 阶段接受这个局限性 |
| **套利仓位的误判** | 原文提到"不看毫无意义的总空单"，但仍可能将做市商的 delta-neutral 仓位误判为"对冲" | 增加规则：做市商类（C1）地址的 Perp 仓位不纳入修正项计算 |
| **时间窗口** | 未明确 Perp 仓位的采集频率和与现货信号的时间对齐方式 | 建议：Perp 快照与 CBS 正向信号计算同步（每小时） |
| **修正幅度** | 净空对冲比例的折扣阶梯（0.9 至 0.35）和净多增强（+3 到 +8 分）的具体数值需要回测验证 | V1 使用建议值，Phase 3 通过回测优化 |
| **"中性不修正"需细化** | 净空 = 净多时确实中性，但如果 Perp 仓位波动很大（频繁翻转），本身也是一个信号 | 增加"Perp 仓位波动率"作为辅助观测指标，不做修正但输出到解释层 |

**综合结论：Perp 修正项的框架设计合理，建议纳入 CBS v2，但标注为 Phase 2 功能。** V1 阶段聚焦现货信号，Phase 2 接入链上 Perp 数据后启用修正。

### 6.3 聪明钱共识度 vs 新增高质量资金参与数：去重分析

**核心问题**：v1 建议新增的"聪明钱共识度"与已有的"新增高质量资金参与数"是否重叠？

| 维度 | 新增高质量资金参与数（原指标 3） | 聪明钱共识度（v1 建议新增） |
|------|------------------------------|------------------------|
| **计算对象** | "首次"参与该 Token 的高质量地址/实体**数量** | 所有高质量实体对该 Token 的**多空立场比例** |
| **时间维度** | 增量（仅看"新增"） | 存量 + 增量（看所有活跃实体的当前立场） |
| **方向性** | 不区分方向（新增参与 = 新增买入，但不包含"新增卖出"信号） | 明确区分多/空 |
| **信号含义** | "越来越多聪明钱开始关注这个 Token" | "聪明钱群体是否形成了一致看法" |

**分析结论**：

**存在部分重叠，但不是冗余**。关键区别在于：

1. 指标 3 是**增量入场信号**，共识度是**存量态度信号**。5 个新实体买入（指标 3 = 5）不等于高共识度——如果同时有 10 个老实体在卖出，共识度可能是负值。

2. 但确实可以将两者**合并优化**而不是分别独立。建议方案：

**不单独新增"聪明钱共识度"指标，而是将指标 3 升级为"高质量资金参与动态"**：

```
原指标3: 新增高质量资金参与数 (count of new participants)
  ↓ 升级为
新指标3: 高质量资金参与动态 (Smart Money Participation Dynamics)
  包含三个子维度:
  - 3a: 新增参与实体数 (仍保留原始定义)
  - 3b: 净方向比例 (净买入实体数 / 总活跃实体数)
  - 3c: 独立实体覆盖率 (参与该Token的高质量实体数 / 白名单总实体数)
```

这样既保留了原始指标的价值，又吸收了"共识度"的信号维度，且不增加独立指标数量。

### 6.4 其他去重分析

| 被检查指标 | 是否与其他指标重叠 | 结论 |
|-----------|:-:|------|
| 指标 1（净流入）vs 指标 4（交易所流量） | 部分 | **保留两者**。指标 1 聚焦 DEX 现货买卖（链上透明），指标 4 聚焦 CEX 入出金（推断性更强）。两者数据源不同、信号语义不同。 |
| 指标 7（大额转移）vs 指标 1/4 | 事件级 | **保留但重新定位**。指标 7 的独特价值不在"大额"，而在"实体标签"和"跨链迁移"。建议重命名为"标记实体异动追踪"，弱化与 1/4 的金额重叠。 |
| 指标 2（连续增持天数）vs 指标 1 | 衍生 | **保留**。时间维度上的持续性信号独立于单次规模信号。 |
| v1 建议的"资金情绪温度" | 复合 | **取消独立指标，改为 CBS 模块总分逻辑**（见下节）。一个复合评分不应与其子项并列为同级指标。 |

### 6.5 重构后的 CBS 指标体系

移除"未来解锁压力"（迁至 ECS）、合并共识度到指标 3、取消"资金情绪温度"（改为总分）、纳入 Perp 修正项后：

| # | 指标名称 | 类型 | 变更说明 |
|---|---------|------|---------|
| **正向基础分** | | | |
| 1 | 高质量资金净流入/流出 | 主项 | 保留，明确为"经过真实买入/卖出确认的净方向" |
| 2 | 连续增持/减持天数 | 主项 | 保留，扩展为双向（增持 + 减持） |
| 3 | 高质量资金参与动态 | 主项 | **升级**：原"新增参与数" → 含参与数、净方向、覆盖率三个子维度 |
| **风险/结构分** | | | |
| 4 | 交易所净流量 | 主项 | 保留 |
| 5 | 持仓集中度变化 | 主项 | 保留 |
| 6 | 标记实体异动追踪 | 主项 | **重命名+重新定位**：强化实体标签和跨链追踪，弱化金额维度 |
| 7 | LP 行为变化 | 主项 | 保留 |
| **修正项** | | | |
| Adj | Perp 仓位修正 | 修正项 | **新增**：仅修正正向基础分，Phase 2 启用 |

**CBS 总分计算逻辑**：

```
Step 1: CBS_Positive_Base = f(指标1, 指标2, 指标3)
Step 2: CBS_Positive_Adj = CBS_Positive_Base × PerpModifier  (Phase 2启用)
Step 3: CBS_Risk_Base = g(指标4, 指标5, 指标6, 指标7)
Step 4: CBS_Net_Score = CBS_Positive_Adj - CBS_Risk_Base
```

**与原 8 指标的变化总结**：
- 移除 1 个（解锁压力 → ECS）
- 升级 1 个（新增参与 → 参与动态）
- 重命名 1 个（大额转移 → 标记实体异动）
- 新增 1 个修正项（Perp）
- 取消 2 个 v1 建议新增（共识度被合并、情绪温度成为总分逻辑）
- **最终：7 个主项 + 1 个修正项**

### 7.1 盲区必要性评估

| 盲区 | 必要性 | 理由 | 接入建议 |
|------|:------:|------|---------|
| **隐私层与混淆检测** | ★★★★★ **必要** | 不处理则白名单穿透率会持续下降，特别是高质量资金越来越多用 Fresh Wallet 操作 | **Phase 1 接入** — 通过 Gas Funder 溯源 + 时序关联分析，建立 Fresh Wallet → Known Entity 的推断引擎 |
| **L2 与新兴链覆盖** | ★★★★★ **必要** | 2025-2026 年大量资金和活动已迁移至 Base/Arbitrum/Solana，不覆盖等于丢失大量信号 | **Phase 0 接入** — 作为数据管道基础能力，从第一天就支持多链 |
| **MEV 与噪声过滤** | ★★★★★ **必要** | 与图 2 的 D 类（去噪排除）直接对应。如果不过滤，指标 1/3/4 被严重污染 | **Phase 0 接入** — 内置于数据清洗层，是 Event Layer 的核心能力 |
| **时间粒度框架** | ★★★★ **必要** | 不同指标和不同用户场景需要不同时间粒度 | **Phase 1 接入** — 建立多时间窗口计算框架（1h/4h/24h/7d/30d），从计算层支持 |
| **反指标与操纵检测** | ★★★ **重要但可延后** | V1 阶段可以先接受这个风险，通过后续回测发现异常模式 | **Phase 3 接入** — 属于智能化阶段的异常检测能力 |
| **链上↔链下关联** | ★★ **锦上添花** | CEX 内部操作不可见是行业共识限制，短期无法突破 | **Phase 3+ 接入** — 结合有限的公开数据（大额清算、期货资金费率）做辅助推断 |
| **标签衰减机制** | ★★★★ **必要** | 直接影响白名单质量和指标准确性 | **Phase 1 接入** — 在动态质量评分中内置时间衰减因子 |

### 8.1 体系总览

```

├── 绝对确认卖出 / 推定确认卖出
```

### 8.3 关键设计决策清单

| 决策点 | 最终决策 | 理由 |
|--------|---------|------|
| 一级分类框架 | 采纳图 2 的五维分类 | 按资金角色分类比按实体性质分类信号密度更高 |
| 二级分类/风格标签 | 采纳图 3-4 的三层标签体系 | 三维正交设计，颗粒度和灵活性远优于扁平分类 |
| 质量评级位置 | 拆分为"准入评级"（来源阶段）+ "动态评分"（行为阶段） | 过早精细评分缺乏依据 |
| 异动定义 | 采纳图 5-6 的五类行为识别作为底层 | 解决了"Transfer ≠ 买入"这一根本问题 |
| 解锁压力归属 | 迁移至 ECS 模块 | 属于结构化事件，不属于已发生的资金行为 |
| Perp 修正项 | 纳入，但作为修正项，Phase 2 启用 | 设计合理，但数据覆盖受限，不宜做主项 |
| 聪明钱共识度 | 合并入升级版指标 3 | 与原指标 3 有信号交叉，升级合并更优 |
| 资金情绪温度 | 取消独立指标，改为 CBS 总分逻辑 | 复合评分不应与子项同级 |
| 指标总数 | 8 → 7 主项 + 1 修正项 | 精简比膨胀更有利于信号清晰度 |

### 9.3 关键 Prompt 补充

**ChatGPT — 五类行为识别规则设计**：

```
角色: Web3 链上行为分析专家
任务: 为 CBS 模块的"绝对确认买入"设计精确的判定规则

上下文:
- 绝对确认买入定义: 风险资产增加 + 主要资产减少 + 同 hash 或清晰链路中完成配对
- 主要资产: USDT, USDC, DAI, ETH/WETH, BTC/WBTC
- 数据源: DEX Swap 事件 (Uniswap V2/V3, SushiSwap, Curve, Balancer, Raydium)

请设计:
1. 针对每种 DEX 协议的具体事件解析规则
2. "同 hash 配对"的匹配逻辑（含多跳 swap）
3. Router/Aggregator 穿透规则
4. 阈值设定：最小金额、最小主要资产占比
5. 边界情况处理：wrap/unwrap、同 Token 不同版本、rebasing token
6. 输出格式：{buyer, token, amount, cost_basis, confidence, source_tx}
```

**Cursor — Contrast Layer 实现**：

```
当前任务: 实现 CBS Contrast Layer 的三维异常对比引擎

三个对比维度:
1. Self-Baseline: 当前行为 vs 该实体过去 90 天的行为基线
   - 需要计算的指标: 单笔规模偏离、频率偏离、持仓集中度偏离
   - 异常阈值: 偏离 > 历史中位数的 3 倍

2. Peer Compare: 当前行为 vs 同风格标签实体的近期行为
   - 同类定义: A层标签相同的实体集合
   - 需要计算: 群体共振度（同方向操作的实体占比）

3. Object Compare: 当前标的的买方质量 vs 该标的过往买方质量
   - 需要计算: 平均买方质量评分的变化趋势

数据存储: ClickHouse (历史快照) + Redis (当前状态)
输出: 每次异常触发时生成结构化报告 JSON
```

### 9.4 MVP 验收标准

| 维度 | 标准 |
|------|------|
| **数据覆盖** | Ethereum + Base + Arbitrum (Solana Phase 1 后期加入) |

| **输出形式** | Token 级 CBS 评分 + 异动报告 + REST API |
