## 一、名词定义

| 术语 | 全称 | 定义 |
|------|------|------|
| CBS | Capital Behavior Signals | 资金行为信号，注意力引擎模块 2 |
| 实体 (Entity) | — | 一个独立的资金决策主体（机构/个人），可拥有多个链上地址 |
| 地址 (Address) | — | 单个链上钱包地址，归属于某个实体 |
| 白名单 (Whitelist) | — | 被纳入 CBS 持续监控的高质量实体集合 |
| 行为事件 (BehaviorEvent) | — | 经 Event Layer 清洗分类后的标准化链上事件 |
| 标准行为 | — | 五类行为之一：真实买入、真实卖出、迁移、结构、噪音 |
| CBS 信号 | — | 系统识别出的、关于某 Token 的资金异动信号 |
| 实体画像 (Profile) | — | 基于历史链上行为回测生成的实体特征数据集 |
| 行为基线 (Baseline) | — | 某实体过去一段时间的行为统计均值，用于异常检测 |
| 行为匹配分 (BMS) | Behavior Match Score | 某次异动与该实体历史高胜率模式的匹配程度评分 |
| 确认买入 | Confirmed Buy | 风险资产增加 + 主要资产减少 + 同 hash 或链路配对 |
| 推定买入 | Inferred Buy | 前序主要资产流出 + 后续风险资产流入 + 时间/规模匹配 |
| 主要资产 | — | USDT, USDC, DAI, ETH/WETH, BTC/WBTC |

## 二、系统目标

构建一个持续运行的自动化系统，监控链上高质量资金实体的行为，从中识别资金异动信号，当信号强度达到阈值后推送给投研分析师，帮助团队捕获早期投资机会或风险预警。

核心链路：

```
发现高质量实体 → 采集链上行为 → 构建实体画像
→ 持续监控异动 → 与画像对比评估 → 计算指标与评分
→ 达阈值推送通知 → 回测验证并更新画像
```

## 四、M1 — 实体发现与白名单管理

### 4.1 实体来源

| 来源 | 方式 | 执行频率 |
|------|------|---------|
| Arkham Intelligence API | 拉取已标记实体及其地址 | 每日增量 |
| Nansen Labels | 导入 Smart Money / Fund 标签地址 | 每日增量 |
| 链上溯源 | 从已知实体出发，通过 Gas Funder / 资金流聚类发现关联地址 | 每周 |
| 手动导入 | 投研团队手动添加已知机构/鲸鱼地址 | 按需 |
| 模式 B 发现 | 跨模块触发时发现的"疑似高质量"新地址 | 按需 |

去重逻辑：以链上地址为唯一标识，已存在则跳过。多个地址可归属同一实体。

### 4.2 实体归因（Entity Resolution）

一个实体通常拥有多个地址。归因方法：

| 方法 | 原理 | 准确率 |
|------|------|:------:|
| Gas 来源分析 | 多个地址的初始 Gas 来自同一 Funder | 高 |
| 资金流聚类 | 多个地址频繁互转或汇入同一地址 | 高 |
| 时序行为聚类 | 极短时间窗口内执行类似操作 | 中高 |
| 合约工厂追踪 | 同一工厂合约创建的多个代理地址 | 极高 |

### 4.3 实体分类（一级/二级）

5 大类 18 子类。以 `entity_id` 为唯一标识。同一实体对不同 Token 可持有不同角色（通过 `entity_token_roles` 表实现）。

| 一级 | 二级 | 定义 | 看到时优先怎么理解 | 核心关注行为 |
|------|------|------|-----------------|-----------|
| **A 主动买方** | A1 机构买方 | 有明确机构背景、主动配置下注 | 看机构有没有真下场 | 首次买入某 Token；加仓行为；买入后质押/锁仓（最强看多增强）；稳定币激活 |
| | A2 公开人物/KOL | 身份公开、市场关注度高 | 注意"表演折扣"——知道被追踪可能做非真实操作 | 首次买入某 Token；大额加仓（真金白银 vs 嘴上说说）；清仓（可能引发跟随者抛售） |
| | A3 匿名高质量买方 | 身份不公开但历史质量高 | 看真正做交易的人在干什么 | **首次参与（最高 Alpha 值）**；多个 A3 同时买入同 Token（独立共振）；建仓速度和规模；获利了结模式 |
| **B 潜在卖方** | B1 机构供给方 | 低成本筹码持有者 | 看低成本筹码会不会出来 | 解锁后第一步行为（转 CEX=减仓/质押=持有/LP=观望）；冷→热钱包转移（**减仓前兆**）；未解锁链上 Perp 做空；解锁后长期不动（最强持有信号） |
| | B2 项目方/基金会/Treasury | 项目直接相关、影响供给 | 看项目自己有没有在散货 | 大额 Token 转出；回购自家 Token（看好）；向做市商转入 Token（做市/上所准备）；为自家 Token 添加 LP（护盘） |
| **C 中介通道** | C1 做市商 | 库存管理、报价、对冲 | 常规行为过滤，异常行为高价值 | 撤出/新增做市（★★★★★）；区间上移/下移；库存偏移；自营方向性交易（★★★★★）；多做市商同向（★★★★★）；做市商间筹码转移 |
| | C2 交易所体系 | 充值、冷钱包、归集 | 交易通道，不是观点表达者 | 冷钱包异动；新 Token 出现在热钱包（可能上所） |
| | C3 桥/路由/聚合器/Solver | 跨链、路由、聚合、执行 | 只是路径，穿透到终态买方 | 不直接关注——穿透后归为实际操作者 |
| | C4 LP/池子/流动性调度 | 池子增减仓和深度调度 | 看这个币的深度在变厚还是变薄 | 纳入指标 7（LP 动态）；策略型 LP 归入指标 1 |
| **D 去噪排除** | D1 MEV/套利/Bot | 高频执行、净值接近零 | 直接过滤 | 不追踪。确保准确识别和过滤 |
| | D2 羊毛/女巫 | 空投活动批量小号 | 直接过滤 | 同上 |
| | D3 伪高手 | 运气型 | 直接过滤 | 同上 |
| | D4 已知操纵者 | Rug Pull 记录 | 风险标记 | 同上 |
| **E 特殊观察** | E1 借贷/清算 | 波动和爆仓阶段关键 | 谁快扛不住了 | 接近清算线（潜在强制卖压）；追加抵押物（"选择不被迫出局"，置信度低）；清算发生（已实现抛售） |
| | E2 托管/代持 | 资金在但决策权未必在手 | 不一定是自己在做决定 | 大额资产变动 |
| | E3 治理/质押 | 与治理质押有关 | 看制度层变化 | 大额质押（长期信心）；大额解除质押（可能准备退出）；治理投票参与 |
| | E4 稳定币发行方 | Tether/Circle | 宏观资金意愿 | Mint/Burn 大额稳定币 |

### 4.4 准入评级

硬性门槛，任一不满足则 `status = rejected`：

| 检查项 | 条件 | 数据来源 |
|--------|------|---------|
| 标签可信度 | 至少 1 个可靠来源标记 | Arkham/Nansen/手动 |
| 活跃度 | 近 90 天有交易记录 | 链上数据 |
| 规模门槛 | 管理资产估值 > `[TUNABLE: $100K]` | 持仓快照 |

### 4.5 白名单管理

- 达标实体写入 `whitelist_entities` 表，状态为 `active`
- 每月复审：底部 `[TUNABLE: 10%]` 进入 `review` 状态，投研确认后淘汰或保留
- 标签衰减：`[TUNABLE: 30d]` 无链上活动 → 置信度 -10%；`[TUNABLE: 180d]` → 降入 `dormant`

## 五、M2 — 实体画像构建与评分

### 5.1 为什么需要画像

分类告诉你"这个实体是谁"。**画像告诉你"这个实体过去表现如何、擅长什么、这次行为对它来说是否异常"。**

画像不是人为标注的，而是**通过回测历史链上数据计算出来的**。

### 5.2 画像构建流程

```
Step 1: 历史行为采集
  拉取该实体所有地址在过去 [TUNABLE: 6个月] 的链上事件
  → 通过 Event Layer 归类为五类行为
  → 提取所有"真实买入"和"真实卖出"事件

Step 2: 交易配对
  将同一 Token 的买入和卖出匹配为"完整交易"
  规则: 按时间顺序，先买先配。部分卖出按比例拆分
  未平仓的持仓标记为 open_position

Step 3: 逐笔计算
  每笔完整交易计算:
  - PnL% = (卖出均价 - 买入均价) / 买入均价
  - 持仓时间 = 卖出时间 - 买入时间
  - 仓位占比 = 买入金额 / 买入时该实体总持仓估值
  - 买入时机 = (买入价 - 30d最低价) / (30d最高价 - 30d最低价)
    → 0 = 买在最低点(左侧), 1 = 买在最高点(右侧)

Step 4: 聚合统计 → 生成画像指标 (见 5.3)

Step 5: 标签生成 → 基于指标自动打标 (见 5.4)

Step 6: 快照存储 → 每日 UTC 00:00 更新
```

### 5.3 画像指标体系

| 指标组 | 指标 | 计算方式 | 用途 |
|--------|------|---------|------|
| **胜率** | win_rate_all | 盈利交易数 / 总完成交易数 | 整体能力 |
| | win_rate_30d | 近 30 天完成交易的胜率 | 近期状态 |
| | win_rate_90d | 近 90 天胜率 | 中期趋势 |
| **盈亏** | avg_pnl | 所有完成交易的平均 PnL% | 盈利能力 |
| | avg_win_pnl | 盈利交易的平均 PnL% | 赚多少 |
| | avg_loss_pnl | 亏损交易的平均 PnL% | 亏多少 |
| | profit_factor | 总盈利额 / 总亏损额 | 盈亏比 |
| **持仓** | avg_hold_days | 平均持仓天数 | 持仓风格 |
| | median_hold_days | 持仓天数中位数 | 抗极端值 |
| | avg_position_pct | 平均仓位占比 | 下注习惯 |
| | max_position_pct | 历史最大仓位占比 | 最大单注 |
| **节奏** | avg_trades_per_month | 月均交易次数 | 活跃度 |
| | avg_entries_per_trade | 每笔交易平均建仓次数 | 分批/一次性 |
| **择时** | avg_entry_position | 买入价在 30d 高低点中的位置 (0-1) | 左侧/右侧 |
| | event_proximity_rate | 买入后 `[TUNABLE: 72h]` 内有重大事件的比例 | 事件驱动度 |
| **偏好** | preferred_mcap_range | 胜率最高的市值区间 | 能力圈 |
| | preferred_chain | 胜率最高的链 | 生态偏好 |

### 5.4 基于画像的风格标签自动生成

**A 层（主风格）**：每个实体仅 1 个。给分析师看，帮助快速解读。

| 标签 | 触发条件 | 优先级 |
|------|---------|:------:|
| 事件驱动型 | event_proximity_rate > `[TUNABLE: 30%]` | P0 |
| 趋势配置型 | avg_hold_days > `[TUNABLE: 14]` 且 avg_entry_position > `[TUNABLE: 0.5]` | P0 |
| 早期发现型 | preferred_mcap_range 中位数 < `[TUNABLE: $10M]` | P0 |
| 均值回归型 | avg_entry_position < `[TUNABLE: 0.2]` 且 win_rate > 50% | P1 |
| 叙事轮动型 | avg_hold_days < 7 且 sector_diversity 高 | P1 |
| 被动配置型 | 持仓分散 + avg_trades_per_month < 3 | P2 |
| 未分类 | 不满足以上任何条件，或交易数据 < 10 笔 | — |

**B 层（执行路径）**：每个实体 2-4 个。给 Contrast Layer 计算用。

| 标签 | 触发条件 |
|------|---------|
| 阶梯建仓 | avg_entries_per_trade > `[TUNABLE: 3]` |
| 一次性重仓 | avg_entries_per_trade < 1.5 且 avg_position_pct > `[TUNABLE: 10%]` |
| 左侧入场 | avg_entry_position < `[TUNABLE: 0.2]` |
| 右侧入场 | avg_entry_position > `[TUNABLE: 0.5]` |
| 分批止盈 | 卖出拆成 3+ 笔的比例 > 50% |
| 快速兑现 | 卖出在买入后 3 天内完成的比例 > 50% |
| 中线持有 | median_hold_days 在 14-90 天之间 |
| 高集中度 | max_position_pct > `[TUNABLE: 20%]` |

**C 层（状态）**：每个实体 1-3 个。分析师看 + 调权重。

| 标签 | 触发条件 |
|------|---------|
| 近期有效 | win_rate_30d > `[TUNABLE: 55%]` |
| 近期衰减 | win_rate_30d < `[TUNABLE: 40%]` |
| 特定生态有效 | 某链上的胜率显著高于整体 (>15pp) |

### 5.5 行为匹配分（Behavior Match Score）

当检测到实体异动时，系统将本次行为与其画像对比，计算行为匹配分。

**匹配维度**：

| 维度 | 对比方式 | 信号含义 |
|------|---------|---------|
| 仓位 | 本次仓位占比 vs avg_position_pct | 高于均值=认真下注; 远低于均值=试探性 |
| 建仓方式 | 本次分批/一次 vs B 层标签 | 偏离惯常=紧迫感变化 |
| 择时 | 本次买入位置 vs avg_entry_position | 符合=惯常操作; 偏离=可能有新判断 |
| 标的 | 本次 Token 市值 vs preferred_mcap_range | 在能力圈内=更可信; 圈外=参考价值降低 |
| 历史类似操作 | 查询历史上仓位/方式/时机相似的交易 | 计算类似操作的历史胜率 |

**输出标签**：

| 标签 | 条件 | 投研含义 |
|------|------|---------|
| `HIGH_CONVICTION` | 仓位高于均值 + 类似操作历史胜率 > 整体胜率 | 该实体的高确信度操作，值得重点关注 |
| `NORMAL` | 各维度在基线范围内 | 常规操作 |
| `LOW_CONVICTION` | 仓位远低于均值 或 标的在能力圈外 | 试探性操作，参考价值较低 |
| `UNUSUAL` | 建仓方式/择时 显著偏离 B 层标签 | 异常操作，可能有新信息驱动 |

### 5.6 画像更新机制

| 触发事件 | 更新内容 | 频率 |
|---------|---------|------|
| 新的完成交易（卖出平仓） | 增量更新受影响指标 | 实时 |
| 每日快照 | 全量重算所有指标 + 标签 | 每日 UTC 00:00 |
| 回测完成 | 信号回测结果反馈到画像 | 随回测触发 |

### 5.7 画像冷启动

新入白名单的实体若无足够历史数据：
- 交易记录 < 10 笔：A 层标签 = "未分类"，行为匹配分不可用
- 交易记录 10-30 笔：标签可用但标注 `low_confidence`
- 交易记录 > 30 笔：正常计算

## 六、M3 — 链上行为监控（Event Layer）

### 6.1 数据采集

| 链 | 数据源 | 监听事件 | 优先级 |
|---|--------|---------|:------:|
| Ethereum | Allium/Goldsky + 备用 RPC | Transfer, Swap, Mint, Burn, Deposit, Withdraw | P0 |
| Base | 同上 | 同上 | P0 |
| Arbitrum | 同上 | 同上 | P0 |
| Solana | Helius + 备用 RPC | SPL Transfer, Raydium/Orca Swap | P0 |
| BSC | 同上 | 同上 (PancakeSwap) | P1 |
| Hyperliquid | API | 仓位快照 | P1 |

架构设计为链无关——每条链仅需一份配置（RPC + DEX 合约地址 + CEX 地址 + 标签库）。

### 6.2 五类行为识别

#### 6.2.1 真实买入（7 种链上路径）

| # | 路径 | 链上识别方式 | 置信度 |
|---|------|-----------|:------:|
| 1 | DEX Swap 买入 | Swap event: 主要资产(USDC/ETH)流出 + 风险 Token 流入 | 1.0 |
| 2 | 聚合器路由买入 | 1inch/Paraswap 的 Swapped event → 穿透到发起交易的 EOA | 1.0 |
| 3 | 交易场所对价推定 | 向 CEX/DEX 侧链转入主要资产 → `[TUNABLE: 24-72h]` 内转出风险 Token → 金额匹配(±20%) | 0.6-0.8 |
| 4 | LP 隐含买入(区间穿越) | V3 LP 头寸完全变为单边风险 Token | 0.5 |
| 5 | LP 意图买入(区间设定) | V3 LP 区间全部低于当前价格 = 等效限价买单 | 0.2 |
| 6 | 跨链后买入 | Bridge 到目标链 → 目标链 Swap 买入 | 1.0 |
| 7 | OTC 对价买入 | 两地址直接 Transfer 对价交换，金额匹配 | 0.5 |

**不应计入买入**：VC 轮分配（来源为 B2 地址+无对应主要资产流出）、空投 Claimed event、LP Burn 收回双边资产、Bridge 合约到账（仅迁移）

#### 6.2.2 真实卖出（7 种，与买入对称）

| # | 路径 | 置信度 |
|---|------|:------:|
| 1 | DEX Swap 卖出 (风险 Token 流出+主要资产流入) | 1.0 |
| 2 | 聚合器路由卖出 | 1.0 |
| 3 | 交易场所对价推定卖出 | 0.6-0.8 |
| 4 | LP 隐含卖出 (区间穿越, Token 全被换走) | 0.5 |
| 5 | LP 意图卖出 (区间全高于当前价格) | 0.2 |
| 6 | 跨链后卖出 | 1.0 |
| 7 | OTC 对价卖出 | 0.5 |

**不应计入卖出**：LP Burn 收回双边资产、迁移至自有冷钱包、质押解除

#### 6.2.3 迁移行为（8 种）

| # | 表现 | 信号含义 |
|---|------|---------|
| 1 | 冷→热钱包转移 | 卖出前兆（高信号） |
| 2 | 热→冷钱包转移 | 长期存储意图 |
| 3 | 跨链迁移 | 生态偏好变化 |
| 4 | CEX 入金 | 可能准备卖出 |
| 5 | CEX 出金 | 可能准备链上操作 |
| 6 | 同实体跨地址转移 | 内部调仓 |
| 7 | 向做市商转 Token | 做市合约启动 |
| 8 | 做市商退回 Token | 做市关系终止 |

#### 6.2.4 结构行为（7 种——穿透/过滤）

| # | 表现 | 处理 |
|---|------|------|
| 1 | Router/Aggregator 中转 | 穿透到发起交易的 EOA |
| 2 | Bridge 中转 | 穿透到原始发送者 |
| 3 | 做市商常规做市 | 过滤 |
| 4 | Solver 执行 | 穿透到订单发起者 |
| 5 | LP 全范围做市 | 仅计入指标 7 |
| 6 | 做市商常规库存平衡 | 过滤 |
| 7 | 闪电贷 | 过滤 |

#### 6.2.5 噪音行为（6 种——丢弃）

MEV/Sandwich、套利 Bot、女巫/空投猎人、尘埃攻击(<$1)、合约自动执行、测试交易。通过 D 类名单 + 行为模式匹配识别后全部丢弃。

### 6.3 Event Layer 处理流程

```
Step 1: 原始事件接收
  ← EVM: Transfer, Swap, Mint, Burn, Deposit, Withdraw
  ← Solana: SPL Transfer, DEX Swap

Step 2: D 类地址过滤
  黑名单匹配 + 行为模式匹配 (Sandwich/套利模式)
  命中 → 丢弃 | 未命中 → 继续

Step 3: 结构行为穿透
  Router/Bridge/Solver → 追踪到原始 EOA
  闪电贷 → 丢弃
  C1 常规做市 → 过滤

Step 4: 白名单匹配
  在白名单 → 继续精细分析
  不在白名单 → 仅计入指标 5(持仓)/7(LP)的全量统计

Step 5: 行为分类 (白名单地址)
  Swap → 真实买入/卖出
  Transfer to/from CEX → 迁移
  Transfer 同实体 → 迁移
  LP Mint/Burn → LP 方向性判定
    策略型+方向性 → 真实买入/卖出
    全范围/做市型 → 结构行为
  做市商行为 → 异常检测

Step 6: 标准化事件输出
  {实体, Token, 行为类型, 金额, 置信度, 时间, 链, 标签}
```

### 6.4 双触发运行模式

**模式 A（白名单扫描，常驻）**：每小时扫描白名单全部地址 → Event Layer → 指标更新 → CBS Score → 异动检测

**模式 B（跨模块响应，按需）**：其他模块通知 CBS 检查某 Token →
1. 白名单维度：查询该 Token 相关实体的近期行为。"白名单无异动"本身也是信号
2. Token 维度：拉取全量大额交易，识别疑似高质量的非白名单地址 → 标记为"待入库观察"

## 七、M4 — 指标计算与信号引擎

### 7.1 核心设计：行为 → 画像对比 → 指标

CBS 不是简单地"事件发生→计入指标"。完整链路：

```
链上事件 → Event Layer 分类 → 行为匹配分(与画像对比)
  → 带匹配标签的事件 → 映射到对应指标 → 各指标打分
  → 加权汇总 CBS Score → 异动检测 → 推送
```

**行为匹配分的作用**：同样是"$500K 买入"，一个 `HIGH_CONVICTION` 事件在指标 1 中的贡献 > 一个 `LOW_CONVICTION` 事件。具体而言：

```
指标1(净流入) 的单事件贡献 = 
  金额 × 置信度 × quality_score × conviction_multiplier

其中:
  conviction_multiplier:
    HIGH_CONVICTION = 1.3
    NORMAL = 1.0
    LOW_CONVICTION = 0.7
    UNUSUAL = 1.0 (金额正常计入, 但触发指标6事件)
```

### 7.2 指标体系（7+1）

7 个指标不分组，扁平排列，各自输出有向值 [-100, +100]。

#### 指标 1：高质量资金净流入/流出（权重 0.25）

```
回答: "白名单资金对该 Token 的净方向是什么？"

计算:
  Raw = Σ(买入金额 × 置信度 × quality_score × conviction_mult)
      - Σ(卖出金额 × 置信度 × quality_score × conviction_mult)

归一化到 [-100, +100]:
  使用该 Token 过去 30d 的 Raw 值分布做 Z-score 归一化
  Z > 2 → +100, Z < -2 → -100, 线性映射中间值

时间窗口: 分别计算 24h / 7d / 30d
```

#### 指标 2：连续增持/减持天数（权重 0.15）

```
回答: "方向持续了多久？"

计算:
  如果指标1的24h值 > 0 且前一天也 > 0 → 天数 +1
  如果指标1的24h值 < 0 且前一天也 < 0 → 天数 -1
  方向翻转时重置

归一化:
  连续增持 7天 → +70, 14天 → +100 (线性, 上限14天)
  连续减持 7天 → -70, 14天 → -100
```

#### 指标 3：高质量资金参与动态（权重 0.15）

```
回答: "多少独立实体在参与？方向是否一致？"

子维度:
  3a: 新增参与实体数 (首次与该Token交互的白名单实体, 窗口内)
  3b: 净方向比例 = (净买入实体数 - 净卖出实体数) / 总活跃实体数
  3c: 覆盖率 = 参与该Token的白名单实体数 / 白名单总实体数

归一化:
  综合三个子维度: 0.3×f(3a) + 0.5×f(3b) + 0.2×f(3c)
  3a: 每新增1个实体 +10, 上限 +50
  3b: 直接映射 [-100, +100] (100%看多=+100, 100%看空=-100)
  3c: 覆盖率 > 5% 为显著, 映射到 [0, +50]

时间窗口: 24h / 7d / 30d
```

#### 指标 4：交易所净流量（权重 0.15）

```
回答: "CEX 端的资金供需如何？"

计算:
  Raw = 白名单地址 CEX 出金总额 - 白名单地址 CEX 入金总额
  正值 = 净提币(看多), 负值 = 净充值(看空)

归一化: 同指标1, 使用Z-score

时间窗口: 24h / 7d / 30d

注意: 金额维度归指标4, "谁在做"的实体维度归指标6
```

#### 指标 5：持仓集中度变化（权重 0.10）

```
回答: "筹码在向谁集中/分散？"

方法: 分层持仓分析
  Layer 1 (鲸鱼层): 持仓 > 总供应量的 [TUNABLE: 0.1%]
  Layer 2 (中等层): 0.01% ~ 0.1%
  Layer 3 (零售层): < 0.01%
  排除: CEX / 合约 / 桥 / 销毁地址

每层叠加一级分类标签:
  A 类鲸鱼占比 ↑ → 正向信号
  B 类鲸鱼占比 ↑ → 负向信号
  零售层分散化 → 结构改善(正向)

归一化:
  综合各层变化方向和幅度, 映射到 [-100, +100]

快照频率: 每日
时间窗口: 7d / 30d
```

#### 指标 6：结构性资金事件（权重 0.10）

```
回答: "除了链上买卖，还有哪些结构动向？"

双层输出:

层 1 (量化, 参与 CBS Score):
  将有方向性但不属于买卖的事件量化:
  - 大额入所: (入所金额/实体总持仓) × quality × (-1) → 偏空
  - 大额出所: 同上 × (+1) → 偏多
  - 跨链迁移: 按迁移方向
  - 冷→热转移: 固定负分 (卖出前兆)
  - 做市商区间上移/下移: 按偏移比例
  - 做市商库存偏移: 按偏向方向
  - 做市商撤出/新增: 偏空/偏多
  - 多做市商同向: 强方向性

  不重叠规则:
  - DEX Swap 买卖 → 只计入指标1, 不计入指标6
  - CEX 入出金金额 → 指标4; 指标6只记"谁在做"的方向性加权
  
  归一化: 事件评分加总后Z-score归一化到 [-100, +100]

层 2 (事件流, 不参与评分):
  完整事件明细 → Dashboard + 异动推送
  含: 实体身份 / 行为匹配分 / Contrast 基线对比 / 推测 / 建议
```

#### 指标 7：LP 行为与流动性动态（权重 0.10）

```
回答: "资金在流动性层面有什么异动？"

子维度:
  7a: 池子深度变化 (±2%区间, 侧重变化速度而非绝对值)
  7b: 撤池/加池行为检测 (短时间多LP撤出+深度骤降 → 高风险)
  7c: 流动性集中度 (Top 5 LP 占比变化, 升高=脆弱)
  7d: 流动性迁移 (V2→V3, 链A→链B)

数据范围: 全量LP数据(不限白名单)

归一化:
  综合4个子维度的改善/恶化方向
  7b 撤池模式触发 → 强制负向值

不重叠:
  - 白名单LP的方向性行为 → 指标1
  - 做市商异常LP行为 → 指标6
  - 指标7 = 全量LP的资金动静

不含 (归属BAS):
  - TVL 绝对值/增长率
  - LP 提供者数量绝对值

时间窗口: 7d / 30d
```

#### Perp 修正项（乘数）

```
数据源: Hyperliquid (P1) + GMX/dYdX (P2)
计算: 白名单地址的 Perp 净敞口
  净多头 → 乘数 > 1 (增强)
  净空头 → 乘数 < 1 (削弱)
  中性 → 乘数 = 1

排除: C1a/C1b 做市对冲仓位 (delta-neutral)
纳入: C1d 自营 Perp 仓位

启用条件: 有活跃合约市场 + 数据稳定
否则: 乘数 = 1 (不修正)

Phase 2 启用
```

### 7.3 CBS Score 计算

```
CBS_Score = [Σ(wi × Ii)] × PerpModifier

权重: w1=0.25, w2=0.15, w3=0.15, w4=0.15, w5=0.10, w6=0.10, w7=0.10

窗口共振: 某指标 24h/7d/30d 全同向 → 该指标权重 ×[TUNABLE: 1.2]

结果范围: [-100, +100]
  +60~+100: 强看多 | +20~+60: 温和看多 | -20~+20: 中性
  -60~-20: 温和看空 | -100~-60: 强看空
```

### 7.4 异动检测与推送

| 触发条件 | 优先级 | 推送内容要点 |
|---------|:------:|-----------|
| A 类绝对确认买入 > `$500K` | 高 | 实体画像 + 行为匹配分 + CBS 指标 |
| 多独立实体 4h 内同向操作同一 Token | 高 | 参与实体列表 + 各自匹配分 |
| 做市商异常（撤出/反向/多做市商同向） | 高 | 做市商详情 + 风险评估 |
| A1 机构首次参与某 Token | 高 | 机构画像 + 该 Token CBS |
| 连续增持 > 7 天 | 中 | 增持趋势 + 参与实体 |
| 撤池 + 深度恶化 | 高(风险) | 流动性数据 + 风险等级 |
| 冷→热钱包大额转移 | 中 | 实体身份 + 后续观察建议 |

推送降噪：同一 Token 每小时最多 `[TUNABLE: 3]` 条推送。

### 7.5 异动推送 Payload


## 八、M5 — 回测与画像更新引擎

### 8.1 信号级回测

以异动推送时间为 T0，在以下窗口回测：

| 窗口 | 权重 | 设计理由 |
|------|:----:|---------|
| +24h | 0.35 | 短线验证 |
| +7d | 0.40 | 核心窗口 |
| +30d | 0.25 | 中线参考 |

取窗口前后 `[TUNABLE: 5分钟]` TWAP，避免闪崩闪涨导致不合理分数。

### 8.2 回测得分计算

```
每个窗口:
  PnL% = (窗口价格 - 推送时价格) / 推送时价格
  raw_score: 盈利 → min(10, PnL%/10); 亏损 → max(-10, PnL%/10)
  weighted_score = raw_score × window_weight

信号总回测分 = Σ weighted_score
```

### 8.3 画像反馈闭环

```
异动推送 → 价格回测 → 该笔交易标记盈/亏
  → 更新实体画像 (胜率/PnL/持仓时间等)
  → 标签可能变化 (如"近期有效"→"近期衰减")
  → 下次异动时, 画像对比更准确
```

### 8.4 系统级参数调优（Phase 3）

定期分析全部推送信号的回测结果，自动调整指标权重、推送阈值、行为匹配分条件。

## 十一、边界条件与风险

| 场景 | 处理方式 |
|------|---------|
| Fresh Wallet | Gas Funder 溯源 + 时序关联 |
| Router/Bridge 中转 | 穿透到原始 EOA |
| CEX 内部不可见 | 接受局限，只推测不确认 |
| VC 未解锁做空 | 链上 Perp 可监测；CEX 不可 |
| 做市商常规噪音 | 常规过滤/异常纳入 |
| 做市商间筹码转移 | 指标6层2事件(方向不明, 人工判断) |
| Token 无价格 | 回测标记 failed，不计入画像 |
| 代币改名 | 以 contract_address + chain 为键 |
| 标签冲突 | 多源交叉验证，取最高置信度 |
| 画像冷启动 | 交易<10笔→未分类; 10-30→low_confidence |
| 避免清算≠看好 | 低置信度参考(0.3); 大额追加提升至0.5 |
