## 一、模块定位

### 1.1 在注意力引擎中的位置

CBS 是注意力引擎五大模块中的**模块 2**。

| 模块 | 名称 | 核心问题 |
|------|------|---------|
| 1 | 市场交易信号 (MTS) | 市场是否已经开始交易它、拥挤它、重新定价它？ |
| **2** | **资金行为信号 (CBS)** | **钱是否正在流向/撤离它，以及这些资金是否值得信** |
| 3 | 叙事传播信号 (NDS) | 市场是否正在形成共识、扩散讨论，还是营销噪音？ |
| 4 | 事件催化信号 (ECS) | 是否存在可能触发重估的明确事件窗口？ |
| 5 | 业务采用信号 (BAS) | 它是否真的被用起来了，使用是否有质量？ |

### 1.2 系统定位

**CBS 是团队内部的投研信号发现工具。** 用户是人类分析师，不是交易机器人。系统发现异常信号，人类分析师介入判断。不做高频。

设计原则：
- **召回率优先**：宁可多报不漏报，人类过滤误报
- **可解释性**：比精确评分更重要的是"为什么发出这个信号"
- **批处理 + 异动触发**：每小时批量计算 + 大额事件即时推送

## 二、实体分类体系

### 2.1 一级分类（5 大类 + 扩展子类）

按实体相对于某个标的的**资金角色**分类（非按实体性质）。同一实体对不同 Token 可有不同角色。

| 一级 | 二级 | 定义 | 核心理解 |
|------|------|------|---------|
| **A 主动买方** | A1 机构买方 | 有明确机构背景、会主动配置和下注的资金 | 看机构有没有真下场 |
| | A2 公开人物/KOL 买方 | 身份公开、市场关注度高的个人资金 | 看有没有能带情绪的人在买 |
| | A3 匿名高质量买方 | 身份不公开但历史交易质量高的地址 | 看真正在做交易的人在干什么 |
| | A4 稳定币激活型买方 | 长期持有大额稳定币后首次转入风险资产 | 沉默资金苏醒的信号 |
| **B 潜在卖方** | B1 机构供给方 | 低成本筹码持有者，未来可能转化为供给 | 看低成本筹码会不会出来 |
| | B2 项目方/基金会/Treasury | 和项目本身直接相关、能影响供给的资金 | 看项目自己有没有在散货 |
| **C 中介通道** | C1 做市商 | 负责库存管理、报价、成交、对冲和结算 | 别把做市动作当成真实观点——但异常行为除外 |
| | C2 交易所体系地址 | 交易所用于充值、冷钱包、充值归集、清算 | 它是交易通道，不是观点表达者 |
| | C3 桥/路由/聚合器/Solver | 负责跨链、路由、聚合和执行的地址 | 很多时候只是路径，要判断谁是终态买方 |
| | C4 LP/池子/流动性调度 | 负责池子增减仓和深度调度的地址 | 看这个币的深度在变厚还是变薄 |
| **D 去噪排除** | D1 MEV/套利/高频机器人 | 高频执行、净值接近零的地址 | 防止把机器人当聪明钱 |
| | D2 羊毛/女巫/营销分发 | 围绕空投和活动的批量小号 | 防止把热闹当成真实需求 |
| | D3 污染型伪高手 | 看起来收益不错但不可复制的运气型地址 | 防止把运气好的人当高质量鲸 |
| | D4 已知操纵者 | 有历史 Rug Pull、操纵记录的地址 | 风险标记 |
| **E 特殊观察** | E1 借贷/清算相关 | 在波动和爆仓阶段很关键的钱包 | 谁快扛不住了 |
| | E2 托管/代持 | 资金存在但决策权未必在手 | 钱在这儿，不一定是它自己在做决定 |
| | E3 治理/质押/验证 | 与治理、质押、共识机制有关的地址 | 看制度层的变化 |
| | E4 稳定币发行方 | Tether Treasury、Circle Mint 等 | 宏观资金意愿的风向标 |

### 2.2 跨类机制

同一实体对不同 Token 的角色可以不同。通过"实体 × Token 角色矩阵"实现：

```
Paradigm 对 ETH = A1 (主动买入新仓位)
Paradigm 对 已解锁项目Token = B1 (持有低成本筹码的潜在卖方)
```

## 三、实体风格标签体系（三层）

### A 层：主风格标签（Alpha 来源）

该实体主要依赖何种模式获利。**每个实体仅贴 1 个主标签（最多 1 个辅助）。**

P0 精选：事件驱动型、趋势配置型、早期发现型

### B 层：修饰风格标签（行为执行路径）

该实体惯用的建仓、持仓及退出手法。**每个实体贴 2-4 个。**

P0 精选：左侧潜伏/右侧确认、阶梯建仓/一次性重仓、分批止盈/快速兑现、中线持有、高集中度

### C 层：状态与适配性标签（有效性与胜率场景）

该实体当前的有效性及最擅长的生态/环境。**每个实体贴 1-3 个，需高频动态更新。**

P0 精选：近期有效/近期衰减、高波动期有效、中小市值有效、特定生态有效（如 Solana）

### 量化优先级

- **P0（V1 必做）**：可观测性强、可回测的硬指标
- **P1/P2（逐步迭代）**：需依赖额外数据或逻辑较重
- **P3（暂缓）**：主观性强，保留人工标注

## 四、行为识别体系

### 4.1 五类行为识别

CBS 的 Event Layer 将所有链上活动归入五类：

| 行为类型 | 定义 | 处理方式 |
|---------|------|---------|
| **真实买入** | 实体主动建立或增加对某风险资产的敞口 | 计入指标 1/2/3 |
| **真实卖出** | 实体主动减少或退出对某风险资产的敞口 | 计入指标 1/2/3 |
| **迁移行为** | 资产在地址或账户之间转移，不代表观点变化 | 计入指标 6 |
| **结构行为** | 做市、路由、桥接、LP 调度等执行层行为 | 过滤/穿透后归类 |
| **噪音行为** | 对研究判断没有实际意义的动作 | 丢弃 |

### 4.2 买入确认层级

| 层级 | 定义 | 置信度 |
|------|------|:------:|
| 绝对确认买入 | 风险资产增加 + 主要资产减少 + 同 hash 配对 | 1.0 |
| 推定确认买入 | 前序主要资产流出 + 后续风险资产流入 + 时间窗口/规模匹配 | 0.6-0.8 |
| LP 隐含买入 | 策略型 LP 区间穿越完成 | 0.5 |
| LP 意图信号 | 策略型 LP 下方窄区间设定（等效限价买单）| 0.2 |

**不应计入买入**：VC 轮分配、空投/奖励、LP 撤除后收币、非透明 OTC

卖出侧采用对称设计。

### 4.3 LP 行为处理

LP 不是独立于买卖的第三种行为，而是买卖的一种执行手法。处理流程：

```
LP 事件
├── 实体一级分类?
│   ├── A/B 类 → 方向性分析
│   │   ├── 下方窄区间 → 隐含买入 (A-3)
│   │   ├── 上方窄区间 → 隐含卖出 (A-4)
│   │   ├── 区间穿越完成 → 确认买入/卖出
│   │   ├── 买入后质押 → 信号增强标签 BUY+STAKE (A-2)
│   │   └── 全范围 LP → 非方向性，仅计入指标 7
│   ├── C1 类 → 做市商行为分析 (见 4.4)
│   ├── C4/其他 → 仅计入指标 7
│   └── D 类 → 丢弃
```

### 4.4 做市商行为处理

从 33 种穷举行为中筛选的 18 种高价值信号，按处理方式分类：

**计入指标 1（含方向性的交易行为）**：
- 非做市 Token 上自营买入/卖出（置信度 1.0）
- 做市中异常单向大额交易（剥离做市噪声后）
- 多 Token 同方向操作

**计入指标 6 层 1（方向性结构事件）**：
- 做市区间整体上移/下移
- 库存偏向 Token 端/稳定币端
- 做市商撤出/新增做市
- 多做市商同向入场/撤出

**计入指标 6 层 2（事件明细）**：
- 所有 ★★★★+ 做市商事件的完整记录

```
┌─────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────┘
```

## 六、指标体系（7+1 最终版）

### 6.1 指标 7 定位分析

#### 原定义 vs v2.2 定义对比

| 维度 | 原定义（LP 行为变化） | v2.2 定义（流动性环境变化） |
|------|---------------------|------------------------|
| 关注对象 | LP 提供者（暗含白名单） | 全量 LP + Token 整体 |
| 核心数据 | 撤池/迁池/区间调整 | TVL/深度/LP 数变化 |
| 信号含义 | "有人在撤流动性"（行为） | "流动性环境在变差"（结果） |
| 价值定位 | DEX 原生项目的早期风险信号 | Token 级流动性基础面 |
| 噪音来源 | 做市再平衡、正常调仓 | 被稀释（全量统计噪音更大） |
| 触发逻辑 | 撤池+深度恶化→风险提醒 | TVL 变化→环境评估 |

#### 客观评价

**原定义更贴近 CBS 的核心价值——它关注的是"行为"而非"结果"。**

CBS 的灵魂是"谁在做什么"。指标 1-6 都是行为驱动的（谁买了、谁卖了、谁入所了、谁做市了），只有 v2.2 的指标 7 变成了"环境结果"。这打破了 CBS 内部的一致性。

但原定义也有问题：
1. 白名单 LP 的方向性行为（A 类策略型 LP）在 v2.3 中已归入指标 1，不应在指标 7 重复
2. 做市商 LP 异常行为在 v2.4 中已归入指标 6，也不应重复
3. 如果原定义只追踪白名单 LP，剩下的信号被抽走后内容太单薄

**最优方案：融合两者。**

指标 7 应该是**"流动性行为与环境"——既看行为也看结果**，但与指标 1/6 严格不重叠：

| 来源 | 信号内容 | 归入指标 |
|------|---------|---------|
| A/B 类地址的策略型 LP | 方向性买卖信号 | 指标 1（已确定） |
| C1 做市商的异常 LP 行为 | 结构性事件 | 指标 6（已确定） |
| **全量 LP 的 TVL/深度/LP 数变化** | **流动性环境趋势** | **指标 7** |
| **撤池/深度恶化模式检测** | **流动性风险早期预警** | **指标 7** |
| **LP 迁移（V2→V3, 链 A→链 B）** | **流动性结构变化** | **指标 7** |
| **流动性集中度**（少数LP控制大量TVL） | **流动性脆弱性** | **指标 7** |

#### 指标 7 最终定义

```
指标 7: 流动性行为与环境

回答的问题: "这个 Token 的流动性在变好还是变差？有没有流动性风险的早期信号？"

数据范围: 全量 LP 数据（不限白名单）
时间窗口: 7d / 30d

子维度:
  7a: TVL 变化趋势 (总锁仓量的 7d/30d 变化)
  7b: LP 提供者数量变化 (参与做市的地址数变化)
  7c: 深度变化 (买卖各 2% 价格区间内的挂单深度)
  7d: 流动性集中度 (Top 5 LP 占总 TVL 的比例——越高越脆弱)
  7e: 撤池/深度恶化模式 (短时间内多个LP撤出 + 深度骤降)

有向值逻辑:
  正值: TVL↑ + LP数↑ + 深度↑ + 集中度↓ → 流动性健康改善
  负值: TVL↓ + LP数↓ + 深度↓ + 集中度↑ → 流动性恶化/风险
  
特殊触发: 7e 撤池模式检测到时 → 强负向值 + 异动推送
  原文"撤池+深度恶化→高风险提醒或降级"的逻辑被保留在此
```

这个定义融合了原定义的"早期风险信号"价值和 v2.2 的"环境全貌"价值，同时不与指标 1/6 重叠。

### 6.2 完整指标体系

7 个指标不分组，扁平排列。每个指标独立输出有向值（正=看多/健康，负=看空/风险）。

| # | 名称 | 回答的问题 | 数据来源 | 时间窗口 | 权重 |
|---|------|---------|---------|---------|:----:|
| 1 | **高质量资金净流入/流出** | 白名单确认买卖的净方向 | 白名单地址的 Swap + 推定买卖 + LP 隐含买卖 | 24h/7d/30d | 0.25 |
| 2 | **连续增持/减持天数** | 方向持续多久 | 指标 1 的连续同向天数 | 本身是时间指标 | 0.15 |
| 3 | **高质量资金参与动态** | 多少人参与、方向一致性 | 3a 新增实体数 + 3b 净方向比例 + 3c 覆盖率 | 24h/7d/30d | 0.15 |
| 4 | **交易所净流量** | CEX 端资金供需 | 白名单地址的 CEX 入金/出金差 | 24h/7d/30d | 0.15 |
| 5 | **持仓集中度变化** | 筹码向谁集中/分散 | 分层持仓分析 + 一级分类叠加 | 7d/30d | 0.10 |
| 6 | **结构性资金事件** | 除买卖外还有哪些结构动向 | 层 1 量化 + 层 2 事件流 | 事件触发 | 0.10 |
| 7 | **流动性行为与环境** | 流动性在变好还是变差 | 全量 LP: TVL + 深度 + LP 数 + 集中度 + 撤池检测 | 7d/30d | 0.10 |
| Adj | **Perp 仓位修正** | 衍生品增强/削弱现货信号 | Hyperliquid + 链上 Perp | 当前快照 | 乘数 |

### 6.3 各指标详细定义

#### 指标 1: 高质量资金净流入/流出

```
计算:
  NetFlow = Σ(确认买入量 × quality_score) - Σ(确认卖出量 × quality_score)

确认买入包含:
  - DEX Swap (置信度 1.0)
  - CEX 等额对价推定 (0.6-0.8)
  - LP 隐含买入 (区间穿越 0.5, 区间设定 0.2)
  - 做市商自营买入 (1.0)

不计入: VC轮分配、空投、LP撤除后收币、Router/聚合器(穿透到终端)
```

#### 指标 2: 连续增持/减持天数

```
如果指标 1 的 24h 值 > 0，且前一天也 > 0，天数 +1
如果指标 1 的 24h 值 < 0，且前一天也 < 0，天数 -1
方向翻转时重置
```

#### 指标 3: 高质量资金参与动态

```
3a: 新增参与实体数 (首次与该Token交互的白名单实体)
3b: 净方向比例 = (净买入实体数 - 净卖出实体数) / 总活跃实体数
3c: 覆盖率 = 参与该Token的白名单实体数 / 白名单总实体数

有向值 = f(3a增长率, 3b方向, 3c变化趋势)
```

#### 指标 4: 交易所净流量

```
仅基于白名单地址的 CEX 入出金:
  正值 = 净提币 (看多信号)
  负值 = 净充值 (看空信号)

注意: 金额维度由指标4负责，"谁在做"的实体维度由指标6负责
```

#### 指标 5: 持仓集中度变化

```
分层持仓分析 (方法C):
  Layer 1 (鲸鱼层): 持仓 > 总供应量的 0.1%
  Layer 2 (中等层): 0.01% ~ 0.1%
  Layer 3 (零售层): < 0.01%
  排除: CEX / 合约 / 桥 / 销毁地址

每层叠加一级分类标签:
  A 类鲸鱼占比↑ → 正向
  B 类鲸鱼占比↑ → 负向
  散户分散化 → 结构改善 (正向)

每 24h 快照，计算 7d/30d 变化
```

#### 指标 6: 结构性资金事件

```
层 1 (量化，参与 CBS Score):
  将有方向性但不属于买卖的事件量化为有向值:
  - 大额入所 (偏空，按 金额/总持仓 × 实体质量 计负分)
  - 大额出所 (偏多，按同等公式计正分)
  - 跨链迁移 (按迁移方向判断)
  - 冷→热钱包转移 (偏空，卖出前兆)
  - 做市商区间上移/下移 (按偏移方向)
  - 做市商库存偏移 (按偏向方向)
  - 做市商撤出/新增做市 (偏空/偏多)
  - 多做市商同向模式 (强方向性)

  不重叠规则:
  - 已计入指标1的(Swap买卖) → 不计入指标6
  - 指标4记录CEX入出金金额 → 指标6记录"谁在做"的实体方向性加权

层 2 (事件流，不参与评分):
  完整事件明细 → Dashboard + 异动推送
  包含: 实体身份/Contrast Layer基线对比/推测/后续观察建议
```

#### 指标 7: 流动性行为与环境

```
全量 LP 数据 (不限白名单):
  7a: TVL 变化 (7d/30d)
  7b: LP 提供者数量变化
  7c: ±2% 区间深度变化
  7d: 流动性集中度 (Top 5 LP 占 TVL 比例)
  7e: 撤池模式检测 (短时间多LP撤出 + 深度骤降)

有向值:
  综合 7a-7d 的改善/恶化方向
  7e 触发时: 强制负向 + 异动推送 ("撤池+深度恶化→高风险提醒")

不重叠:
  - 白名单LP的方向性行为 → 已归入指标1
  - 做市商LP异常 → 已归入指标6
  - 指标7只负责Token级的流动性全貌
```

#### Perp 修正项

```
数据源: Hyperliquid (P1优先) + GMX/dYdX (P2)
仅修正CBS总分，不独立输出

净多头 → 乘数 > 1 (增强现货信号)
净空头 → 乘数 < 1 (削弱现货信号)
中性 → 乘数 = 1

排除: C1a/C1b 做市行为的Perp仓位 (delta-neutral对冲)
纳入: C1d 自营交易的Perp仓位

启用条件: 有活跃合约市场 + 地址群仓位可观测 + 数据稳定
否则: 修正值 = 1 (不修正)
```

### 6.4 指标间关系

```
指标 1 (净流入)  ←── 核心方向指标
   ├── 指标 2 (增持天数): 时间维度衍生
   ├── 指标 3 (参与动态): 广度维度分解 ("多少钱" vs "多少人")
   └── 指标 4 (交易所流量): 独立数据源验证 (CEX vs DEX)

指标 5 (持仓集中度) ←── 独立于交易的持仓结果分析

指标 6 (结构性事件) ←── 非买卖行为的方向性信号 + 事件明细

指标 7 (流动性环境) ←── Token级环境指标，不限于白名单

7 个指标不分组，各自独立输出有向值，通过权重汇总
```

## 七、CBS 评分与输出

### 7.1 CBS Score

```
CBS_Score = [Σ(wi × Ii_normalized)] × PerpModifier

每个指标归一化到 [-100, +100]
加权求和后归一化到 [-100, +100]

附加: 窗口共振
  某指标 24h/7d/30d 全同向 → 该指标权重 ×1.2
  窗口间出现反转 → 输出 SHORT_REVERSAL 标记

评分区间:
  +60 ~ +100: 强看多信号
  +20 ~ +60:  温和看多
  -20 ~ +20:  中性
  -60 ~ -20:  温和看空
  -100 ~ -60: 强看空信号
```

### 7.2 输出形式

```
Token: $XYZ | CBS Score: 71 | 趋势: ACCELERATING
```
