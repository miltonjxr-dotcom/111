## 问题一：LP 与做市商的"一级分类 vs 信号贡献"矛盾

### 1.1 矛盾的本质

一级分类中，LP（C4）和做市商（C1）被归入"中介通道"。但在实际信号层面，它们产生的行为经常等价于买入/卖出，且对投研有重大参考价值。这不是分类错误，而是**"身份"和"行为"是两个不同维度**的问题。

**一个实体的身份是固定的（它是做市商），但它的某次具体行为可以是多种性质（做市 / 自营 / 风控退出）。**

### 1.2 解决思路：分类归分类，信号归信号

一级分类（A/B/C/D/E）解决的是**"这个实体是谁"**的问题。它不应该决定这个实体的行为是否被纳入信号计算。决定信号贡献的是 Event Layer 对具体行为的判定结果。

```
正确的逻辑链:
  实体身份 (一级分类) → 告诉我们"谁在做"
  行为判定 (Event Layer) → 告诉我们"做了什么"
  信号计算 (指标层) → 综合"谁"+"做了什么"输出信号

错误的逻辑链:
  实体身份 = C1 做市商 → 所以它的行为不算信号  ← 这是错的
```

### 1.3 买入/卖出行为的完整图谱

你的反馈提到了多种买入/卖出手段，以下是完整梳理：

| 行为路径 | 举例 | 是否构成"真实买入/卖出" | 置信度 |
|---------|------|:--:|:--:|
| **DEX Swap** | 在 Uniswap 用 USDC 换 Token | 绝对确认 | 1.0 |
| **CEX 等额对价推定** | 转入等额 USDT 到 CEX/DEX，一段时间后转出等值/不等值 Token | 推定确认 | 0.6-0.8 |
| **集中流动性 LP 区间穿越** | 在 Uniswap V3 设置单边区间，价格穿越后全部变为 Token | 隐含买入 | 0.5 |
| **集中流动性 LP 区间设定** | 在当前价格下方设窄区间（等效限价买单），但尚未穿越 | 意图信号 | 0.2 |
| **全范围 LP 添加** | 添加 V2 式的全范围 LP，提供双边流动性 | 非方向性 | 0 |
| **做市商库存偏移** | 做市商有意在做市过程中保持偏向某一边 | 隐含方向性 | 0.3 |
| **做市商自营 Swap** | 做市商用非做市地址在非做市对上进行单向交易 | 绝对确认 | 1.0 |
| **跨链转入后买入** | 从 A 链 bridge 资金到 B 链，在 B 链买入 Token | 绝对确认 (B 链 swap) | 1.0 |
| **OTC/大宗匹配** | 链上看到大额对价转移但不经 DEX | 推定确认 | 0.5 |

**关键结论：LP 操作不是独立于买卖的第三种行为，而是买卖的一种"执行手法"。** 它和 Swap、CEX 出入金一样，都是实现"真实风险敞口变化"的路径之一。

### 1.4 LP 指标的双重含义

你指出了 LP 指标实际上指向两种完全不同的信号：

**含义 1：高质量资金的 LP 行为 → 作为方向性/意图信号**

- 某 A3 类匿名高手为 $XYZ 组了集中流动性 LP → 可能看好，也可能是买入/卖出策略
- 某做市商大幅撤出 $XYZ 的 LP → 风控信号
- 多个独立实体同时在 $XYZ 下方加 LP → 集体"限价买入"意图

**含义 2：某 Token 的整体 LP 状态变化 → 作为流动性环境信号**

- 其他模块（如 NDS 叙事信号）触发了对 $XYZ 的关注，分析师来 CBS 查看该 Token 的 LP 变化
- 这时关注的不是"谁在做 LP"，而是"这个 Token 的流动性环境是在变好还是变差"
- 包括：总 TVL 变化、LP 提供者数量变化、深度变化、集中度变化

**这两种含义对应完全不同的问题：**

| 维度 | 含义 1 (实体行为) | 含义 2 (Token 环境) |
|------|:--:|:--:|
| 关注对象 | 白名单中的高质量实体 | 所有 LP 提供者 |
| 数据范围 | 仅白名单地址 | 全量地址 |
| 触发方式 | CBS 模块自身计算 | 其他模块触发查询 |
| 信号含义 | "聪明钱在 LP 上做了什么" | "这个 Token 的流动性基础面如何" |

**建议处理方式**：含义 1 并入各主项指标（LP 隐含买卖计入净流入，LP 异常行为计入异动追踪），含义 2 作为 Token 级"流动性快照"供跨模块查询，不独立计分。具体见后文指标重构。

## 问题二：指标边界模糊与是否取消分组

### 2.1 问题本质

你的核心质疑是：

> "实体的异动追踪是否和指标 1、指标 2 重复？流入流出也算实体的异动。这几个指标的边界不清晰。能否不分类？最终影响信号的就是权重。"

这是一个非常尖锐且合理的问题。让我不讨好地直面分析。

### 2.2 诚实评估：当前指标之间确实存在边界模糊

| 指标对 | 重叠之处 | 独立之处 |
|--------|---------|---------|
| 净流入(1) vs 实体异动(6) | 一个 A1 机构买入 $2M，既是"净流入"也是"实体异动" | 指标 1 是**聚合值**（所有实体加总），指标 6 是**事件级**（单个实体的单次行为） |
| 增持天数(2) vs 净流入(1) | 增持天数本质上是指标 1 在时间维度上的衍生 | 指标 2 强调**持续性**而非**量级** |
| LP 行为(7) vs 净流入(1) | 策略型 LP 的隐含买卖应计入净流入 | 做市型 LP 和流动性环境不属于净流入 |
| 交易所流量(4) vs 净流入(1) | CEX 提币后到链上买入，同一事件触发两个指标 | 指标 4 是**推断性**（提币≠买入），指标 1 是**确认性** |
| 实体异动(6) vs LP行为(7) | 做市商撤 LP 既是"实体异动"也是"LP 行为" | 概念上重叠 |

**结论：7 个指标中，确实存在信息层面的交叉。它们不是 7 个完全正交的维度。**

### 2.3 是否应该取消分组？

**可以取消分组，但不建议取消指标本身。** 原因如下：

**取消分组的合理性**：
- 分组（资金方向/市场结构/行为追踪）的边界确实模糊
- 最终影响 CBS Score 的确实是每个指标的权重，分组只是视觉组织
- 强行分组可能给分析师造成"这几个指标是同一类"的误解，而实际上它们内部差异可能比组间差异更大

**保留指标本身的合理性**：
- 虽然有信息交叉，但每个指标回答的"问题"不同（见下表）
- 指标间的交叉在某种程度上是**互相验证**——净流入高 + 增持天数长 + 新增参与多，三者指向同一方向但各自独立计算，共振时置信度更高
- 对分析师而言，看到不同角度的数据比一个黑箱总分更有决策参考价值

### 2.4 v2.2 方案：取消分组，保留指标，重新定义每个指标的独特"问题域"

| # | 指标 | 回答的问题 | 独特数据来源/逻辑 | 与其他指标的关系 |
|---|------|---------|-----------------|--------------|
| 1 | 高质量资金净流入/流出 | "白名单资金对该 Token 的净方向是什么？" | 汇总所有白名单实体的确认买入/卖出（含 LP 隐含买卖），输出加权净值 | 是"总量"指标，指标 2/3 是其不同维度的分解 |
| 2 | 连续增持/减持天数 | "这个方向持续了多久？" | 基于指标 1 的符号（正/负）连续天数计数 | 依赖指标 1，但独立表达"持续性" |
| 3 | 高质量资金参与动态 | "多少独立实体在参与？方向是否一致？" | 统计实体数量和方向分布，不看金额 | 与指标 1 互补：1 看"多少钱"，3 看"多少人" |
| 4 | 交易所净流量 | "CEX 维度的资金供需如何？" | 仅基于 CEX 地址的入出金数据 | 独立数据源，与链上 DEX 数据互相验证 |
| 5 | 持仓集中度变化 | "筹码在向谁集中/分散？" | 基于 Token 持仓快照的分布分析 | 独立于交易行为，反映持仓**结果** |
| 6 | 标记实体异动 | "有哪个关键实体做了异常的事？" | 单个实体级别的异常行为检测（Contrast Layer） | 是"事件级"信号，其他指标是"聚合级" |
| 7 | 流动性环境变化 | "这个 Token 的流动性基础面在变好还是变差？" | 全量 LP 数据（不限于白名单），TVL/深度/LP 数变化 | 不依赖白名单，是 Token 级环境指标 |

**关键修正**：

1. **取消三组分类**。7 个指标不分组，扁平排列，各自独立输出有向值。
2. **指标 6（实体异动）重新定义**：不是"所有实体的所有行为"，而是**"偏离该实体自身基线的异常行为"**。一个 A1 机构常规地每周买入一些 Token，这计入指标 1 但不触发指标 6。只有当它突然买入了历史中位数 3 倍的量，或者首次参与一个新 Token，才触发指标 6。**指标 6 的独特性在于"异常检测"，而非"行为追踪"。**
3. **指标 7 重新定义**：从"LP 行为变化"改为"流动性环境变化"。白名单实体的 LP 操作中有方向性的部分（策略型 LP）归入指标 1；做市商异常 LP 行为归入指标 6；指标 7 只负责"这个 Token 的流动性环境整体怎么样"。

### 2.5 指标间关系图

```
指标 1 (净流入)  ←── 核心方向指标，汇总所有确认买卖
   │
   ├── 指标 2 (增持天数): 指标1的时间维度衍生
   │
   ├── 指标 3 (参与动态): 指标1的广度维度分解
   │
   └── 指标 4 (交易所流量): 独立数据源验证指标1

指标 5 (持仓集中度) ←── 独立于交易的持仓结果分析

指标 6 (实体异动)   ←── 事件级异常检测，触发投研介入

指标 7 (流动性环境) ←── Token 级环境指标，不限于白名单
```

指标 1/2/3/4 构成"资金方向证据链"（从不同角度互相验证），指标 5/6/7 各自独立回答不同问题。**它们不需要分组，但它们确实不冗余。**

## 问题三：持仓集中度的本质与计算方法

### 3.1 持仓集中度到底是什么？

持仓集中度衡量的是：**一个 Token 的供应量有多大比例被少数地址控制。**

这对投研有两个核心意义：
1. **控盘风险**：如果少数地址持有 70% 供应量，它们的任何行为都能剧烈影响价格
2. **筹码流转方向**：集中度在上升还是下降，反映筹码是在"聚集"还是"分散"

### 3.2 "统计 Top N 集中度变化就够了吗？"

**够用于 V1，但不是最好的方法。** 客观分析如下：

#### 方法 A：Top N 持仓占比（简单直接）

```
计算: Top10_Ratio = Σ(Top 10 地址持仓) / 总供应量
信号: Top10_Ratio_Change = 本期 - 上期
```

| 优点 | 缺点 |
|------|------|
| 计算简单，直观易懂 | N 的选择是主观的（Top 10 还是 Top 20 还是 Top 50？） |
| 对分析师的可解释性强 | 无法区分"一个人持有 50%"和"10 个人各持有 5%"，两者 Top10 占比相同但风险完全不同 |
| 适合 V1 快速上线 | 如果 CEX 地址占 Top 10，会严重干扰（需要排除已知 CEX/合约地址） |

#### 方法 B：HHI 指数（赫芬达尔-赫希曼指数）

```
计算: HHI = Σ(si²)，其中 si 是每个地址的持仓占比
范围: 0 (完全分散) ~ 1 (一个人持有全部)
```

| 优点 | 缺点 |
|------|------|
| 金融学标准方法，无需选择 N | 对分析师不够直观 |
| 能区分"一人持 50%"和"10 人各持 5%" | 计算需要全量持仓数据（成本较高） |
| 无 Top N 选择的主观性 | 微小地址太多会稀释指标含义 |

#### 方法 C：分层持仓分析（推荐的最优方案）

```
不是统计 Top N，而是按持仓规模分层:

Layer 1 (鲸鱼层): 持仓 > 总供应量的 0.1% 的地址
Layer 2 (中等层): 持仓在 0.01% ~ 0.1%
Layer 3 (零售层): 持仓 < 0.01%

分别计算:
- 每层的总持仓占比
- 每层的地址数量变化
- 跨层的筹码流转方向（鲸鱼层 → 零售层 = 分散化）
```

| 优点 | 缺点 |
|------|------|
| 能同时看到"谁在集中"和"在向哪里流转" | 计算复杂度高于 Top N |
| 分层阈值可以用相对值（占比），适用于不同市值的 Token | 需要全量持仓数据 |
| 直接服务于投研判断："鲸鱼在加仓，散户在离场" | 需要排除合约地址/CEX/桥 |

### 3.3 与一级分类的结合

前文指出"集中度方向需要结合 A/B/C/D/E 分类判断"。这在分层分析中天然实现：

```
如果我们在分层分析中叠加一级分类标签:

鲸鱼层中:
  A 类(主动买方)持仓占比 ↑ → 强正向信号
  B 类(潜在卖方)持仓占比 ↑ → 风险信号
  C 类(中介通道)持仓占比 ↑ → 中性（可能是做市库存）

散户层中:
  地址数量 ↑ + 持仓占比 ↑ → 分散化（结构健康）
  地址数量 ↓ + 持仓占比 ↓ → 集中化（可能被洗出）
```

### 3.4 V1 建议

**V1 阶段用 Top N + 一级分类标签即可**，原因：
1. 全量持仓快照的获取和计算有一定成本，V1 优先控制复杂度
2. Top N（建议 Top 20，排除已知 CEX/合约/桥地址）对投研分析师已有足够参考价值
3. 在 Top 20 中标注每个地址的一级分类，分析师可以快速判断"集中在谁手里"

**Phase 2 升级为分层持仓分析**，增加跨层流转检测。

## 问题四：Hyperliquid 作为信号来源链

### 4.1 Hyperliquid 的独特价值

Hyperliquid 不同于一般 EVM 链。它是一条**专为衍生品设计的链**，其特殊性在于：

| 维度 | Hyperliquid | 一般 EVM 链 |
|------|-------------|-----------|
| 核心功能 | 永续合约交易 | 通用智能合约/DeFi |
| 数据类型 | 仓位数据（多空、杠杆、清算） | Transfer/Swap/LP 事件 |
| CBS 价值 | **Perp 修正项的最高质量数据源** | 现货方向性信号 |
| 数据透明度 | 所有仓位完全链上可查（含地址） | 标准 EVM 透明度 |
| 与白名单的关联 | 很多已知鲸鱼/机构在 Hyperliquid 上活跃 | 取决于链的生态 |

**Hyperliquid 的核心价值不在于它是一条"需要覆盖的链"，而在于它是 Perp 修正项最直接、最高质量的数据源。**

### 4.2 具体信号贡献

| Hyperliquid 数据 | 对应 CBS 环节 | 信号含义 |
|-----------------|-------------|---------|
| 白名单地址的永续合约多头仓位 | Perp 修正项 — LeverageRatio | 现货信号的增强确认 |
| 白名单地址的永续合约空头仓位 | Perp 修正项 — HedgeRatio | 现货信号的对冲折扣 |
| 大额仓位变动 | 指标 6（实体异动） | 关键实体在 Perp 端的异常行为 |
| 清算事件 | 异动触发 | 大额清算 = 强制平仓信号 |
| 资金费率 | 全局参考 | 市场整体多空情绪 |
| 某 Token 的未平仓合约量变化 | Token 级参考数据 | 衍生品端的关注度 |

### 4.3 接入建议

| 阶段 | 接入内容 | 理由 |
|------|---------|------|
| **Phase 1** | Hyperliquid 白名单地址的仓位快照（每小时） | 即使 Perp 修正项在 Phase 2 才正式启用，提前采集数据可以积累历史基线 |
| **Phase 2** | 正式接入 Perp 修正项计算 + 异动触发 | 有了历史数据支撑，修正参数更可靠 |
| **持续** | 大额清算事件的实时推送 | 清算是高价值异动信号，不需要等 Perp 修正项 |

**Hyperliquid 应该被视为"Perp 数据层"而非"又一条需要覆盖的链"。** 它与 EVM 链的数据管道逻辑不同——不需要解析 Swap/Transfer/LP 事件，而是直接读取仓位数据和交易记录。

### 4.4 其他链上 Perp 协议的对比

| 协议 | 链 | 数据透明度 | 活跃度 | 接入优先级 |
|------|---|:--:|:--:|:--:|
| **Hyperliquid** | Hyperliquid L1 | ★★★★★ | ★★★★★ | **P1 最高优先** |
| GMX v2 | Arbitrum | ★★★★ | ★★★★ | P2 |
| dYdX v4 | dYdX Chain (Cosmos) | ★★★★ | ★★★ | P2 |
| Jupiter Perps | Solana | ★★★ | ★★★★ | P2 |
| Vertex | Arbitrum | ★★★ | ★★ | P3 |

**Hyperliquid 是第一优先级**，因为：(1) 数据完全链上透明；(2) 活跃度最高（日交易量经常超越所有 DEX Perp 之和）；(3) 很多高质量资金/鲸鱼以 Hyperliquid 为主要衍生品交易场所。

## 问题五：三组分类的合理性审视

### 5.1 "资金方向信号 / 市场结构信号 / 行为追踪信号"到底在说什么？

让我先严格定义，然后诚实评估。

| 分组 | 我给的定义 | 直白翻译 |
|------|---------|---------|
| 资金方向信号 | 核心方向性判断——钱在往哪流、持续了多久、多少人参与 | "聪明钱在买还是卖" |
| 市场结构信号 | CEX 层面的供需 + 筹码分布 | "盘面结构怎么样" |
| 行为追踪信号 | 关键实体的异常行为 + 流动性环境 | "有没有值得关注的事" |

### 5.2 诚实评估：分组是有问题的

| 问题 | 具体说明 |
|------|---------|
| **边界模糊** | 交易所净流量（指标 4）和净流入（指标 1）都在回答"钱在往哪流"，为什么一个是"资金方向"一个是"市场结构"？仅因为数据源不同？这对分析师没有意义。 |
| **分组暗示了优先级** | 把 1/2/3 叫"资金方向"，把 4/5 叫"市场结构"，会让分析师觉得前者更重要。但实际上 CEX 大额流出可能比链上小额买入更有信号价值。 |
| **实体异动和 LP 被强行归入一组** | 指标 6（异常行为检测）和指标 7（流动性环境）的逻辑完全不同，放在一起只因为"剩下的不知道放哪"。 |
| **分组增加了认知成本** | 分析师在看 Dashboard 时，三组分类增加了一层"这属于哪类"的认知负担，但没带来更好的理解。 |

### 5.3 v2.2 决策：取消分组

**采纳你的建议：7 个指标不分组，扁平排列。每个指标独立输出有向值，通过权重直接汇总为 CBS Score。**

理由：
1. 分组在逻辑上不严密（如上分析）
2. 对投研分析师来说，7 个指标的 Dashboard 已经足够直观，不需要中间层的"分组"概念
3. 取消分组后，指标间的"互相验证"关系反而更清楚——分析师可以自行判断哪些指标在共振
4. 权重本身就已经表达了重要性差异，不需要分组来额外暗示

**但保留指标间关系的文档说明**（如 2.5 节的关系图），帮助分析师理解"为什么有些指标看起来相关"。

## 问题六：时间颗粒度的本质与使用方式

### 6.1 时间颗粒度是什么？

时间颗粒度（Time Granularity / Time Window）是指：**计算某个指标时，向回看多长的时间范围。**

同一个指标在不同时间窗口下可能给出完全不同的信号：

| 指标 1（净流入）| 24h | 7d | 30d |
|---|---|---|---|
| $XYZ | +$2.3M | -$1.5M | +$8.7M |
| 含义 | 短期在流入 | 中期在流出 | 长期整体流入 |
| 分析师解读 | 可能是反弹 | 可能是下跌中继 | 长期资金仍然看好 |

**时间颗粒度不是"多久更新一次"（那是计算频率），而是"每次计算时向回看多远"。**

### 6.2 不同时间窗口回答不同问题

| 窗口 | 回答的问题 | 适用场景 | 对投研的价值 |
|------|---------|---------|-----------|
| **24h** | "最近一天发生了什么？" | 捕捉短期异动、即时信号 | 发现新动作 |
| **7d** | "最近一周的趋势是什么？" | 判断短期趋势方向 | 确认方向、寻找拐点 |
| **30d** | "过去一个月的整体态势如何？" | 判断中期趋势、区分噪音 vs 趋势 | 建立基线认知 |

### 6.3 如何使用：信号共振逻辑

**核心用法：当多个时间窗口指向同一方向时，信号置信度更高。**

```
场景 A: 三窗口共振 (强信号)
  24h 净流入: +$2M
  7d  净流入: +$5M
  30d 净流入: +$12M
  → 短中长期资金持续流入，方向高度一致
  → 置信度: ★★★★★

场景 B: 短期反转 (关注信号)
  24h 净流入: +$3M
  7d  净流入: -$1M
  30d 净流入: -$8M
  → 短期出现反转信号，但中长期仍在流出
  → 置信度: ★★ (可能是反弹，不是趋势转变)
  → 投研动作: 标记观察，等待 7d 窗口确认

场景 C: 长期转向 (高价值信号)
  24h 净流入: +$0.5M
  7d  净流入: +$2M
  30d 净流入: -$3M (但趋势在收窄)
  → 30d 仍为负但在好转，7d 已转正
  → 置信度: ★★★★ (可能是趋势拐点)
  → 投研动作: 建议深入调研
```

### 6.4 v2.1 建议 3 个窗口（24h/7d/30d）的评估

v2.1 将 v2 的 5 个窗口（1h/4h/24h/7d/30d）简化为 3 个。**这个简化对投研定位是合理的，但需要补充"窗口比较"逻辑。**

不是简单地分别计算三个值然后展示，而是要**自动识别窗口间的模式**：

| 模式 | 定义 | 信号含义 | 自动标签 |
|------|------|---------|---------|
| **全共振看多** | 24h > 0 且 7d > 0 且 30d > 0 | 强看多 | `BULL_ALIGNED` |
| **全共振看空** | 24h < 0 且 7d < 0 且 30d < 0 | 强看空 | `BEAR_ALIGNED` |
| **短期反转** | 24h 与 7d 方向相反 | 可能的拐点 | `SHORT_REVERSAL` |
| **趋势加速** | 24h 绝对值 > 7d 日均 > 30d 日均 | 趋势在加速 | `ACCELERATING` |
| **趋势减速** | 24h 绝对值 < 7d 日均 < 30d 日均 | 趋势在减弱 | `DECELERATING` |
| **混合信号** | 三个窗口方向不一致 | 市场纠结 | `MIXED` |

### 6.5 在 Dashboard 中的呈现

```
指标 1: 高质量资金净流入/流出

  24h:  +$2.3M  ████████████░░░░  (中等流入)
  7d:   +$5.1M  ████████████████  (强流入)
  30d:  -$1.2M  ░░░░██░░░░░░░░░░  (轻微流出)

  模式: SHORT_REVERSAL — 短期已转正，但30d仍偏空。7d确认中。
  趋势: 30d日均 -$40K → 7d日均 +$729K → 24h +$2.3M (加速改善)
```

### 6.6 哪些指标适合哪些窗口

不是每个指标都需要三个窗口：

| 指标 | 24h | 7d | 30d | 说明 |
|------|:--:|:--:|:--:|------|
| 1 净流入 | ✓ | ✓ | ✓ | 三窗口都有意义 |
| 2 增持天数 | — | — | — | 本身就是时间指标，不需要窗口 |
| 3 参与动态 | ✓ | ✓ | ✓ | 三窗口：短期新增 vs 中期趋势 vs 长期基线 |
| 4 交易所流量 | ✓ | ✓ | ✓ | 三窗口都有意义 |
| 5 持仓集中度 | — | ✓ | ✓ | 24h 变化太小无意义，7d/30d 足够 |
| 6 实体异动 | ✓ | — | — | 事件级信号，发生就触发，不需要累计窗口 |
| 7 流动性环境 | — | ✓ | ✓ | 流动性变化是缓慢的，24h 波动无意义 |

## CBS v2.2 重构后的完整指标体系

### 指标定义

| # | 名称 | 回答的问题 | 计算方式 | 时间窗口 | 有向值含义 |
|---|------|---------|---------|---------|---------|
| 1 | 高质量资金净流入/流出 | 白名单资金对该 Token 的净方向 | 汇总所有确认买卖（Swap + 推定 + LP隐含），加权 quality_score | 24h / 7d / 30d | 正=净买入，负=净卖出 |
| 2 | 连续增持/减持天数 | 方向持续了多久 | 指标 1 连续同向天数 | 不适用（本身是时间指标） | 正=连续增持N天，负=连续减持N天 |
| 3 | 高质量资金参与动态 | 多少人参与、方向是否一致 | 3a 新增实体数 + 3b 净方向比例 + 3c 覆盖率 | 24h / 7d / 30d | 正=净看多共识，负=净看空共识 |
| 4 | 交易所净流量 | CEX 端的资金供需 | 白名单地址的 CEX 入金/出金差 | 24h / 7d / 30d | 正=净提币(看多)，负=净充值(看空) |
| 5 | 持仓集中度变化 | 筹码向谁集中/分散 | Top 20 持仓占比变化 + 一级分类标注 (V1)；分层流转分析 (V2) | 7d / 30d | 正=A类集中↑或分散化，负=B类集中↑或A类退出 |
| 6 | 关键实体异常行为 | 有没有重要实体做了异常的事 | Contrast Layer 自我基线偏离检测 | 事件触发（不累计） | 正=异常买入/做市加码，负=异常卖出/做市撤退 |
| 7 | 流动性环境变化 | Token 的流动性基础面 | 全量 LP TVL 变化 + LP 数 + 深度变化 | 7d / 30d | 正=流动性改善，负=流动性恶化 |
| Adj | Perp 仓位修正 | 衍生品对现货信号的增强/削弱 | Hyperliquid + 链上 Perp 仓位汇总 | 当前快照 | 乘数 (0.35~1.2) |

### 与 v2.1 的变更

| 变更点 | v2.1 | v2.2 |
|--------|------|------|
| 指标分组 | 三组（资金方向/市场结构/行为追踪） | **取消分组，扁平排列** |
| 指标 6 定义 | "标记实体异动追踪"（所有行为） | **"关键实体异常行为"（仅偏离基线的异常）** |
| 指标 7 定义 | "LP 行为变化"（混合白名单 LP 和环境 LP） | **"流动性环境变化"（全量 LP，不限白名单）** |
| LP 方向性信号 | 部分归入指标 7 | **全部归入指标 1（作为买卖手段之一）** |
| 做市商异常 | 部分在指标 6，部分在指标 7 | **统一归入指标 6（异常行为检测）** |
| 时间窗口 | 所有指标统一 3 窗口 | **按指标适配不同窗口 + 窗口比较逻辑** |
| Hyperliquid | 未提及 | **Phase 1 开始数据采集，Phase 2 正式接入** |

### CBS 总分逻辑 (v2.2)

```
CBS_Score = Σ(wi × 指标i_normalized) × PerpModifier

每个指标归一化到 [-100, +100]
加权求和后再归一化到 [-100, +100]

权重 (初始值):
  w1 = 0.25  (净流入——最直接的信号)
  w2 = 0.15  (增持天数——持续性验证)
  w3 = 0.20  (参与动态——广度验证)
  w4 = 0.10  (交易所流量——独立数据源)
  w5 = 0.10  (持仓集中度——结构性信号)
  w6 = 0.10  (实体异常——事件级信号)
  w7 = 0.10  (流动性环境——基础面信号)

附加: 窗口共振加成
  当某指标的 24h/7d/30d 全共振时，该指标权重 ×1.2
  当某指标的窗口间出现 SHORT_REVERSAL 时，输出特殊标记
```

### 一级分类 vs 信号贡献的最终关系

```
一级分类 (A/B/C/D/E):
  → 决定"这个实体是谁"
  → 不决定"这个实体的行为是否计入信号"

行为判定 (Event Layer):
  → 决定"这个实体的这次行为是什么性质"
  → 买入/卖出 → 计入指标 1/2/3
  → CEX 入出金 → 计入指标 4
  → 异常行为 → 计入指标 6
  → LP 相关 → 方向性部分计入指标 1，环境部分计入指标 7

做市商 (C1) 举例:
  C1 常规做市 → Event Layer 判定为"结构行为" → 不计入方向性指标
  C1 异常撤出 → Event Layer 判定为"异常行为" → 计入指标 6
  C1 自营买入 → Event Layer 判定为"真实买入" → 计入指标 1

LP 地址 (C4) 举例:
  C4 全范围 LP → Event Layer 判定为"结构行为" → 仅计入指标 7 (环境)
  C4 策略性窄区间 + 穿越 → Event Layer 判定为"隐含买入" → 计入指标 1
  A3 高手组单边 LP → Event Layer 判定为"隐含买入" → 计入指标 1
```
