## 1. 模块定位与系统角色

### 1.1 在注意力引擎中的位置

CBS 是注意力引擎五大模块中的**模块 2**——回答"钱是否正在流向/撤离某个标的，以及这些资金是否值得信"。

| 模块 | 名称 | 核心问题 |
|------|------|---------|
| 1 | 市场交易信号 (MTS) | 市场是否已经开始交易它、拥挤它、重新定价它？ |
| **2** | **资金行为信号 (CBS)** | **钱是否正在流向/撤离，以及这些资金是否值得信** |
| 3 | 叙事传播信号 (NDS) | 市场是否正在形成共识、扩散讨论，还是营销噪音？ |
| 4 | 事件催化信号 (ECS) | 是否存在可能触发重估的明确事件窗口？ |
| 5 | 业务采用信号 (BAS) | 它是否真的被用起来了，使用是否有质量？ |

五模块形成统一证据框架：MTS 看"市场有没有动" → CBS 看"资金有没有动" → NDS 看"共识有没有扩散" → ECS 看"催化有没有临近" → BAS 看"真实采用有没有变化"。

### 1.2 系统定位

**CBS 是团队内部的投研信号发现工具。用户是人类分析师，不是交易机器人。不做高频。**

| 设计原则 | 含义 |
|---------|------|
| 召回率优先 | 宁可多报不漏报，人类过滤误报 |
| 可解释性 | 比精确评分更重要的是"为什么发出这个信号" |
| 批处理 + 异动触发 | 每小时批量计算 + 大额事件即时推送到 Slack/飞书 |

### 1.3 CBS 的战略价值

CBS 是注意力引擎中信息密度最高、Alpha 含量最大的模块：
- **信息不对称优势**：高质量资金拥有普通用户不具备的信息渠道，其链上行为是信息泄露的最直接通道
- **先行指标属性**：资金行为通常领先于价格变动和市场叙事
- **可验证性**：链上数据透明、可溯源、不可篡改

## 2. 高质量资金地址从何而来

### 2.1 需要解决的三个子问题

1. **发现** — 如何找到这些地址？
2. **归因** — 如何将地址归属到实体（一个机构有多个地址）？
3. **准入** — 如何决定是否纳入白名单？

### 2.2 地址来源渠道

| 来源渠道 | 具体方法 | 覆盖度 | 可靠性 |
|----------|----------|:------:|:------:|
| 公开标签数据库 | Arkham, Nansen, Etherscan Labels | ★★★★ | ★★★★★ |
| 链上溯源分析 | 从已知地址出发追踪资金流向 | ★★★★★ | ★★★ |
| 合约交互分析 | 分析与已知机构合约（多签/Vault）交互的地址 | ★★★★ | ★★★★ |
| Token 持仓反向识别 | 早期持仓 + 高胜率记录的地址 | ★★★ | ★★★ |
| 社交身份绑定 | ENS、Farcaster、Twitter 自公开 | ★★★ | ★★★★★ |
| CEX 出入金对手方 | 已知交易所钱包的对手方分析 | ★★★★ | ★★ |
| VC 投资组合映射 | 公开融资信息 → Token 分配地址 | ★★★ | ★★★★ |

### 2.3 实体归因（Entity Resolution）

一个实体通常拥有多个地址。归因方法：

| 方法 | 原理 | 准确率 |
|------|------|:------:|
| Gas 来源分析 | 多个地址的初始 Gas 来自同一 Funder | 高 |
| 资金流聚类 | 多个地址频繁互转或汇入同一地址 | 高 |
| 时序行为聚类 | 极短时间窗口内执行类似操作 | 中高 |
| 合约工厂追踪 | 同一工厂合约创建的多个代理地址 | 极高 |

### 2.4 准入评级

在地址来源阶段做**简单二元决策**（是否纳入白名单），不做复杂评分：

| 维度 | 标准 | 说明 |
|------|------|------|
| 标签可信度 | 至少 1 个可靠来源标记 | 多源交叉验证更优 |
| 基础活跃度 | 近 90 天有交易记录 | 排除死亡地址 |
| 最低规模 | 管理资产 > 阈值 | 排除小额地址 |

复杂的多维质量评分（历史胜率、信息优势度等）放在后续行为分析阶段（Feature Layer），因为需要积累足够行为数据才能评估。

## 3. 高质量资金如何分类

### 3.1 一级分类：按资金角色

按实体相对于某个标的的**资金角色**分类。关键原则：同一实体对不同 Token 可有不同角色（通过"实体×Token 角色矩阵"实现）。

| 一级 | 二级 | 定义（人话） | 看到时优先怎么理解 |
|------|------|------------|-----------------|
| **A 主动买方** | A1 机构买方 | 有明确机构背景、主动配置下注 | 看机构有没有真下场 |
| | A2 公开人物/KOL | 身份公开、市场关注度高 | 看有没有能带情绪的人在买。注意"表演折扣" |
| | A3 匿名高质量买方 | 身份不公开但历史交易质量高 | 看真正做交易的人在干什么 |
| **B 潜在卖方** | B1 机构供给方 | 低成本筹码持有者 | 看低成本筹码会不会出来 |
| | B2 项目方/基金会/Treasury | 项目直接相关、能影响供给 | 看项目自己有没有在散货 |
| **C 中介通道** | C1 做市商 | 库存管理、报价、成交、对冲 | 别把做市动作当真实观点——但异常行为除外 |
| | C2 交易所体系地址 | 充值、冷钱包、归集、清算 | 交易通道，不是观点表达者 |
| | C3 桥/路由/聚合器/Solver | 跨链、路由、聚合、执行 | 只是路径，要穿透到终态买方 |
| | C4 LP/池子/流动性调度 | 池子增减仓和深度调度 | 看这个币的深度在变厚还是变薄 |
| **D 去噪排除** | D1 MEV/套利/高频Bot | 高频执行、净值接近零 | 防止把机器人当聪明钱 |
| | D2 羊毛/女巫/营销分发 | 空投活动的批量小号 | 防止把热闹当真实需求 |
| | D3 污染型伪高手 | 收益不错但不可复制的运气型 | 防止把运气好的人当高质量鲸 |
| | D4 已知操纵者 | 有 Rug Pull、操纵记录 | 风险标记 |
| **E 特殊观察** | E1 借贷/清算 | 波动和爆仓阶段很关键 | 谁快扛不住了 |
| | E2 托管/代持 | 资金在但决策权未必在手 | 钱在这儿，不一定是它自己在做决定 |
| | E3 治理/质押/验证 | 与治理质押共识机制有关 | 看制度层的变化 |
| | E4 稳定币发行方 | Tether Treasury、Circle | 宏观资金意愿的风向标 |

### 3.2 三层风格标签

一级分类告诉你"这个实体是谁"。风格标签告诉你"这个实体习惯怎么操作"。标签体系解耦为三层，服务于不同目的：

#### A 层：主风格标签（Alpha 来源）——"它靠什么赚钱？"

**主要给人类分析师看**，帮助快速解读该实体的动作含义。每个实体仅贴 1 个主标签。

| 标签 | 定义 | 如何识别 | 优先级 |
|------|------|---------|:------:|
| 事件驱动型 | 在重大事件前精准布局 | 事件前 `[TUNABLE: 72h]` 内建仓比例 > `[TUNABLE: 30%]` | P0 |
| 趋势配置型 | 顺势配置中长线仓位 | 平均持仓 > `[TUNABLE: 14天]` 且建仓时趋势已形成 | P0 |
| 早期发现型 | Token 极早期介入 | 买入时市值 < `[TUNABLE: $10M]` 或上线 < `[TUNABLE: 30天]` 比例 > `[TUNABLE: 40%]` | P0 |
| 均值回归型 | 极端偏离时逆向操作 | 买入时价格在 30d 低点附近 20% 内 | P1 |
| 供需博弈型 | 利用解锁/做市等供给信息 | 建仓时间与供给事件的相关性 | P1 |
| 叙事轮动型 | 跟随热点快速轮动 | 持仓周期短 + Token 集中在热门板块 | P1 |
| 被动配置型 | 类指数基金风格 | 持仓分散 + 调仓频率低 + 跟随市场权重 | P2 |
| 未分类 | 数据不足以判定 | 默认状态 | — |

所有 `[TUNABLE]` 参数为合理初始假设，Phase 3 通过回测优化。

#### B 层：修饰风格标签（执行路径）——"它习惯怎么操作？"

**主要给 Contrast Layer 计算用**，判断某次行为是否偏离惯常路径。每个实体贴 2-4 个。

P0 精选：左侧潜伏/右侧确认、阶梯建仓/一次性重仓、分批止盈/快速兑现、中线持有、高集中度

**示例**：一个"阶梯建仓"风格的实体突然一次性重仓 $800K → Contrast Layer 检测到偏离基线 → 标记为异常 → 推断该实体对这次操作的紧迫感高于平时。

#### C 层：状态标签（有效性）——"它最近靠谱吗？"

**分析师看 + 计算层调权重**。每个实体 1-3 个，需高频更新。

P0 精选：近期有效/近期衰减（基于 `[TUNABLE: 30D]` 胜率）、特定生态有效（如 Solana）

#### 标签获取路径

| 阶段 | 方式 | 覆盖范围 |
|------|------|---------|
| Phase 0 | 投研团队对头部 200-500 实体**人工标注** | 种子数据集 |
| Phase 1 | 基于交易数据**自动计算** P0 标签（3 个 A 层 + B 层高优 + C 层有效性），人工复核 | 全白名单 |
| Phase 2 | ML 分类器 + P1/P2 标签扩展 | 全白名单 + 自动化 |

## 4. 每类资金的行为模式是什么

### 4.1 各分类需看重的行为

#### A1 机构买方

| 核心关注行为 | 为什么重要 |
|------------|---------|
| 首次买入某 Token | 新的机构配置方向 |
| 加仓（已持仓 Token 上增持） | 信心加强 |
| 买入后质押/锁仓 | 长期持有意图确认（最强看多增强信号） |
| 稳定币激活（长期稳定币→风险资产） | 沉默资金苏醒 |

#### A3 匿名高质量买方

| 核心关注行为 | 为什么重要 |
|------------|---------|
| 首次参与某 Token | **最高信号价值**——新 Alpha |
| 多个 A3 同时买入同一 Token | 独立发现共振 |
| 建仓速度和规模 | 急切程度反映信息时效性 |
| 获利了结模式 | 分批=有纪律，全清=判断变化 |

#### B1 机构供给方

| 核心关注行为 | 为什么重要 |
|------------|---------|
| 解锁后第一步行为 | 立即转 CEX=减仓，质押=继续持有，LP=观望 |
| 冷→热钱包转移 | **减仓前兆** |
| 未解锁状态下链上 Perp 做空 | 锁定利润（链上可监测部分） |
| 解锁后长期不动 | 最强持有信号 |

#### B2 项目方/基金会/Treasury

| 核心关注行为 | 为什么重要 |
|------------|---------|
| 大额 Token 转出（非常规运营） | 可能抛售 |
| 回购自家 Token | 看好信号 |
| 向做市商转入 Token | 新做市合约/上所准备 |

#### C1 做市商（关注异常行为）

做市商常规做市行为过滤。以下异常行为从 33 种穷举中筛选的 18 种高价值信号：

**最强信号（★★★★★）**：
- 完全撤出做市 / 多 Token 同时撤出 / 多家做市商同向撤出
- 自营方向性买入/卖出（非做市 Token 上）
- 做市同时反向做空（利益冲突信号）
- 多家做市商同时入场

**高价值信号（★★★★）**：
- 做市区间整体上移/下移（公允价格判断）
- 库存偏向 Token 端/稳定币端（隐含方向性）
- 首次做市 / 跨链部署做市（关系信号）
- 接收/退回项目方 Token（关系变化）
- 做市商间筹码转移（方向不明，需人类判断）

#### E1 借贷/清算

| 核心关注行为 | 为什么重要 |
|------------|---------|
| 接近清算线 | 潜在强制卖压 |
| 追加抵押物 | "选择不在当前价格被迫出局"（置信度 0.3；大额追加提升至 0.5） |
| 接近清算但不追加 | 更强信号——实体可能已放弃 |
| 清算发生 | 已实现的强制抛售 |

### 4.2 共性与特性

**共性（所有分类通用的重要行为）**：首次参与某 Token、规模异常（偏离自身基线）、稳定币激活、冷→热钱包转移、跨链迁移。

**特性差异**：

| | A 类 | B 类 | C1 做市商 |
|-|------|------|----------|
| 核心看什么 | 在买什么、买多少、持有多久 | 什么时候卖、通过什么方式 | 常规 vs 异常的分界 |
| 信号方向 | 偏重看多信号 | 偏重看空/风险信号 | 双向 |
| 分析重点 | 后续行为（买→质押=加强） | 前置行为（冷→热=前兆） | 基线偏离程度 |

## 5. 链上行为如何识别与归类

### 5.1 五类行为识别

CBS 的 Event Layer 将所有链上活动归入五类。这是 CBS 最底层的数据处理逻辑——所有后续指标都建立在这五类行为的准确识别之上。

| 行为类型 | 定义 | 处理方式 |
|---------|------|---------|
| **真实买入** | 实体主动建立或增加对某风险资产的敞口 | 计入指标 1/2/3 |
| **真实卖出** | 实体主动减少或退出对某风险资产的敞口 | 计入指标 1/2/3 |
| **迁移行为** | 资产在地址或账户之间转移，不代表观点变化 | 计入指标 4/6 |
| **结构行为** | 做市、路由、桥接、LP 调度等执行层行为 | 过滤/穿透后归类 |
| **噪音行为** | 对研究判断没有实际意义的动作 | 丢弃 |

### 5.2 真实买入——7 种链上路径

| # | 路径 | 链上识别方式 | 置信度 |
|---|------|-----------|:------:|
| 1 | **DEX Swap** | Swap event：主要资产(USDC/ETH)流出 + 风险 Token 流入 | 1.0 |
| 2 | **聚合器路由** | 1inch/Paraswap 的 Swapped event → 穿透到发起交易的 EOA 地址 | 1.0 |
| 3 | **交易场所对价推定** | 向 CEX/DEX 专属链转入主要资产 → 时间窗口 `[TUNABLE: 24-72h]` 内转出风险 Token → 金额匹配(±20%) | 0.6-0.8 |
| 4 | **LP 隐含买入（区间穿越）** | Uniswap V3 LP 头寸完全变为单边风险 Token | 0.5 |
| 5 | **LP 意图买入（区间设定）** | V3 LP 区间全部低于当前价格（等效限价买单） | 0.2 |
| 6 | **跨链后买入** | Bridge 到达目标链 → 目标链上 Swap 买入 | 1.0 (Swap) |
| 7 | **OTC 对价** | 两地址直接 Transfer 对价交换，金额匹配 | 0.5 |

**不应计入买入**：VC 轮分配（无对价）、空投/奖励、LP 撤除后收回双边资产、非透明 OTC

路径 3 中"交易场所"不限于 CEX，也包括 DEX 专属链（如 Aster：ETH 链转入主要资产 → 后转出 Aster Token 到 BSC）、跨链 DEX（Thorchain/Chainflip）、OTC desk 链上地址。

### 5.3 真实卖出——7 种链上路径（与买入对称）

| # | 路径 | 置信度 |
|---|------|:------:|
| 1 | DEX Swap 卖出 | 1.0 |
| 2 | 聚合器路由卖出 | 1.0 |
| 3 | 交易场所对价推定卖出 | 0.6-0.8 |
| 4 | LP 隐含卖出（区间穿越，Token 全被换走） | 0.5 |
| 5 | LP 意图卖出（区间全高于当前价格） | 0.2 |
| 6 | 跨链后卖出 | 1.0 |
| 7 | OTC 对价卖出 | 0.5 |

**不应计入卖出**：LP 撤除收回双边资产（非方向性）、迁移至自有冷钱包、质押解除（不等于卖出意图）

### 5.4 迁移行为——8 种链上表现

| # | 表现 | 信号含义 |
|---|------|---------|
| 1 | 冷→热钱包转移 | **卖出前兆**（高信号） |
| 2 | 热→冷钱包转移 | 长期存储意图（看好） |
| 3 | 跨链迁移 | 生态偏好变化 |
| 4 | CEX 入金 | 可能准备卖出/OTC/其他 |
| 5 | CEX 出金 | 可能准备链上操作/买入 |
| 6 | 同实体跨地址转移 | 内部调仓，中性 |
| 7 | 向做市商转 Token | 做市合约启动 |
| 8 | 做市商退回 Token | 做市关系终止 |

### 5.5 结构行为——7 种（穿透/过滤）

| # | 表现 | 处理 |
|---|------|------|
| 1 | Router/Aggregator 中转 | **穿透**到发起交易的 EOA |
| 2 | Bridge 中转 | **穿透**到原始发送者 |
| 3 | 做市商常规做市 | **过滤**（不计入方向性） |
| 4 | Solver 执行 | **穿透**到原始订单发起者 |
| 5 | LP 全范围做市 | 不计入方向性，仅计入指标 7 |
| 6 | 做市商常规库存平衡 | **过滤** |
| 7 | 闪电贷 | **过滤**（零风险敞口变化） |

### 5.6 噪音行为——6 种（丢弃）

MEV/Sandwich、套利 Bot、女巫/空投猎人、尘埃攻击、合约自动执行、测试交易 → 通过 D 类名单 + 行为模式匹配识别后**全部丢弃**。

### 5.7 LP 行为特殊处理

LP 不是独立于买卖的第三种行为，而是买卖的一种执行手法：

```
LP 事件 → 判断实体类型
  A/B 类 → 区间分析 → 隐含买入/卖出 → 计入指标 1
  C1 做市商 → 做市商行为分类 → 异常行为计入指标 6
  其他 → 仅计入指标 7
```

### 5.8 Event Layer 处理流程（附举例）

```
Step 1: 原始事件接收
  ← 监听 EVM Event Logs: Transfer, Swap, Mint, Burn, Deposit, Withdraw
  ← Solana Program Logs: SPL Transfer, Raydium/Orca Swap
  
  例: 检测到 Uniswap V3 Swap event，地址 0x7a25 用 50K USDC 换了 125K TOKEN_X

Step 2: D 类地址过滤
  查询黑名单 + 行为模式匹配(Sandwich/套利模式)
  例: 0x7a25 不在黑名单，非 Sandwich 模式 → 通过

Step 3: 结构行为穿透
  如果是 Router/Bridge/Solver → 追踪到原始 EOA
  如果是闪电贷 → 丢弃
  例: 0x7a25 是 EOA 直接调用 → 无需穿透

Step 4: 白名单匹配
  地址在白名单 → 精细分析
  不在白名单 → 仅计入指标 5(持仓)/7(流动性)的全量统计
  例: 0x7a25 = A3 匿名高质量买方 → 命中，进入精细分析

Step 5: 行为分类
  Swap → 真实买入/卖出
  Transfer to CEX → 迁移行为
  LP Mint/Burn → LP方向性判定
  做市商行为 → 33种分类
  例: USDC→TOKEN_X = 绝对确认买入 (同hash内主要资产减少+风险资产增加)

Step 6: 标准化事件输出
  {实体, Token, 行为类型, 金额, 置信度, 时间, 链, 标签}
  例: {SM_0042, TOKEN_X, CONFIRMED_BUY, $50K, 1.0, 2026-04-14T10:23Z, ethereum, []}
  → 计入指标 1 (+$50K), 指标 3 (若首次参与 +1 实体)
```

## 6. 行为如何映射到指标

### 6.1 映射逻辑

不是"一种行为对应一个指标"，而是"一种行为可能触发多个指标，但每个指标从不同角度处理"。

| 行为 | 指标 1 | 指标 2 | 指标 3 | 指标 4 | 指标 5 | 指标 6 | 指标 7 |
|------|:------:|:------:|:------:|:------:|:------:|:------:|:------:|
| A3 绝对确认买入 $500K | +$500K | ±1天 | +1实体 | — | 快照更新 | 若异常规模→层2 | — |
| B1 向 CEX 充入 $5M Token | — | — | — | +$5M入金 | — | 层1偏空+层2 | — |
| C1 撤出做市 | — | — | — | — | — | 层1偏空+层2 | 深度变化 |
| A 类设下方窄LP | +隐含买入 | — | — | — | — | — | — |
| 多LP同时撤池 | — | — | — | — | — | — | 撤池检测 |

### 6.2 不重叠规则

| 数据项 | 唯一归属指标 | 不计入 |
|--------|-----------|--------|
| DEX Swap 买卖金额 | 指标 1 | 不计入指标 6 |
| CEX 入出金金额 | 指标 4 | 指标 6 只记录"谁在做"+方向性加权 |
| 做市商自营 Swap | 指标 1 | 不计入指标 6 |
| 做市商异常 LP 行为 | 指标 6 | 不计入指标 7 |
| 全量 LP 深度/撤池 | 指标 7 | 不计入指标 1 |

## 7. 指标体系是否完备

### 7.1 最终 7+1 指标体系

7 个指标不分组，扁平排列。每个指标独立输出有向值。

| # | 名称 | 回答的问题 | 数据来源 | 窗口 | 权重 |
|---|------|---------|---------|:----:|:----:|
| 1 | **高质量资金净流入/流出** | 白名单确认买卖的净方向 | 白名单 Swap+推定+LP 隐含 | 24h/7d/30d | 0.25 |
| 2 | **连续增持/减持天数** | 方向持续多久 | 指标 1 连续同向天数 | 自身时间指标 | 0.15 |
| 3 | **高质量资金参与动态** | 多少人参与、方向一致性 | 新增实体+净方向比例+覆盖率 | 24h/7d/30d | 0.15 |
| 4 | **交易所净流量** | CEX 端资金供需 | 白名单 CEX 入出金差 | 24h/7d/30d | 0.15 |
| 5 | **持仓集中度变化** | 筹码向谁集中/分散 | 分层持仓+一级分类叠加 | 7d/30d | 0.10 |
| 6 | **结构性资金事件** | 非买卖的方向性结构动向 | 层1量化+层2事件流 | 事件触发 | 0.10 |
| 7 | **LP 行为与流动性动态** | 流动性层面的资金异动 | 深度变化+撤池+集中度+迁移 | 7d/30d | 0.10 |
| Adj | **Perp 仓位修正** | 衍生品修正 | Hyperliquid+链上 Perp | 快照 | 乘数 |

### 7.2 各指标详细定义

**指标 1：高质量资金净流入/流出**
```
NetFlow = Σ(确认买入量 × quality_score) - Σ(确认卖出量 × quality_score)
含: DEX Swap(1.0) + 推定(0.6-0.8) + LP隐含(0.5/0.2) + 做市商自营(1.0)
```

**指标 2：连续增持/减持天数** — 指标 1 连续同向天数，翻转时重置。

**指标 3：高质量资金参与动态** — 3a 新增实体数 + 3b 净方向比例 + 3c 覆盖率。

**指标 4：交易所净流量** — 白名单 CEX 入出金差。正=净提币(偏多)，负=净充值(偏空)。

**指标 5：持仓集中度变化** — 分层持仓分析（鲸鱼层 >0.1% / 中等 0.01%-0.1% / 零售 <0.01%），排除 CEX/合约/桥/销毁地址，叠加一级分类标签判断方向。

**指标 6：结构性资金事件**
- 层 1（量化，参与评分）：大额入出所的实体方向性加权、跨链迁移、冷热转移、做市商区间/库存变化、做市商新增/撤出、多做市商同向模式
- 层 2（事件流，不参与评分）：完整事件明细 → Dashboard + 异动推送

**指标 7：LP 行为与流动性动态** — 聚焦"资金在流动性层面的异动"（不含 TVL/LP 数等归属 BAS 的基本面指标）：
- 7a：池子深度变化（±2% 区间，侧重**变化速度**而非绝对值，与 MTS 的绝对值视角互补）
- 7b：撤池/加池行为检测（撤池+深度恶化→高风险提醒）
- 7c：流动性集中度（Top 5 LP 占比变化→脆弱性）
- 7d：流动性迁移方向

**Perp 修正项** — Hyperliquid 为第一数据源。净多→乘数>1，净空→乘数<1。排除 C1a/C1b 做市对冲仓位。Phase 2 启用。

### 7.3 指标间关系

```
指标 1 (净流入)  ←── 核心方向，汇总所有确认买卖
   ├── 指标 2 (增持天数): 时间维度
   ├── 指标 3 (参与动态): 广度维度 ("多少钱" vs "多少人")
   └── 指标 4 (交易所流量): 独立数据源验证

指标 5 (集中度) ←── 持仓结果分析
指标 6 (事件) ←── 非买卖行为的方向性信号 + 明细
指标 7 (流动性) ←── LP 层面的资金异动
```

### 7.4 CBS Score 计算

```
CBS_Score = [Σ(wi × Ii)] × PerpModifier

窗口共振: 某指标 24h/7d/30d 全同向 → 该指标权重 ×1.2

评分区间 [-100, +100]:
  +60~+100: 强看多 | +20~+60: 温和看多 | -20~+20: 中性
  -60~-20: 温和看空 | -100~-60: 强看空
```

### 7.5 关于"未来解锁压力"

已从 CBS 移至 ECS 模块——解锁是"尚未发生的结构化事件"而非"已发生的资金行为"。CBS 与 ECS 建立事件订阅：ECS 发出解锁预警时，CBS 自动提升对该 Token 的 B 类地址监控灵敏度。

## 8. 系统运行机制

### 8.1 四层处理架构

```
Layer 1: Event Layer (数据清洗)
  原始事件 → D类过滤 → 结构穿透 → 白名单匹配 → 五类行为识别
  → LP方向性判定 → 做市商行为分类 → 标准化输出

Layer 2: Feature Layer (指标量化)
  一级分类标记 → 三层标签匹配 → 8组特征计算 → 动态质量评分

Layer 3: Profile Layer (实体画像)
  基础身份 + 主/次风格 + 近期有效性 + 核心能力圈 → 每日快照

Layer 4: Contrast Layer (异常研判)
  Self-Baseline: 偏离自身历史？
  Peer Compare: 同风格实体共振？
  Object Compare: 该Token买方质量升级？
```

### 8.2 双触发运行模式

#### 模式 A：白名单主动扫描（常驻）

每小时批处理：扫描白名单全部地址 → Event Layer → 指标更新 → CBS Score → 异动推送。

**发现"聪明钱在做什么"。**

#### 模式 B：跨模块被动响应（按需）

其他模块检测到某 Token 异动 → 通知 CBS →

**Step 1 白名单维度**：查询白名单中与该 Token 相关的实体，检查近期有无异常。"白名单无异动"本身也是信号——其他模块看到异动但聪明钱没动，可能是噪音。

**Step 2 Token 维度**：拉取该 Token 全量大额交易/LP 变化，识别"疑似高质量但不在白名单"的异常地址 → 标记为"待入库观察"（可能是新的聪明钱）。同时更新指标 5 和指标 7。

两种模式互补：A 发现异动可触发其他模块检查；B 回应其他模块可发现新地址。

### 8.3 输出形式

**日常输出（每小时）**：Token 级 CBS 面板
```
Token: $XYZ | CBS Score: 71 | 趋势: ACCELERATING

净流入(1):   24h +$2.3M | 7d +$5.1M | 30d -$1.2M | SHORT_REVERSAL
增持天数(2): 5天连续
参与动态(3): +3实体 | 87%看多 | 覆盖率4.2%
交易所(4):   净流出$1.1M | BULL_ALIGNED
集中度(5):   鲸鱼A类+4.2% | 零售-4.6%
结构事件(6): +28分 | Wintermute新增做市/鲸鱼出所/区间上移
流动性(7):   深度+15% | 撤池无 | 集中度稳定

Perp: Hyperliquid净多 ×1.08
```

**异动推送（即时）**：触发条件包括 A 类大额买入、多实体同向、做市商异常、连续增持突破 7 天、撤池+深度恶化等。推送含事件详情 + Contrast 上下文 + 跨模块引导。
